# Checklist de producto

## Propósito y evidencia

- Extraer promesa, target y madurez desde copy, docs, onboarding y producto.
- Formular jobs-to-be-done con contexto, motivación y outcome; no inventar una persona detallada.
- Identificar aha moment y prueba visible de valor.
- Buscar research, tickets, analytics, funnel y feedback; registrar ausencia sin fabricar conclusiones.

## Inventario real

- Enumerar web, móvil, CLI, API/SDK, emails, notificaciones, admin y soporte.
- Marcar feature como construida, parcial, placeholder, especificada, roadmap o inaccesible.
- Detectar superficies huérfanas, WIP expuesto y claims que apuntan a capacidades no construidas.
- Separar table stakes de diferenciación solo con evidencia de categoría vigente.

## Journeys y time-to-value

- Recorrer adquisición/entrada, alta, activación, core loop, retorno, pago si existe y salida.
- Anotar paso, decisión, espera, requisito, feedback, error, recuperación y abandono.
- Probar empty/zero/one/many, permisos, lento/offline, parcial y fallo de tercero cuando sea seguro.
- Preguntar si un primer usuario puede alcanzar valor sin ayuda y si el sistema confirma el resultado.

## Promesa y confianza

- Comparar claim con resultado observable en happy path y failure path.
- Revisar precisión de copy, terminología, estados, límites y explicación de decisiones automáticas/IA.
- Identificar trust breaks: resultado sin procedencia, error opaco, dato perdido, acción irreversible o falsa certeza.
- Evaluar onboarding, sample data, defaults y orientación sin convertirlo en auditoría visual detallada.

## Foco y medición

- Relacionar cada superficie con un job y detectar bloat o duplicación.
- Revisar eventos/señales para activación, core task, retención, errores y abandono.
- Comprobar canal de feedback y capacidad de distinguir uso de éxito.
- Proponer métricas solo si corresponden al outcome, evitando vanity metrics.

## Evidencia suficiente

Un hallazgo debe nombrar usuario, job, paso, comportamiento y consecuencia. Una preferencia estética pertenece a `$audit-ux`; una limitación técnica solo es hallazgo de producto cuando cambia el outcome del usuario.
