### Alcance

`agent-run status` y subcomandos list/show permiten reconstruir el estado sin
conservar IDs en la conversacion del host: orchestrations/traces, tasks, sessions,
pending approvals, operations/retries y coordination lag. Las acciones
cancel/reattach/reconcile/erase reusan challenges y firma B/2/C/0/02; status es
read-only. Cada fila muestra estado canonico, owner/trace, edad, ultimo evento y
next action, nunca prompt/output/raw paths.

### TDD

- Perder todo ID de la sesion del host y recuperar una session activa desde la
  CLI, con filtros deterministas y paginacion.
- Orchestration `completed` con task pending es imposible; estados stale/orphan
  muestran `reconcile`, no exito.
- Gateway/socket ausente, version mismatch y operacion parcial producen error
  accionable, sin leer stores como fallback.
- Terminal estrecha y `--json` conservan IDs/next action; canaries raw no salen.

### Aceptacion

- [ ] Un operador puede descubrir, inspeccionar y recuperar/cancelar todo trabajo
      activo desde la interfaz soportada.
- [ ] Cada accion mutante presenta preview, challenge y firma; list/show no muta.
- [ ] Cero imports/scripts que abran DB, JSONL o Redis desde la CLI.
- [ ] Tests E2E de perdida de contexto/restart y review UX/ops OK.

Rollback: conservar list/show read-only y bloquear acciones mutantes; nunca
volver a IDs opacos mantenidos solo en la conversacion.
