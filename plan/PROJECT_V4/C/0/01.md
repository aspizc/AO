### Alcance

`agent-run approvals list` y `show <id>` consultan el Gateway vivo. Reutilizan
`listPendingApprovals()` existente en `develop`; no crean otra query generica y
no leen SQLite directamente. La respuesta se serializa por allowlist:
approvalId, action, repo, agent/role, target branch, requestedBy, traceId,
created/expiry y status.

### TDD

- Lista solo pending y orden determinista; payload nulo/malformado no rompe.
- Estado vacio claro; `--json` puro y estable.
- Socket ausente/locked/version mismatch produce error acotado con timeout.
- Datos raw o claves adicionales del DB no salen por la API.
- Decidida entre list/show refleja estado first-wins actual.

### Aceptacion

- [ ] El operador descubre que autoriza sin canal lateral.
- [ ] Cero imports/scripts de repositorio state para mutar o leer directo.
- [ ] Tests CLI/control protocol y gate verdes.

Rollback: deshabilitar comandos mutantes; list/show puede quedar read-only si
el protocolo conserva version.
