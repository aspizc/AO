### Flujo

La CLI obtiene detail + challenge del Gateway, muestra action/repo/agent/
branch/digest/expiry, recoge grant/deny/cancel y firma el envelope exacto con
el provider de operador. Antes de aplicar, el Gateway revalida status,
challenge y change-set para cerrar TOCTOU.

| Entorno | Flags | Resultado |
|---|---|---|
| TTY | sin `-d` | preview + grant/deny/cancel + firma |
| TTY | `-d`, sin `--yes` | preview + confirmacion + firma |
| cualquiera | `-d ... --yes` + signer explicito | no prompt, pero firma obligatoria |
| no-TTY | `-d`, sin `--yes` | exit 2, cero mutacion |
| cualquiera | `--json`, sin `--yes` | solo cambia formato; nunca consiente |

Grant interactivo exige una prueba de user-presence del provider. El signer de
automatizacion es una capacidad externa montada solo en un job protegido y
explicitamente autorizado; `--yes` no prueba presencia. No se acepta key
path/env heredable por agentes.

### TDD

- Preview sucede antes de firmar/mutar.
- Cancel, EOF, no-TTY sin `--yes`, firma fallida y digest cambiado: cero writes.
- `--json` no concede; salida permanece JSON pura.
- Dos CLIs en carrera producen una decision/evento first-wins.
- Challenge replay/approval mismatch falla.
- La decision aparece una vez, con el mismo event ID y campos allowlisted, en
  audit JSONL y Redis; sink ausente/partial no produce exito silencioso.

### Aceptacion

- [ ] Ningun modo concede solo por flags/formato/TTY.
- [ ] Key material nunca aparece en argv/env/logs/artifacts.
- [ ] Consumidores Redis no dejan una approval pending despues de la decision
      confirmada por el Gateway.
- [ ] CLI timeout y errores de contrato son defensivos, sin traceback.
- [ ] Reviews A+B para esta tarea de trust y E2E real verdes.

Rollback: bloquear grant y mantener deny/cancel si el signer funciona; nunca
volver al script DB directo.
