## Ficha ejecutable

- **Estado:** Planificada.
- **Objetivo:** derivar estados de proyecto y release desde SHA/evidencia.
- **Scope/evidencia:** status index, checklists, candidate/status validator y structure tests.
- **Aceptación:** separa planned/implemented/reviewed/integrated/promoted/released; `[ ]` bloquea claims; V0–V5 y tags reconciliados.
- **Decisión de versión:** SemVer; `<1.0.0` es interno pero cada minor es funcional/usable; `1.0.0` es el primer MVP mostrable/publicable y `v0.1.0` no se crea retroactivamente como release público.
- **Tests/gate:** README/review/checklist/ref/tag contradictorios o evidence de otro tree fallan.
- **Dependencias:** M0/4/00 y M0/4/01.
- **Esfuerzo/riesgo:** ≤1 día; riesgo **alto** por semántica de release.
- **Fuente:** [trazabilidad V4](../../AUDIT.md), [spec/índice de stage](../TASKS.md) y [auditoría integral](../../../../audit/2026-07-26-project-wide/README.md).

## Especificación detallada

- **Dep:** M0/4/00, M0/4/01. **Paths:** `plan/**` status index, acceptance docs,
  candidate/status validator y tests structure; no marcar criterios sin revisar.
- **Entrega:** manifest distingue `planned`, `implemented`, `reviewed`,
  `integrated`, `promoted` y `released`, cada estado con SHA/evidencia. Un
  review OK no implica tag/release; checklist `[ ]` bloquea claims dependientes.
  V0–V5, V3 en `develop`, V4 worktrees y ausencia/presencia de tags quedan
  reconciliados. El validador aplica SemVer: `<1.0.0` es desarrollo/prueba
  interna, cada minor debe ser funcional/usable y el primer MVP
  mostrable/publicable es `1.0.0`; no crea retroactivamente `v0.1.0`.
- **Rojo/verify:** README/review/checklist/ref/tag contradictorios, OK ligado a
  otro tree o tag fuera del candidate falla. El validator no depende de contar
  substrings ni acepta estados alternativos indistintamente.
- **Rollback/review:** manifest se puede regenerar desde refs/evidencia; no
  degradar a estado manual ambiguo; review documental + release.
