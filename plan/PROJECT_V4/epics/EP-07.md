# EP-07 — Cutover MCP 0.2 y threat gates

[← Índice de épicas](README.md) · [Proyecto V4](../README.md) · [Auditoría integral](../../../audit/2026-07-26-project-wide/README.md)

> Estado actual: **ejecución autorizada; cierre pendiente de absorción V5**. Las tareas enlazadas siguen siendo las unidades canónicas y no se cierran sin evidencia.

**Propósito y outcome.** Introducir un contrato MCP fail-closed, migrar todos
los consumidores de forma atómica y demostrar la frontera con exploits contra
un servidor real persistente.

**Findings cubiertos.** `QA-01` de boundary, `QA-03/04` de E2E, autoridad
declarativa en schemas, mixed versions y ausencia de threat tests reales.

**Stages implicados.** B/4 y B/5.

**Tareas y orden.**

1. [`B/4/00`](../B/4/00.md) — server/schema 0.2 tras flag.
2. [`B/4/01`](../B/4/01.md) — shim worker V1 hacia Gateway único.
3. [`B/4/02`](../B/4/02.md) — migrar clientes y retirar 0.1.
4. [`B/5/00`](../B/5/00.md) — authority/spoof MCP E2E.
5. [`B/5/01`](../B/5/01.md) — artifact/egress/audit MCP E2E.
6. [`B/5/02`](../B/5/02.md) — lifecycle/control-plane E2E persistente.

**Gates y dependencias.** Consume EP-03–EP-06. `B/5/00` cierra G2,
`B/5/01` G3 y `B/5/02` aporta G4/G5 técnico. El shim preserva replay V1 antes
del cutover.

**Exit criteria.**

- Authority inputs se eliminan o son assertions exactas; cliente 0.1 recibe
  version error en 0.2.
- Todos los clientes y server cambian en un mismo gate; no existe mixed mode.
- Histories V1 pendientes drenan con un único PID/lock/writer.
- Exploits de self identity/repo/trace/task/session/audience/replay fallan contra
  MCP externo, sin mocks.
- Un mismo proceso/conexión completa y solapa llamadas; shutdown deja cero
  listeners, Gateways o sessions.
- Coverage productivo >=85/75 y mutación focalizada son gates.
