# EP-03 — Contexto y ejecución no bloqueante

[← Índice de épicas](README.md) · [Proyecto V4](../README.md) · [Auditoría integral](../../../audit/2026-07-26-project-wide/README.md)

> Estado actual: **ejecución autorizada; cierre pendiente de absorción V5**. Las tareas enlazadas siguen siendo las unidades canónicas y no se cierran sin evidencia.

**Propósito y outcome.** Derivar repo/contexto server-side y sustituir
subprocess síncrono por una primitive async con cancelación, backpressure,
admission y presupuestos explícitos.

**Findings cubiertos.** `GW-06`, `GW-08`, `GW-09`, `ABUSE-01`, spoof de repo,
event-loop blocking y ausencia de límites comunes.

**Stages implicados.** B/0, con dependencia cruzada en B/1.

**Tareas y orden.**

1. [`B/0/00`](../B/0/00.md) — repository context canónico.
2. [`B/0/01`](../B/0/01.md) — process runner async.
3. [`B/0/02`](../B/0/02.md) — migrar adapters.
4. [`B/0/03`](../B/0/03.md) — cancelación, concurrencia y admission MCP.

`B/0/00` y `B/0/01` pueden avanzar tras G1; la cuarta tarea cruza con identity
server-side de EP-04.

**Gates y dependencias.** Depende de G1 y `M0/2/01`; `B/0/03` espera
`B/1/01`. Sus garantías se ejercen definitivamente en EP-07/B/5/02.

**Exit criteria.**

- Repo efectivo deriva de realpath+task binding; hints sólo pueden causar deny.
- Ningún delegate usa `spawnSync` o shell interpolation.
- Output grande no bloquea el event loop y dry-run no crea child.
- Cancelación es idempotente; timeout de transporte no duplica session.
- Concurrencia, bytes, artifacts/audit y coste se limitan antes del launch.
