# EP-11 — Lanes live, estabilidad y release

[← Índice de épicas](README.md) · [Proyecto V4](../README.md) · [Auditoría integral](../../../audit/2026-07-26-project-wide/README.md)

> Estado actual: **ejecución autorizada; cierre pendiente de absorción V5**. Las tareas enlazadas siguen siendo las unidades canónicas y no se cierran sin evidencia.

**Propósito y outcome.** Convertir Redis, Temporal, stack y agentes reales en
evidencia obligatoria del mismo candidato y cerrar promoción/release sólo tras
una ventana estable.

**Findings cubiertos.** `TEST-01`, Redis/Postgres/Temporal/agentes skipped,
ausencia de carreras simultáneas, skip budget abierto y release sin tag.

**Stages implicados.** M0/4, E/2 y gates H4/G7/G8.

**Tareas y orden.**

1. [`M0/4/01`](../M0/4/01.md) — Redis 7/V5 concurrente required.
2. [`E/2/00`](../E/2/00.md) — `v1-temporal-real`.
3. [`E/2/01`](../E/2/01.md) — `v1-stack-real`.
4. [`E/2/02`](../E/2/02.md) — `v1-agents-real`.
5. [`E/2/03`](../E/2/03.md) — promotion/stability evidence.

La lane Redis participa temprano en G1. Las lanes V1 son secuenciales después
del cutover Temporal y convergen en H4/G7; G8 sigue siendo una decisión de
promoción/release separada.

**Gates y dependencias.** `M0/4/01` depende del gate reproducible EP-00.
`E/2/00` depende de `E/1/07`; stack añade recovery, agentes exige H3 por run y
promotion exige las tres sobre el mismo candidate. H4 precede E/3/00.

**Exit criteria.**

- Redis 7 required ejecuta 100 seeds con barreras, cero skip y cero key leak.
- Temporal real cubre replay/crash/approval exacta y pasa 5 veces consecutivas.
- Stack usa Postgres+Redis+Temporal+un Gateway+worker, images por digest y red
  efímera.
- Agents real usa repos efímeros, budget/sandbox, no push y approval H3.
- Las cinco Temporal, una stack y una agents comparten tree, locks e images.
- G7 queda verde; G8 demuestra candidate=`main`=tag/publicación con approvals
  separadas.
