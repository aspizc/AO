## Scope

1. **Operator-local registry overlay.** New optional config
   `AGENTS_REPOSITORIES_OVERLAY` (absolute path to a JSON file with the same
   `{ "version", "repositories": {...} }` shape), read in `config.js` and passed
   to `loadRegistries({ policiesDir, repositoriesOverlay })`. Rules:
   additive only; every overlay entry passes the same validation as base
   entries; an id present in both base and overlay is a `RegistryError`
   (fail closed — an overlay must never silently reclassify a shipped repo);
   unset means no overlay; a set-but-missing file is an error. The doctor
   (`doctor_command.py:32`) and `agent-run policy validate` honour the same
   variable.
2. **Parameterize every I-1 entry** as the inventory table says: placeholders
   in prose and templates (the KYA templates are copied by hand per
   `docs/kya-implementation-runbook.md:41-42`), repository-relative or
   environment-derived paths in executable examples. The KYA scripts require
   `KYA_REPO_CWD` / `AGENTS_REPO_ROOTS` and exit non-zero with a clear message
   when unset, instead of defaulting to a personal path.
3. **Test fixtures.** `codex_enable_profile.test.js:76,103` switch to
   `/srv/example/agents-orchestrator/...`, keeping the same absolute-path
   hostile-spelling intent without a home prefix; `ephemeral_redis.js` resolves
   `redis-server` from an env var, else `PATH`. I-3 fixtures are not changed.
4. **Deterministic scan.** New `scripts/check_public_hygiene.py`, wired into
   `scripts/ci_gate.py` as a structure check. It reads `git ls-files` and
   reports each hit as `path:line`, failing on:
   (a) any `/home/<name>/` or `/Users/<name>/` absolute path, except
   (a1) files matching the **history allowlist** (I-4 globs) and
   (a2) entries of a separate **synthetic-fixture allowlist**
   (`ci/public-hygiene-fixtures.json`, reviewed with this sheet) that lists
   exact `(path, literal)` pairs from I-3 — a literal is allowed only in its
   listed file, and any other home path in that same file still fails;
   (b) any base `policies/repositories.json` id outside the public set
   (`cvision`, `cvlib`, `developer-tools`, `sample-apps`, `agents-orchestrator`
   — the ids the existing tests use as fixtures).
5. **Operator step (not an agent change).** The operator moves the personal
   entries out of `policies/repositories.json` (and, per the owner decision,
   out of `policies/profiles/*`) into their overlay file, and configures their local MCP launcher to point at the overlay.
   AO keeps machine-specific `.mcp.json` untracked and its portable examples
   under `client-config/`. Agents never edit `policies/` (AGENTS.md Rule 15; Codex
   `excludedPaths`). Order on the sheet branch: coder commits the code (scan's
   registry check red on the personal ids) → operator commits the policy edit
   on the same branch → review request. The reviewed candidate's gate is
   therefore green; a red registry lane at review time is a KO, never a skip.
