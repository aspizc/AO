## Problem

The Gateway enforces `code.write` denials only at its own API. The child CLI it
launches gets write tools regardless of role:

- Codex: one Gateway-wide sandbox, `workspace-write` by default
  (`gateway/src/config.js:212`; `configuredCodexSandbox` at
  `gateway/src/services/agent_service.js:355-360`, computed once per service at
  `:523`; the adapter re-reads config at `gateway/src/adapters/codex_adapter.js:36-38`
  and passes it to `-s` at `:45` (exec) and `:54` (launch)). The service asserts
  `result.sandbox === codexSandbox` at `agent_service.js:409-416`.
- Claude: headless delegate `buildClaudeArgs` always passes
  `--permission-mode dontAsk` with the full tool set
  (`gateway/src/adapters/claude_adapter.js:34-47`, used at `:238-250`); the
  supervised spawn `buildClaudeLaunch` (`:49-54`, typed into tmux at `:344-345`)
  passes no permission or tool flag at all, so it runs in the CLI's default
  interactive mode with every tool.
- antigravity: permission bypass is opt-in through
  `AGENTS_ANTIGRAVITY_AUTO=1` in both builders
  (`antigravity_adapter.js:39-61`), but there is no role-derived read-only
  restriction. Preserve the opt-in rule for writers.
- gemini-cli: the adapter code builds `["-p", "--yolo", prompt]`
  (`gemini_adapter.js:189`), but the provider is `registry-only`
  (`gateway/contracts/orchestrator-profile-v1.json:120-124`) and
  `assertProviderExecutable` (`gateway/src/core/orchestrator_profile.js:321-328`)
  refuses it before any session starts, as the suites assert
  (`tests/gateway/gemini_delegate.test.js:29-55`,
  `tests/gateway/gemini_supervised.test.js:36-54`). It launches no child today.
- pi: every built-in tool enabled (`pi_adapter.js:40-54`).
- opencode: default `build` agent; `--auto` when `AGENTS_OPENCODE_AUTO=1`
  (`opencode_adapter.js:40-42`, `:50-66`).

Base `reviewer`, `planner`, `editor` (and `orchestrator`, `tester`,
`documenter`, `security_reviewer`) deny `code.write`
(`policies/roles.json:23-24,33,58,63,68,73,83`), while the kya profile's
`reviewer` allows it (`policies/profiles/kya/roles.json:57-67`). `gateway/src/tools/index.js:38-43` registers six adapters; only the **five
executable providers** — `codex`, `claude-code`, `antigravity`, `pi`,
`opencode` — launch children and are in scope. `gemini-cli` stays
registry-only; executable Gemini support is outside this increment.

## Scope

1. **One deterministic predicate.** Export from
   `gateway/src/core/policy_engine.js` (next to `evaluate`, `:352-357`):
   `resolveCliWriteAccess({ agent, role, repo }, registries)` →
   `evaluate({ agent, role, repo, action: "code.write" }, registries).decision === "allow"`.
   `deny` and `require_approval` both yield `false` (fail closed). No role-name
   comparison anywhere.
2. **Codex.** Effective sandbox = `writeAccess ? configured : "read-only"`.
   `AGENTS_CODEX_SANDBOX` becomes a ceiling: configured `read-only` stays
   `read-only` for writers. The adapter takes the sandbox from the call (computed
   from its own `registries` + `role` + `repo`), not from `codexSandbox(config)`;
   `agent_service.js` computes the expected per-call sandbox the same way and
   asserts the adapter result against it (replacing the single value at `:523`).
3. **Claude** (flags verified against installed `claude` 2.1.292 `--help`:
   `--disallowedTools <tools...>`, `--permission-mode` choices
   `acceptEdits|auto|bypassPermissions|manual|dontAsk|plan`). When
   `writeAccess` is false, both `buildClaudeArgs` and `buildClaudeLaunch` append
   `--disallowedTools Edit Write NotebookEdit`. Keep `dontAsk` on the headless
   path. `--permission-mode plan` is rejected: it changes the session's task
   semantics, not just its permissions.
4. **gemini-cli: no change.** It stays registry-only; its refusal tests stay
   byte-for-byte unchanged. (If a later increment makes Gemini executable, the
   verified read-only flag is `--approval-mode plan` — `gemini` 0.55.1
   `--help` — and that increment owns it.)
5. **pi** (`pi --help`: `--tools <allowlist>`, documented example
   `pi --tools read,grep,find,ls` as "Read-only mode"). Non-writers append
   `--tools read,grep,find,ls` to both builders.
6. **opencode** (`opencode` 1.18.20: `run --agent`; built-in `plan` agent denies
   `edit` except its own plan files, per `opencode agent list`). Non-writers pass
   `--agent plan` and never `--auto`, even when `AGENTS_OPENCODE_AUTO=1`.
7. **antigravity** (`agy` 1.3.0 `--help`: `--mode accept-edits|plan`,
   `--sandbox`, `--dangerously-skip-permissions`). Non-writers drop
   `--dangerously-skip-permissions` and pass `--mode plan`. This is the only
   adapter whose read-only behaviour is not documented by its help text, so the
   implementer must record a dry probe (Verification step 3). If the probe
   cannot show writes are refused, the adapter fails closed for non-writers with
   the existing `POLICY_DENIED` path rather than launching a writable child.
8. **Result contract.** The service validates adapter results against exact
   key lists (`SPAWN_RESULT_FIELDS`, `agent_service.js:263-270`;
   `ADAPTER_RESULT_FIELDS`, `:272-344`; checked by `hasExactFields` in
   `assertAdapterSelectionResult`, `:431-450`), so a new field is rejected
   unless the lists change. This sheet adds one field, `writeAccess` (boolean),
   to `SPAWN_RESULT_FIELDS` and to the `delegate` list of each of the five
   executable providers (not `gemini-cli`). The service computes the expected
   value per call with `resolveCliWriteAccess` and rejects a missing,
   non-boolean, or mismatching `writeAccess` with the existing invalid-selection
   error, alongside the unchanged selection-identity checks. The spawn
   `launchCommand` already carries the CLI flags; the audit
   `session.started` event also records `writeAccess`. A/0/01 adds its own
   field (`newSessionArgv`) to the same `SPAWN_RESULT_FIELDS` list; no other
   new result field is introduced by either sheet.
9. Document per adapter in `docs/adapters/{codex,claude-code,antigravity,pi,opencode}.md`:
   the flags, the derivation rule, and the residual below.

**Residual (documented, not fixed here):** for Claude, opencode and antigravity
the read-only profile removes file-edit tools; a shell tool that the CLI still
allows can write. pi's allowlist excludes `bash`, so it has no shell tool, but
it is still a tool restriction, not a sandbox. Only Codex `read-only` is an OS sandbox. Claude headless
`dontAsk` denies Bash unless settings pre-allow it; the supervised Claude
session prompts the operator.

## Non-scope

- No change to `policies/` (operator-owned; Codex cannot write it).
- No new role, action, or rule id; no change to which roles allow `code.write`.
- No OS-level sandbox for non-Codex CLIs.
- No change to `AGENTS_CODEX_SANDBOX` parsing or `CODEX_SANDBOXES`
  (`agent_service.js:337-341`).
