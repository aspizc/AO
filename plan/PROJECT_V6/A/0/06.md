## Problem

Supervised children raise interactive prompts the Gateway never sees: Codex's
first-run "Trust this folder" and its per-command "Would you like to run the
following command?" (options `y`, `p` = don't ask again for this exact
command, `esc`), and Claude Code's permission dialogs. No adapter detects
them (no match for either text under `gateway/src/`), and `view`
(`codex_adapter.js:468-477`) only returns a raw pane snapshot. The child waits
until a person types into tmux. AO already has the right decision point:
`approval_service.request` (`gateway/src/services/approval_service.js:80`)
with `isAutoApprovable` (`:45`) and the `NEVER_AUTO` set (`:11-15`). Field
evidence: on 2026-10-07 an orchestrator answered more than a dozen such
prompts by hand, reading each full command first.

## Scope

1. Per-provider prompt recognisers (Codex trust, Codex command approval,
   Claude Code permission dialog) in each adapter, as pure functions over a
   captured pane, returning `{ kind, command, options }` or `null`. Fixtures
   are recorded pane captures, sanitized.
2. A watcher on supervised sessions (reusing `view`'s capture) that, on a
   recognised prompt, raises an `approval_request` with action
   `session.prompt.<kind>` and the exact command text as context. The
   existing approval policy decides: auto-approved scopes answer through
   a separate approval-bound answer operation; everything else waits for `approval_respond`;
   `NEVER_AUTO` actions and anything the resolved role policy (A/0/00) does
   not grant are never auto-answered.
3. Never answer with a "don't ask again" option (`p`): each command is
   decided on its own.
4. Every answer, automatic or human, is audited with the command text and
   decider.
5. An unrecognised prompt-like pane (a waiting cursor with options) is
   surfaced as `session.prompt.unknown` for a person, never answered.
6. Do not route decision keys through A/0/04's composer-only `submitPrompt`.
   The answer operation must recheck the exact current command, target and
   options against the approved request immediately before sending the
   minimal one-time response. A changed/disappeared prompt receives no keys;
   a decision is consumed at most once. Reusing a low-level transport never
   bypasses approval, role or prompt-binding checks.

## Non-scope

- Any change under `policies/` by an agent (AGENTS.md Rule 15): the operator
  adds the auto-approval scopes this sheet's human gate decides.
- Headless `agent_delegate` (no interactive prompts).
