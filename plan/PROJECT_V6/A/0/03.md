## Problem

AO `1.0.0` is the only public release (`git ls-remote --tags
https://github.com/aspizc/AO` → `refs/tags/1.0.0^{}` = `41f9ce2`). Its tag
message records `Candidate`, `Reviewed implementation tree`, and the full-gate
totals (`2626 passed, 0 failed, 12 skipped; exit 0`). In AO, `41f9ce2` is
both the public 1.0.0 base and the starting commit of `release/1.1.0`.
The source plan's sibling `main` diverged from AO; no re-baseline is selected.
AO's `CHANGELOG.md` has an `Unreleased` section and no `1.0.0` heading.

## Scope

0. **Release-verifier prerequisite (reviewed before the candidate freezes).**
   The ledger verifier only accepts `v`-prefixed tags:
   `SEMVER_TAG` (`scripts/release_candidate.py:67-71`) is
   `^refs/tags/v<semver>$`, applied to `release-tag` evidence at `:3795-3801`,
   so `refs/tags/1.1.0` would fail `verify` even with correct evidence. Change
   `SEMVER_TAG` to accept canonical unprefixed SemVer (`refs/tags/1.1.0`, AO's
   public scheme) while keeping legacy `v`-prefixed tags valid; no other
   identity, ancestry, or provenance check changes. This is a T1 change with
   its own review round inside this sheet (trial `A_0_3-1` covers it; the
   release candidate is a later trial), and its commit must be integrated
   before step 2's candidate is frozen.
1. **Lineage (operator-selected option a).** `release/1.1.0` starts from
   AO `41f9ce2`; integrate the independently reviewed A/0/00–02 and A/0/04–06
   commits on that branch. If a commit is ported from another history, review
   the resulting candidate and any conflict resolution. The release must
   descend from `1.0.0`. Option (b), a non-descendant re-baseline, is not selected.
   See [decision evidence](../../reviews/A_0_3_human_decision.md).
2. **Candidate.** One full 40-character technical commit/tree containing
   A/0/00–02, A/0/04–06 and the `CHANGELOG.md` `## [1.1.0] - <date>` section (moved from
   `Unreleased`; names the six changes and the Codex/Claude CLI read-only
   residual from A/0/00).
3. **Evidence** per `docs/release-candidate.md`:
   - `python3 scripts/release_candidate.py verify-repository --repo-root .`
     (`:36-41`);
   - `collect` into a path outside the checkout (`:114-131`). The collector
     accepts only exact existing `refs/heads/` refs for both `--base-ref` and
     `--branch-ref` (`_git_identity`, `scripts/release_candidate.py:3919-3925`,
     via `_validate_exact_ref_name`, `:1394-1409`; called at `:3940-3941`), so
     a SHA is rejected. Create
     `git update-ref refs/heads/release-base/1.0.0 41f9ce28aa59673283a7c5494200e0ec7b56e2f6`
     (the full peeled 1.0.0 commit) and pass
     `--base-ref refs/heads/release-base/1.0.0`; pass the full evidence branch
     ref, e.g. `--branch-ref refs/heads/release/1.1.0`. After collection,
     assert the candidate JSON's base commit equals
     `41f9ce28aa59673283a7c5494200e0ec7b56e2f6`. The selected base ref must remain pinned to that commit;
   - full gate `bash scripts/ci.sh` on the candidate with exact
     passed/failed/skipped totals; skipped count within the
     `ci/suites-contract.json` budget; a DEFERRED or skipped required lane is a
     blocker;
   - one independent `reviewed_OK` for `A_0_3` bound to the candidate SHA;
   - external `release-state/v1` ledger advanced in order
     `planned → implemented → reviewed → integrated → promoted → released`
     (`:175-198`) and checked with
     `python3 scripts/release_candidate.py verify --candidate … --state …`
     (`:162-170`).
4. **Tag.** Local annotated tag `1.1.0` (AO uses no `v` prefix) on the promoted
   commit, message in the 1.0.0 shape: `AO 1.1.0`, `Candidate: <sha>`,
   `Reviewed implementation tree: <tree>`, `Full gate: <totals>; exit 0.`
5. **Publication is an operator action.** Agents never push (AGENTS.md
   Rule 15). The operator pushes AO `main` and the tag; the sheet closes only
   after a post-push check shows AO `refs/heads/main` and
   `refs/tags/1.1.0^{}` resolve to the candidate-containing promoted commit.

## Non-scope

- Any feature beyond A/0/00–02 and A/0/04–06.
- Back-filling a `1.0.0` CHANGELOG heading (flag it; fix only if the owner asks).
- Signing keys or new provenance formats.
