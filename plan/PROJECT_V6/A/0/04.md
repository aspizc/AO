## Problem

`buildSendKeysCmd` (`gateway/src/adapters/tmux_client.js:15-17`) sends the
prompt text and `Enter` in one `tmux send-keys` call. Field observations show
prompts left in the input box without submission; the precise TUI/paste
mechanism has not been established. Every executable adapter's `ask` uses this one call
(`codex_adapter.js:456`, `claude_adapter.js:376`, `antigravity_adapter.js:381`,
`pi_adapter.js:387`, `opencode_adapter.js:399`), then sleeps
`tmuxAskDelayMs || 1500` (`codex_adapter.js:457`) and returns a pane snapshot
without checking that the prompt was accepted. Field evidence: on 2026-10-07
an orchestrator had to send `Enter` by hand through tmux after every
`agent_ask`, sometimes twice, across Claude Code and Codex sessions. Without
`-l`, `send-keys` also interprets an argument that matches a key name, so a
prompt that is exactly a key name (for example `Enter` or `C-c`) is not sent
as text.

## Scope

1. Separate exact text delivery from the final submit in `tmux_client.js`.
   `send-keys -l` prevents key-name interpretation but does not establish
   multiline framing. Use a uniquely named per-operation tmux buffer loaded
   over stdin (no shell interpolation), verify the target has bracketed
   paste enabled atomically via the [guarded runtime primitive](04-transport.md),
   then `paste-buffer -G -p -r` into that exact target. Preserve
   newline bytes and delete the owned buffer in success/failure cleanup.
   Refuse when framing cannot be established; do not fall back to raw
   multiline keystrokes. The separately guarded final `Enter` follows a
   bounded settle delay (`tmuxSubmitDelayMs`, default measured and recorded).
   Reject unsupported control bytes before creating a buffer or writing to
   the target. Tests must observe emitted input, including no intermediate
   submit, rather than merely assert a command flag.
2. One shared `submitPrompt` helper in `base_adapter.js` used by all five
   executable adapters' `ask` (reuse, not five copies). Before sending text
   or submit, classify the current provider pane deterministically. Known
   trust/permission/model-selection menus, busy output and unknown states
   must not receive an automatic Enter. Use provider-specific, tested input
   and acceptance markers; disappearance of the prompt alone is not proof
   of acceptance. A bounded observation waits for positive evidence of
   acceptance and returns `AGENT_PROMPT_NOT_SUBMITTED` with a safe reason
   when it cannot establish it. Never report uncertain delivery as success.
3. At most one retry is allowed, only when fresh observations positively
   identify the same pending composer and its unchanged prompt, with no
   intervening busy/menu state. Never resend text or retry after ambiguous
   acceptance. Guard concurrent asks to one target against interleaving.
   Record bounded audit metadata, not raw private pane content or prompts.
   This closes the operator-approved 2026-10-07 refinement: a second Enter
   must not accept an unrelated interactive decision.
4. The launch command path (`line: launchCommand`) also separates literal
   single-line text and submit. Reject embedded command newlines/control
   bytes rather than depending on a shell's paste mode. Its launch semantics
   are distinct from an already running provider composer; do not infer
   provider readiness from launch.
5. `gemini-cli` stays registry-only (unchanged refusal tests).
6. Add `AGENT_PROMPT_NOT_SUBMITTED` to the `agent.ask` public error catalog
   and safe projection. Its fixed message is `prompt submission not confirmed`;
   its optional `reason` is exactly one of `busy`, `decision_required`,
   `unknown_state`, `paste_unavailable`, `invalid_text`, `not_submitted`,
   `acceptance_uncertain`, `concurrent_ask`, or `transport_failed`. Unknown
   reason values are omitted; arbitrary exception/pane/prompt content never
   appears. `not_submitted` requires positive unchanged-composer evidence;
   `acceptance_uncertain` must never trigger automatic replay. Update derived
   catalog/contracts/docs with the existing generator and test the emitted
   MCP error envelope. Preserve sanitization of all other unknown errors.

The public composer helper never answers a trust, permission or model menu.
A/0/06 owns a separate approval-bound answer operation; it may reuse transport
primitives, which themselves grant no approval authority. A/0/04 does not
implement that operation or change command scopes.

Additional implementation scope for the public failure contract:
`gateway/src/tools/catalog.js`, `gateway/src/tools/tool_errors.js`, derived
`gateway/contracts/mcp-tools-v1.json` and `docs/mcp-tool-catalog.md`, plus
`tests/gateway/tool_error_serialization.test.js` and contract checks.

The [transport prerequisite](04-transport.md) records the build-discovered
missing tmux mode guarantee, its bounded vendor patch and real-input tests.
Its runtime and adapter checkpoints belong to this same sheet; neither a
runtime-only result nor refusal on every prompt closes A/0/04.
