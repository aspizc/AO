## Problem

`buildSendKeysCmd` (`gateway/src/adapters/tmux_client.js:15-17`) sends the
prompt text and `Enter` in one `tmux send-keys` call. Interactive TUIs (Claude
Code, Codex) receive the text as a bracketed paste and the trailing `Enter`
inside or before the paste ends, so the prompt sits in the input box
unsubmitted. Every executable adapter's `ask` uses this one call
(`codex_adapter.js:456`, `claude_adapter.js:376`, `antigravity_adapter.js:381`,
`pi_adapter.js:387`, `opencode_adapter.js:399`), then sleeps
`tmuxAskDelayMs || 1500` (`codex_adapter.js:457`) and returns a pane snapshot
without checking that the prompt was accepted. Field evidence: on 2026-10-07
an orchestrator had to send `Enter` by hand through tmux after every
`agent_ask`, sometimes twice, across Claude Code and Codex sessions. Without
`-l`, `send-keys` also interprets an argument that matches a key name, so a
prompt that is exactly a key name (for example `Enter` or `C-c`) is not sent
as text.

## Scope

1. Split the send in `tmux_client.js`: a literal text send
   (`send-keys -t <target> -l <text>`) and a separate submit
   (`send-keys -t <target> Enter`) after a short settle delay
   (config `tmuxSubmitDelayMs`, default chosen from measured TUI behaviour and
   recorded in the review request).
2. One shared `submitPrompt` helper in `base_adapter.js` used by all five
   executable adapters' `ask` (reuse, not five copies). It confirms
   submission: after the submit, the captured pane's input line no longer
   holds the prompt text; if it still does, send one more `Enter` and check
   again; if the prompt is still unsubmitted, `ask` fails with a typed error
   (`AGENT_PROMPT_NOT_SUBMITTED`) and an audit entry. Never more than two
   submits.
3. The launch command path (`line: launchCommand`) uses the same literal
   send, since a shell prompt has the same key-name issue.
4. `gemini-cli` stays registry-only (unchanged refusal tests).

## Non-scope

- Detecting what the child does after it accepts the prompt (A/0/06 handles
  prompts the child raises).
- Any change to `agent_delegate` (headless, no tmux input).
