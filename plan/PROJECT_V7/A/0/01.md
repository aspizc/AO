## Problem

An in-memory semaphore per orchestrator does not bound their combined work.
Coordination notices and expiring presence cannot reserve resources or prove
that a surviving child has stopped.

## Scope and ledger contract

Add `wave_budget.py` with `initialize_budget`, `reserve_capacity`,
`mark_possible_effect`, `record_effect`, `release_capacity`, and
`read_budget` over one operator-configured canonical local JSON file.
All read/modify operations hold an exclusive `fcntl.flock` on its stable
sibling `.lock`; never unlink/replace that lock file. Use no daemon, Redis
notice, PID signaling, or third-party storage engine.

`agent-run wave budget-init --budget <absolute-path> --limits <json-path>
--json` creates a missing ledger exclusively, with mode `0600`; an existing
ledger is not overwritten and conflicting limits are `CAPACITY_CONFIG_CONFLICT`.
Runtime directory and budget paths are explicit operator configuration outside
project write scopes. Canonical aliases share the same file/lock. Reject
symlink/special-file targets, unsupported filesystems/platforms, unsafe parent
paths and invalid versions before admitting work. Local filesystem support is
an operator-declared deployment prerequisite, checked for available locking and
atomic primitives; do not assert a heuristic reliably detects every remote
mount. Limits are immutable during runs and must not be supplied/increased by
a task, role, model, coordination message, or project profile.

Closed `wave-budget/v1` DTO:

- `schemaVersion`, generated UUID `budgetId`, nonnegative integer `revision`.
- `limits`: exact integer keys `gatewayInstances`, `agentSessions`,
  `checkProcesses`, `memoryMiB`, `memoryHeadroomMiB`, plus `providerSessions`
  map. Count/provider limits are 1–128; a provider absent from the map has zero
  capacity. Provider keys are canonical agent IDs. `memoryMiB` is the explicit
  host-configured ceiling, integer 2–1048576; `memoryHeadroomMiB` is integer
  1–`memoryMiB - 1`, kept unavailable for runner admission. These are immutable
  host configuration, not measured available RAM.
- `reservations`: at most 1024 entries with UUID `reservationId`, `ownerRunId`,
  logical `taskId` or null, integer `attempt` or null, `units` with exact keys
  `gatewayInstances`, `agentSessions`, `checkProcesses`, `providerSessions`,
  `memoryMiB`. Scalar count/memory values and canonical-provider map entries
  are nonnegative integers. `effectState` (`reserved`, `possible`, `active`,
  `closed`), and safe `effects` references (`gatewayId`, `traceId`, `sessionId`,
  `checkId`) as applicable. No PID, token, prompt, output, pricing or command
  content is persisted. Entry fields and effect IDs have bounded exact shapes.

`reserve_capacity` accepts one complete closed resource vector and succeeds
atomically only if every count dimension remains within its configured limit
and `used.memoryMiB + requested.memoryMiB <= limits.memoryMiB -
limits.memoryHeadroomMiB`. Memory is part of that same transaction, never a
separate post-launch check. The effective memory admission limit reported in
safe counters is ceiling minus headroom. A missing/unknown resource key or
zero memory request for a Gateway/session/check effect is invalid. It generates a
reservation and increments revision in the same durable replacement. There is
no partially acquired vector. `CAPACITY_EXHAUSTED` includes only resource
names and integer limit/used/requested counters; caller may wait/poll boundedly
or stop, but must reserve before any Gateway/provider/check effect.
Reserve a Gateway slot with profile `gatewayMiB` before SDK startup;
session/global and provider slots with profile `coderMiB` or `reviewerMiB`
together before each spawn; a check slot with its declared `memoryMiB` before
every check subprocess. Charge concurrent effects separately; a borrowed
Gateway's already-held memory is not charged or released a second time.
Memory reservations represent conservative declared expected peaks including
anticipated children. No RSS polling, model estimate, memory-monitor daemon,
OS limit, or automatic correction from live host availability is introduced.

Updates use a unique sibling temporary file, flush/fsync, atomic replace and
parent fsync before returning. Readers reject corrupt/truncated/unknown-field
ledgers as `CAPACITY_STATE_INVALID`, never reset to empty. Lock acquisition
has one monotonic 100–10000 ms caller-supplied deadline; contention returns
`CAPACITY_BUSY`. Invalid units return `CAPACITY_REQUEST_INVALID`.

Before dispatch, mark the reservation `possible` durably. Bind safe effect IDs
when the response is known. An exact owner/reservation retry returns the same
state; contradictory references yield `CAPACITY_CONFLICT`. Release only the
specific reservation owned by that run after known no effect or confirmed
close/exit; repeat release is idempotent through a bounded terminal record.
Closed records count toward the 1024-entry bound; exhaustion of record capacity
returns `CAPACITY_STATE_FULL` before another effect. This increment does not
silently evict records or promise unbounded run history. Exclude closed units
from used-capacity totals. An unknown reservation ID returns
`CAPACITY_RESERVATION_UNKNOWN` without mutation.
Budget IDs and reservation IDs are accounting identifiers, never Gateway
authority. Cooperative owner matching is not a hostile same-UID security gate.

Crash, lock release, heartbeat expiry, PID disappearance, and stale timestamp
never automatically free a possible/active reservation. Unknown effects keep
capacity and return `CAPACITY_RECOVERY_REQUIRED`. A/0/03 reconciles exact
recorded effects through existing public tools/owned process handles, or leaves
them held. A reserved entry with no possible-effect transition is safely
releasable by its owning resumed run. No operator force-reset command is added
in this sheet. Scope remains scheduled instances/sessions/checks and their
declared RAM reservations. Actual descendant usage, token/cost quotas,
output/disk, memory measurement/enforcement and external callers remain outside
the guarantee. Unknown effects retain the entire vector, including memory.

Errors use `{schemaVersion:"wave-error/v1", outcomeCode, field?, resource?,
taskId?, runId?, counters?}`; optional IDs are validated local IDs and optional
fields/resources are schema identifiers, never input values. Counters are
nonnegative integers `limit`, `used`, `requested`. Unknown fields are rejected.
Exits are `2` invalid/config, `3` unsupported/state unavailable,
`4` exhaustion/busy, `5` recovery required. The schema definition of this
shared error envelope is owned by this sheet and reused by later sheets.

## Non-scope

No server-global hard enforcement or V5 D/0/06 closure, online limit changes,
TTL reclamation, authority transfer, process killing by numeric PID, or token/
money estimate or declared RAM treated as measured usage. OS locking
coordinates trusted local cooperators, not arbitrary hostile clients.

## Acceptance criteria

- [ ] Two separate processes at a barrier never exceed any configured limit.
- [ ] Declared memory admissions never exceed host ceiling minus headroom;
      memory rejection has zero partial count/provider reservation or launch.
- [ ] Every successful admission is durable before any effect; rejected
      vectors and failed writes expose no unrecorded capacity.
- [ ] Possible/active crashed work remains charged until exact reconciliation;
      age or unlocked files do not increase available capacity.
- [ ] Limits are shared/immutable and corruption fails closed with safe DTOs.
- [ ] Scoped releases and duplicate retries are deterministic; no token or
      numeric process destruction target enters ledger/output.
