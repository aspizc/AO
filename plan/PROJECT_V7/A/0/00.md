## Problem

The current Doctor/sample describes AO's own checkout. A generic runner needs
explicit project commands, layouts, selections and dependencies, without
personal defaults or duplicating Gateway selection authority.

## Scope and frozen input

Add `project-profile/v1` JSON Schema and plain immutable Python DTOs. Objects
reject unknown fields. UTF-8 input is at most 1 MiB. IDs use
`[a-z][a-z0-9-]{0,63}`; lists preserve declared order but reject duplicate IDs.
Fields below are required except those marked optional:

| Field | Contract |
|---|---|
| `schemaVersion`, `projectId`, `repositoryId` | Version is `project-profile/v1`; repository ID is explicit registry ID, not an absolute path |
| `projectRoot`, `planDirectory`, `reviewDirectory` | Root is an explicit existing absolute directory; the other paths are relative to it |
| `roles` | Exact `orchestrator`, `coder`, `reviewer` entries. Each has `agent`, `role`; coder/reviewer may supply `model`, nullable `reasoningEffort`/`serviceTier`. Actions are fixed by the runner, never profile overrides |
| `epics`, `stories` | ID lists; each story has `epicId`. Every task references an existing story; reverse mapping is emitted in normalized output |
| `checks` | Entries `{id, argv, cwd, timeoutMs, memoryMiB}`. `argv`: 1–64 nonempty strings, each at most 8192 UTF-8 bytes, no NUL; `cwd` relative to project root; timeout integer 100–3600000; declared peak memory integer 1–1048576 MiB |
| `tasks` | Entries `{id, storyId, cwd, writePaths, conflictKeys, dependsOn, checkIds, coderPrompt, reviewerPrompt}`. Paths/prompt files are relative to root; dependency/check IDs exist; duplicate edges forbidden |
| `waves` | Entries `{id, taskIds, maxConcurrentTasks, exitCheckIds}`; concurrency integer 1–32. Each task belongs to exactly one wave; dependency appears in the same or an earlier wave |
| `maxTrials`, `pollIntervalMs` | Integers 1–15 and 100–10000 respectively; explicit values, no environment/model guesses |
| `memoryReservations` | Exact `{gatewayMiB, coderMiB, reviewerMiB}`, each an explicit integer 1–1048576; conservative expected peak footprints for the corresponding effect, including anticipated children, not measurements or host ceilings |

At most 256 tasks/checks/stories and 64 epics/waves; at most 256 paths and 64
conflict keys per task. Relative paths reject absolute spelling, `..`, NUL,
controls and symlink escape. Plan/review directories and task/check cwds must
already exist. Prompt files are existing regular files, at most 256 KiB each;
preflight validates them without printing contents. Write paths can name an
absent leaf only when its existing ancestors resolve inside the task cwd and
project root. Reject dependency cycles and overlapping task membership.

Runtime bindings are separate operator inputs: `--gateway-root`,
`--policies-dir`, repeated `--allowed-root`, `--runtime-root`, and, for run,
`--budget`. They are canonical absolute paths; profile paths cannot expand the
allowed roots. Canonical project/task/check paths must be contained by an
allowed root. Runtime/control paths are outside project write paths; their
validation is configuration hygiene, not OS containment. Repository/cwd must
match the Gateway's existing registration/root rules; unsupported worktree
topology is reported rather than enrolled automatically.

Add `agent-run project validate --profile <path> ... --json` and
`agent-run project preflight --profile <path> ... --json`. Validate parses
profile/path/DAG only. Preflight additionally checks installed Node/Python/MCP
SDK, POSIX locking support, the chosen provider executable, registry/role
actions and effective selections. It does not run project checks, log in,
launch a provider/Gateway, create trace/session state, or write a repository.

The small read-only `gateway/scripts/project-preflight.mjs` imports
`resolveEffectiveAgentSelectionForConsumer`, `safeAuditSelectionProjection`,
`validateRuntimeAgentCapabilities`, and existing registry/policy code. It
consumes bounded JSON stdin via argv execution with `shell=False`, checks
selection/role/target actions and registered repository, and returns only safe
effective selections/digest and decisions. Never reproduce model aliases or
defaults in Python. Do not call the state-creating general Gateway config
loader. Final dispatch still performs its own authoritative policy checks.

Output DTO: `{schemaVersion:"project-preflight/v1", projectId,
profileDigest, status:"ready"|"invalid"|"unavailable", checks:[{id,
status:"pass"|"fail"|"unavailable", outcomeCode}], selections:[safe projection]}`.
Digest is SHA-256 of sorted-key compact normalized profile JSON. Unknown
fields, unsafe paths/DAG yield `PROFILE_INVALID` or `PROFILE_PATH_DENIED`;
registry/selection denial yields `PROFILE_POLICY_DENIED`; absent runtime yields
`PROFILE_RUNTIME_UNAVAILABLE`; unsupported platform yields
`PROFILE_RUNTIME_UNSUPPORTED`. Error projection contains code and schema field
only, never rejected values, prompt bytes, tokens or raw subprocess output.
Exit: ready `0`, invalid/denied `2`, unavailable/unsupported `3`.

Memory declarations are requests to A/0/01's single shared vector. They cannot
set/increase the host memory ceiling or reduce its headroom. Missing, zero,
noninteger or out-of-range declarations fail profile validation before launch;
no model/provider fallback estimate is invented. The deployment operator
chooses conservative declarations and host headroom for OS/unrelated work;
V7 does not promise that actual usage stays within the declared estimates.

For a selected wave, expose `validate_prior_wave_facts(profile, waveId, input)`
and freeze `$defs/priorWaveFacts` in the existing project-profile schema, using
the bounded DTO in A/0/02. The prior-facts document is a separate runtime
input, not a new profile field. Validate current project/profile identities,
unique required earlier-dependency task IDs, their exact earlier-wave
membership and the bounded historical result/receipt references before opening
a Gateway. Missing facts, contradictory identities and failed historical work
have A/0/02's distinct outcomes. No implicit run-directory/database lookup or
prior-task replay fills missing facts.

Ship a JavaScript service example with `plan/stories` and Node checks, and a
Python CLI/library example with `docs/work-items` and Python checks. Each has
epic/story/task/wave links, a dependency and shared-file conflict. Paths are
explicit placeholders resolved by operator inputs; no optional KYA example
becomes a default. Keep Doctor unchanged and expose new project preflight as
the narrow contract above. Lazy imports report missing existing client runtime
instead of installing dependencies or adding a second transport.

## Non-scope

No policy write/enrollment, model-default authority, credential setup, native
offline-build proof, sandbox attestation, arbitrary shell interpolation, or
claim that preflight closes V5 H/0/01.

      identical preflight semantics through the production command.
- [ ] Canonical effective selections agree with the Gateway resolver; denied
      selections never fall back or trigger launch.
- [ ] Preflight readiness is not labeled Doctor isolation or execution success.

      before launch; facts remain historical local results, never authority.
