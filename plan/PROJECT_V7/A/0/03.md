# A/0/03 — Durable checkpoint, status and explicit recovery

| Field | Value |
|---|---|
| Status | `planned` |
| Functional priority | P0 — interrupted work is inspectable and never replayed blindly |
| Depends on | V7 A/0/02; reviewed/integrated V6 A/0/05 for restart acceptance |
| Blocks | V7 A/0/04 |
| absorbed_from | Operational summary/recovery requirement; V5 E/0/03 and C/1/03 guarantees remain open |
| Review id | `A_0_3` |

## Problem

An in-memory runner loses which effects were attempted. Persisted IDs alone
cannot reattach a connection or prove that a missing response caused no work.

## Scope and checkpoint contract

Add `wave_checkpoint.py`, `wave-checkpoint/v1` schema, and CLI
`agent-run wave status --run-directory <path> --json`,
`agent-run wave resume --run-directory <path> ... --json`, and
`agent-run wave cancel --run-directory <path> ... --json`. Resume/cancel use
the same explicit runtime/policy/allowed-root inputs as run. Status only reads
runner-owned state; it does not query Gateway stores, claim live health, or
authenticate an operator control endpoint.

One generated run subdirectory under the validated runtime root contains
`checkpoint.json` and a stable `run.lock`. Hold nonblocking exclusive flock
for a mutating run/resume/cancel invocation; a second writer returns
`WAVE_RUN_BUSY`. Never remove/replace the lock inode. Status reads the last
complete atomic checkpoint and labels it `observed` with its timestamp; a held
lock means another local writer, not proof of provider health.

Closed checkpoint fields: `schemaVersion`, `runId`, `projectId`, `waveId`,
`profileDigest`, `budgetId`, `revision`, `updatedAt` (UTC ISO timestamp),
normalized `runtimeBindingDigest`, `status`, task/result DTOs from A/0/02,
`processedEvents` (event IDs plus SHA-256 content digest), `reservations`, and
`operations`, plus normalized `priorWaveFacts` and `priorFactsDigest` (both null
when no earlier-wave dependencies exist). Task DTOs persist `admissionHeld`
and `pendingDisposition`, including cleanup/recovery phases. No prompt, pane, token, argv, raw artifact, raw response or
credentials. Canonical profile and runtime configuration remain separate input;
checkpoint loading is not authority. Counts are bounded by profile limits;
maximum file is 4 MiB and unknown fields/version/corruption fail closed.
`processedEvents` is bounded to 16384 entries; reaching a bound fails visibly
before consuming another event. History is not silently dropped to permit
duplicate input. Safe status output never includes runtime paths/digests beyond
the documented profile/binding digests and IDs.

Operations contain generated UUID `operationId`, task/attempt or null,
`kind` (`gateway_open`, `trace_create`, `task_assign`, `spawn`, `ask`,
`check`, `kill`, `gateway_close`, `capacity_release`), known safe references, `state` (`intent`, `confirmed`,
`uncertain`), and safe outcome/returned IDs. Persist intent with reservation
reference before dispatch, then persist confirmed result before advancing.
Write by unique sibling temp + flush/fsync + atomic replace + parent fsync.
If intent durability fails, perform zero effect. If response exists but its
durability fails, stop the phase as uncertain; do not redispatch. This ordering
also covers checks and cleanup. The shared capacity ledger is never cleared
because a checkpoint write or process failed. Cross-file updates need not be
atomic: any interrupted combination retains capacity and is reconciled
conservatively; it must not admit an unrecorded effect.

Persist review receipt/pending disposition before retirement, kill intent before
the public close, close confirmation before complete reservation release, and
release confirmation before terminal task/slot advancement. Persist SDK-close
intent and confirmation before owned Gateway release; persist that release
before final successful wave status. A crash at any seam preserves cleanup or
recovery state and any unreleased capacity/held slot. It cannot promote a
pending accepted review into terminal acceptance. Known confirmed retirement
permits idempotent release of the same reservation; an uncertain kill/SDK close
is not replayed or replaced with a release based on its receipt.

Reservation references retain the original closed count/`memoryMiB` vector
from the shared ledger. Recovery never recomputes a smaller memory estimate or
reduces host headroom to free capacity. Uncertain effects keep their entire
declared memory charge. Status exposes only safe booked-memory counters, not
measured RSS or a promise of free host RAM. Reopening a Gateway reserves its
declared memory with the new slot before SDK startup.

Resume first validates profile/budget/runtime digests, acquires the run lock,
and inventories known/uncertain operations. A changed binding/profile is
`WAVE_CHECKPOINT_CONFLICT`, never rebinding by editing IDs. Reopen one owned
SDK client only after reserving a new Gateway slot; old Gateway reservation
is not freed until closure is known. Explicitly call the actual canonical
reattach tool registered by reviewed V6 A/0/05 for each persisted trace, then
inspect returned sessions and existing public `orchestration.view`/`agent.view`
for the recorded IDs. Do not guess dotted/underscored names from prose; verify
the exact integrated catalog and shape as a prerequisite.

Use the frozen validated earlier-wave facts from the checkpoint; do not look
up or dispatch a prior run. If optional `--prior-wave-facts` is supplied on
resume, normalize/validate it and require the same stored digest; mismatch is
`WAVE_CHECKPOINT_CONFLICT`. Facts remain historical local controller inputs,
not authority or source freshness. Reattach only the selected wave's recorded
nonterminal traces/sessions needed for recovery, never prior-wave fact sources
or already retired historical task sessions.

Reconstruct logical concurrency from persisted `admissionHeld`, retaining
cleanup and possible-active `recovery_required` tasks. Active/cleanup phases
with a false held flag, terminal acceptance with unresolved owned cleanup, or
a held count above the frozen wave ceiling is `WAVE_CHECKPOINT_INVALID`, with
no dispatch or budget clearing. No new admission occurs while the held count
equals `maxConcurrentTasks`; resume does not consume a trial to escape it.
An interrupted wave exit with only uncertain old Gateway cleanup remains
recovery required; do not reopen another Gateway merely to repeat its close.

Wrong principal/repository, missing reattach tool, vanished session or unknown
spawn/check/ask outcome returns `WAVE_RECOVERY_REQUIRED` with safe IDs/outcome
codes. No automatic create/spawn/ask/check replay. An intent with uncertain
returned identity cannot be repaired from a coordination notice or numeric PID.
Even a known live session does not prove whether an ambiguous ask was accepted.
The already-authorized parent orchestrator or operator may inspect/close a
recorded session through existing authority; this runner only reconciles
confirmed observations, not force-resets them. Resuming review control does
not introduce a per-task human confirmation; any configured human gate remains
binding, and checkpoint/event content itself grants no authority.

Confirmed close/known owned process exit permits the exact reservation release.
In dry-run mode, recorded dry-run effects are reconciled as simulated effects,
never presented as real process retirement. Cancellation after restart first
requires successful explicit reattachment, then closes known owned sessions;
missing authority/unknown effects stay charged and recovery required. An
externally accepted checkpoint remains a historical runner result, not live
Gateway completion/review proof. Terminal repeated resume returns the same
result without reopening a Gateway or repeating effects.

Errors: `WAVE_RUN_BUSY`, `WAVE_CHECKPOINT_INVALID`,
`WAVE_CHECKPOINT_CONFLICT`, `WAVE_CHECKPOINT_WRITE_FAILED`,
`WAVE_RECOVERY_REQUIRED`. Reuse safe error/exit contracts from A/0/02;
write/unknown-outcome failures use exit `5`. Local status/checkpoint tests may
precede V6 A/0/05. Restart acceptance stays open until that dependency and its
external transcript are available; a stub does not close it.

## Non-scope

No Gateway lineage persistence implementation, ID-based reownership,
zero-ID operator inventory, authentic review gate, provider/token reconstruction,
signed checkpoint, forced PID cleanup, or promise of exactly-once provider work.

## Acceptance criteria

- [ ] Every effect has durable intent first and cannot replay after an
      uncertain response/write; capacity remains charged on every crash seam.
- [ ] Retained capacity includes the original declared memory; recovery never
      reduces estimates/headroom or labels booked counters as measured RAM.
- [ ] Status is deterministic safe runner metadata with freshness limitations.
- [ ] Exactly one writer owns resume/cancel; terminal resume has zero effects.
- [ ] Resume uses identical prior facts without prior-task effects; held task
      slots survive waiting/cleanup/uncertainty and enforce the wave ceiling.
- [ ] Reviewer close and full release precede terminal task advancement; owned
      SDK close and Gateway release precede final success across crash seams.
- [ ] Correct explicit reattachment reaches existing recorded sessions;
      wrong/missing bindings or uncertain operations stop visibly.
- [ ] External restart acceptance is recorded only after V6 A/0/05 is
      integrated; a deferred dependency cannot be a PASS.
