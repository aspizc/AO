## Acceptance criteria

- [ ] Both shapes use the production generic path and real differing checks.
- [ ] One initialization/connection per wave serves multiple distinct traces.
- [ ] Ordered waves consume explicit matched historical facts and emit only
      selected-wave effects; missing/negative history cannot spawn dependents.
- [ ] The wave ceiling controls actual admissions despite ample shared
      capacity, through control waits, retirement and uncertain recovery.
- [ ] Two production runner processes never exceed shared session/provider
      capacity; conflict/dependency failures affect actual dispatch.
- [ ] The RAM-only case bounds declared booked memory by host ceiling minus
      headroom; rejection has zero spawn or partial reservation and recovery
      retains the original vector.
- [ ] Authorized-parent control advances after distinct reviewer evidence
      without a new per-task human step; configured human gates stay pending.
- [ ] Explicit reattachment observes the same existing session, and all
      ambiguous boundaries have zero replay and retained capacity.
- [ ] Failure/cleanup preserve unrelated resources and report unresolved ones.
- [ ] At capacity one each accepted reviewer retires before the next coder;
      final success follows owned SDK closure/Gateway release, with borrowed
      ownership and uncertain retirement reported honestly.
- [ ] Required suite is executed without skips, secret leaks, fabricated
      review acceptance or claims that the V5 guarantees are implemented.
