## ¿Por que existe?

V4 §15 contiene la matriz de visibilidad por (rol, kind, classification). Convertirla en una **table-driven test suite** evita que cambios futuros (nuevo rol, nuevo kind) ensanchen visibility silenciosamente. Tambien es el evidence binding para U/0/4 (bypass regression).

## ¿Que hay que hacer?

`tests/gateway/artifact_visibility_matrix.test.js` con filas que cubran:

- Gemini `restricted-coder`: ve raw restricted, ve sanitized internal.
- Claude `orchestrator`: NO ve raw restricted, ve sanitized.
- Claude `reviewer`: NO ve raw restricted, ve sanitized.
- Codex `tester`: NO ve raw restricted; ve `test_report` interno.

### 2. Test

```javascript
import { test } from "node:test";
import assert from "node:assert/strict";
// setup state, audit, store, registries...
import { put as artifactPut, get as artifactGet } from "../../gateway/src/core/artifact_store.js";
import { shareArtifact } from "../../gateway/src/services/artifact_share_service.js";
import { loadRegistries } from "../../gateway/src/core/registry.js";

const reg = loadRegistries({ policiesDir: "policies" });

const MATRIX = [
  { name: "gemini restricted-coder gets raw_diff restricted",
    requester: { agent: "gemini-cli", role: "restricted-coder" },
    kind: "raw_diff", classification: "restricted", expected: "allow" },
  { name: "claude orchestrator denied raw_diff restricted",
    requester: { agent: "claude-code", role: "orchestrator" },
    kind: "raw_diff", classification: "restricted", expected: "deny" },
  { name: "claude reviewer requires sanitization for raw_diff restricted",
    requester: { agent: "claude-code", role: "reviewer" },
    kind: "raw_diff", classification: "restricted", expected: "allow_with_sanitization" },
  { name: "codex tester denied raw_diff restricted",
    requester: { agent: "codex", role: "tester" },
    kind: "raw_diff", classification: "restricted", expected: "deny" },
  { name: "anyone allowed sanitized",
    requester: { agent: "claude-code", role: "reviewer" },
    kind: "review_notes", classification: "internal", expected: "allow" }
];

for (const row of MATRIX) {
  test(`visibility: ${row.name}`, () => {
    const a = artifactPut({
      traceId: "t-vis", kind: row.kind, classification: row.classification,
      producedBy: "test", content: Buffer.from("data") });
    const r = shareArtifact({ artifactId: a.artifactId, traceId: "t-vis",
                              requesterAgent: row.requester.agent,
                              requesterRole: row.requester.role,
                              registries: reg });
    if (row.expected === "deny") assert.equal(r.error || r.decision, "POLICY_DENIED");
    if (row.expected === "allow") assert.equal(r.decision, "allow");
    if (row.expected === "allow_with_sanitization") assert.equal(r.decision, "allow_with_sanitization");
  });
}
```

## Errores comunes

- ❌ Hardcodear `decision === 'allow'` y olvidar `allow_with_sanitization` (caso reviewer).
- ❌ Reusar el mismo traceId entre tests sin reset (estado compartido).
- ❌ Asumir que `sharedArtifactId` siempre se devuelve. En deny no.
