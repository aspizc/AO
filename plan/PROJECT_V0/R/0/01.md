## ¿Por que existe?

Cierra TM-05 (parcialmente). Cuando el operador hace `tmux attach` y escribe comandos en una sesion del Gateway, el sistema debe (intentar) **darse cuenta** y dejar evidencia. Es **best-effort**: tmux no notifica, asi que comparamos snapshots antes/despues de operaciones esperadas.

## ¿Que hay que hacer?

`gateway/src/adapters/intervention_detector.js` con:

- Tracker en memoria de prompts esperados por session.
- Comparador de snapshots: si entre `view()` y `view()` aparecen cambios no atribuibles a un `agent.ask` reciente, emite `HUMAN_TMUX_INTERVENTION`.

### 2. Detector

```javascript
import { append as auditAppend } from "../core/audit.js";

const _expected = new Map(); // sessionId -> { lastSnapshot, lastAskAt }

export function recordExpectedAsk(sessionId, snapshotBefore) {
  _expected.set(sessionId, { lastSnapshot: snapshotBefore, lastAskAt: Date.now() });
}

export function checkForIntervention({ sessionId, currentSnapshot, traceId }) {
  const prev = _expected.get(sessionId);
  if (!prev) return false;

  // If a long time has passed since the last ask, AND the snapshot changed
  // significantly from what we expected, treat as possible intervention.
  const hoursSinceAsk = (Date.now() - prev.lastAskAt) / 3_600_000;
  if (hoursSinceAsk < 0.001) return false;

  if (prev.lastSnapshot === currentSnapshot) return false;
  // Crude diff signal: more than 200 chars different => possible intervention
  if (Math.abs(currentSnapshot.length - prev.lastSnapshot.length) < 200) return false;

  auditAppend({
    type: "HUMAN_TMUX_INTERVENTION", traceId, sessionId,
    note: "best-effort detection; pane changed without recent agent.ask"
  });
  return true;
}

export function _resetForTests() { _expected.clear(); }
```

### 3. Hook

En `agent_service.ask` y `agent_service.view`, llamar `checkForIntervention(...)` con el snapshot actual antes de devolver al caller.

## Tmux intervention is best-effort

Direct tmux attach + typing is **legitimate** advanced use, but the

## Errores comunes

- ❌ Hacer el detector estricto: tasa alta de falsos positivos enfada al operador.
- ❌ Bloquear la sesion al detectar. Solo audit; el operador es soberano.
- ❌ Olvidar la documentacion "best-effort".
