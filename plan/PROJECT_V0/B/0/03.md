## ¿Por que esta tarea existe?

Los objetos de dominio (`OrchestrationSession`, `Task`, `Artifact`, `Message`, `PolicyDecision`, `Approval`, `RegistryMeta`) cruzan limites: persistencia SQLite, audit JSONL, MCP responses, sanitization. Si cada lugar inventa su forma, vamos a tener bugs sutiles.

Los schemas:

1. Documentan el dato como contrato.
2. Permiten validar fixtures golden y rechazos.
3. Son el origen de verdad para Zod (G/0/1) y para repositorios (F/0/2).

## ¿Que hay que hacer?

Crear 7 schemas JSON Schema 2020-12 en `schemas/`, cada uno con `$id` y `version`. Anadir fixtures golden bajo `tests/fixtures/schemas/`. Validar via `ajv`.

### 2. Schemas

Para cada uno: cabecera comun.

`schemas/orchestration-session.schema.json`:

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "https://agents-orchestrator/v4/orchestration-session.schema.json",
  "version": 1,
  "title": "OrchestrationSession",
  "type": "object",
  "required": ["sessionId", "traceId", "createdAt", "status", "callerAgent", "callerRole"],
  "properties": {
    "sessionId": { "type": "string", "minLength": 1 },
    "traceId":   { "type": "string", "minLength": 1 },
    "createdAt": { "type": "string", "format": "date-time" },
    "status":    { "enum": ["active", "paused", "completed", "cancelled"] },
    "callerAgent": { "type": "string" },
    "callerRole":  { "enum": ["orchestrator"] },
    "goal":        { "type": "string" }
  },
  "additionalProperties": false
}
```

Repetir para:
- `task.schema.json` (campos: `taskId`, `traceId`, `assignedAgent`, `assignedRole`, `repo`, `status`, `createdAt`).
- `artifact.schema.json` (`artifactId`, `traceId`, `kind`, `classification`, `producedBy`, `createdAt`, `sanitizedFrom?`, `path`).
- `message.schema.json` (`messageId`, `traceId`, `from`, `to`, `body`, `createdAt`).
- `policy-decision.schema.json` (`decisionId`, `traceId`, `context`, `decision` enum, `reasonCode`, `at`).
- `approval.schema.json` (`approvalId`, `traceId`, `requestedBy`, `action`, `status` enum, `createdAt`, `decidedAt?`, `decidedBy?`).
- `registry-meta.schema.json` (`version`, `loadedAt`, `paths`).

> Definir `decision`: `["allow", "deny", "require_approval", "allow_with_sanitization"]`.
> Definir `status` (approval): `["pending", "granted", "denied", "expired"]`.
> Definir `kind` (artifact): `["plan", "raw_diff", "raw_code", "raw_stacktrace", "review_notes", "test_report", "doc", "security_finding", "summary"]`.
> Definir `classification`: `["unrestricted", "internal", "restricted"]`.

### 4. Test

`tests/gateway/schemas.test.js`:

```javascript
import { test } from "node:test";
import assert from "node:assert/strict";
import fs from "node:fs";
import path from "node:path";
import Ajv from "ajv/dist/2020.js";
import addFormats from "ajv-formats";

const ajv = new Ajv({ allErrors: true, strict: false });
addFormats(ajv);

const SCHEMAS = [
  "orchestration-session", "task", "artifact",
  "message", "policy-decision", "approval", "registry-meta"
];

function load(rel) {
  return JSON.parse(fs.readFileSync(path.resolve(rel), "utf-8"));
}

for (const name of SCHEMAS) {
  const schema = load(`schemas/${name}.schema.json`);
  const validate = ajv.compile(schema);

  test(`schema_${name}_has_id_and_version`, () => {
    assert.ok(schema.$id, "missing $id");
    assert.ok(schema.version, "missing version");
  });

  test(`valid_${name}_passes`, () => {
    const valid = load(`tests/fixtures/schemas/${name}.valid.json`);
    assert.ok(validate(valid), JSON.stringify(validate.errors));
  });

  test(`invalid_${name}_fails`, () => {
    const invalid = load(`tests/fixtures/schemas/${name}.invalid.json`);
    assert.ok(!validate(invalid));
  });
}
```
