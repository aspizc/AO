## ¿Por que esta tarea existe?

V4 hace policy data-driven: en lugar de codificar "Gemini puede acceder a `cvision`" en if/else, lo declaramos en JSON y el motor (Stage C) lo lee. Esto:

- Permite cambiar capacidades sin tocar codigo (auditoria mas barata).
- Hace los limites del sistema explicitos para revisores humanos.
- Bloquea TM-02 (leak raw restricted) en su origen: Claude/Codex sin acceso a `restricted` por declaracion.

Sin este registry, no hay sobre que evaluar policy, y por tanto Stage C no puede empezar.

## ¿Que hay que hacer?

Crear `policies/agent-capabilities.json` con tres agentes (`gemini-cli`, `claude-code`, `codex`), sus clasificaciones permitidas, los roles que pueden asumir, las acciones que requieren approval y la lista de `protectedBranches`. Ningun path absoluto del operador.

```json
  "version": 1,
  "agents": {

      "binary": "gemini",

        "reviewer", "tester", "documenter", "security_reviewer"
      ],
      "requiresApprovalFor": [
        "git.push", "dependency.change", "code.write.protected_branch"
      ],
      "notes": "Only agent allowed for repos classified as restricted."
    },
    "claude-code": {
      "binary": "claude",
      "allowedClassifications": ["unrestricted", "internal"],
      "allowedRoles": [
        "orchestrator", "planner", "coder",
        "reviewer", "tester", "documenter", "security_reviewer"
      ],
      "requiresApprovalFor": [
        "git.push", "dependency.change", "code.write.protected_branch"
      ]
    },
    "codex": {
      "binary": "codex",
      "allowedClassifications": ["unrestricted", "internal"],
      "allowedRoles": ["coder", "reviewer", "tester"],

      "enabled": false,
      "notes": "Optional MVP. Disabled until P/0/0 promotes it."
    }
  },
  "protectedBranches": ["main", "master", "release/*"]

```

### 3. Test

`tests/gateway/registry_agent_capabilities.test.js`:

```javascript
import { test } from "node:test";
import assert from "node:assert/strict";
import fs from "node:fs";
import path from "node:path";

const FILE = path.resolve("policies/agent-capabilities.json");
const reg = JSON.parse(fs.readFileSync(FILE, "utf-8"));

test("loads_agent_capabilities_registry", () => {
  assert.equal(reg.version, 1);
  assert.ok(reg.agents["gemini-cli"]);
  assert.ok(reg.agents["claude-code"]);
  assert.ok(reg.agents["codex"]);
});

test("gemini_has_restricted_classification", () => {
  assert.ok(reg.agents["gemini-cli"].allowedClassifications.includes("restricted"));
});

test("claude_and_codex_do_not_have_restricted_classification", () => {
  assert.ok(!reg.agents["claude-code"].allowedClassifications.includes("restricted"));
  assert.ok(!reg.agents["codex"].allowedClassifications.includes("restricted"));
});

test("orchestrator_role_is_allowed_for_gemini_and_claude", () => {
  assert.ok(reg.agents["gemini-cli"].allowedRoles.includes("orchestrator"));
  assert.ok(reg.agents["claude-code"].allowedRoles.includes("orchestrator"));
});

test("protected_branches_present", () => {
  assert.ok(Array.isArray(reg.protectedBranches));
  assert.ok(reg.protectedBranches.includes("main"));
});
```

## Errores comunes a evitar

- ❌ Anadir `restricted` a `claude-code` o `codex`. Es lo que el threat model TM-02 bloquea por declaracion.
- ❌ Hardcodear paths absolutos del operador en el registry. Solo metadata.
- ❌ Anadir secrets, API keys o env vars con valores reales.
- ❌ Quitar `orchestrator` de los roles permitidos a los CLIs humano-facing — el LLM lo asume.
