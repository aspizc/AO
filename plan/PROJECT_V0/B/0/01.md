## ¿Por que esta tarea existe?

La policy es `(agent, role, repo, action) -> decision`. Sin un mapping declarativo de **que repos existen y de que clasificacion son**, no podemos decidir nada. Tambien queremos que esta lista sea **portable**: el mismo registry debe funcionar en cualquier maquina del operador, asi que no se hardcodean paths absolutos.

Esta es la frontera que TM-03 protege: solo Gemini puede acceder a `restricted` (`cvision`, `cvlib`).

## ¿Que hay que hacer?

Crear `policies/repositories.json` con cuatro repos representativos y su clasificacion. Mapear `allowedAgents` segun §13.1 V4. Cero paths absolutos.

### 3. Test

`tests/gateway/registry_repositories.test.js`:

```javascript
import { test } from "node:test";
import assert from "node:assert/strict";
import fs from "node:fs";
import path from "node:path";

const reg = JSON.parse(fs.readFileSync(path.resolve("policies/repositories.json"), "utf-8"));

test("cvision_is_restricted", () => {
  assert.equal(reg.repositories.cvision.classification, "restricted");
});

test("cvlib_is_restricted", () => {
  assert.equal(reg.repositories.cvlib.classification, "restricted");
});

test("sample_apps_is_unrestricted", () => {
  assert.equal(reg.repositories["sample-apps"].classification, "unrestricted");
});

test("restricted_repos_allow_only_gemini", () => {
  for (const id of ["cvision", "cvlib"]) {
    const allowed = reg.repositories[id].allowedAgents;
    assert.deepEqual([...allowed].sort(), ["gemini-cli"]);
  }
});

test("each_repo_has_exactly_one_classification", () => {
  const valid = new Set(["unrestricted", "internal", "restricted"]);
  for (const [id, repo] of Object.entries(reg.repositories)) {
    assert.ok(valid.has(repo.classification), `${id} has invalid classification`);
  }
});
```
