## ¿Por que esta tarea existe?

V4 desacopla **agente** (CLI tecnico) de **rol** (funcion). Esto permite que `gemini-cli` actue como `restricted-coder`, `coder` o `orchestrator` sin codificarlo en el binario. Pero solo funciona si los roles estan declarados con sus capacidades concretas: que pueden hacer, que NO pueden hacer.

El rol `orchestrator` es **especialmente sensible** porque lo asume el LLM humano-facing. Cualquier capacidad extra alli es un boquete (TM-01). Por eso este registry lo declara explicitamente y los tests blindan los `denyActions`.

## ¿Que hay que hacer?

Crear `policies/roles.json` con 8 roles y, para cada uno, las acciones permitidas (`allowActions`) y las acciones explicitamente denegadas (`denyActions`). Tests deben fallar si alguien anade `code.write` a `orchestrator`.

### 3. Test

`tests/gateway/registry_roles.test.js`:

```javascript
import { test } from "node:test";
import assert from "node:assert/strict";
import fs from "node:fs";
import path from "node:path";

const reg = JSON.parse(fs.readFileSync(path.resolve("policies/roles.json"), "utf-8"));

const REQUIRED_ROLES = [
  "orchestrator", "planner", "coder", "restricted-coder",
  "reviewer", "tester", "documenter", "security_reviewer"
];

test("all_v4_roles_exist", () => {
  for (const role of REQUIRED_ROLES) {
    assert.ok(reg.roles[role], `missing role ${role}`);
  }
});

test("orchestrator_denies_code_write", () => {
  assert.ok(reg.roles.orchestrator.denyActions.includes("code.write"));
});

test("orchestrator_denies_raw_restricted_artifacts", () => {
  assert.ok(reg.roles.orchestrator.denyActions.includes("artifact.get.raw_restricted"));
  assert.ok(reg.roles.orchestrator.denyActions.includes("code.read.raw_restricted"));
});

test("orchestrator_cannot_self_approve", () => {
  assert.ok(reg.roles.orchestrator.denyActions.includes("approval.respond"));
});

test("reviewer_denies_raw_artifact_kinds", () => {
  assert.ok(reg.roles.reviewer.denyActions.includes("artifact.get.raw_restricted"));
});

test("restricted_coder_is_a_role_not_an_agent", () => {
  assert.ok(reg.roles["restricted-coder"]);
  // The agent registry must not have a "restricted-coder" agent.
  const agents = JSON.parse(fs.readFileSync(path.resolve("policies/agent-capabilities.json"), "utf-8"));
  assert.ok(!agents.agents["restricted-coder"], "restricted-coder must be a role, not an agent");
});
```

## Errores comunes a evitar

- ❌ Anadir `code.write` o `artifact.get.raw_restricted` a `orchestrator`. Bloquea TM-01.
- ❌ Anadir `approval.respond` a cualquier rol agente. Solo el operador humano responde aprobaciones.
- ❌ Hacer `restricted-coder` un agente. Es solo un rol que `gemini-cli` asume.
- ❌ Olvidar `denyActions`: `allow + deny` = explicito; solo `allow` = ambiguo.
