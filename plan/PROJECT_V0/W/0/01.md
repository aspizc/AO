| Skills | adapters, tmux, sessions |

## Por que existe?

El MVP2.0 corre el coder en **modo supervisado** (sesion tmux attachable), igual
que Claude (O/0/1) y Gemini (H/I). Hoy `CodexAdapter.spawn/ask/view/kill` lanzan
`ADAPTER_NOT_IMPLEMENTED`. Esta tarea implementa el ciclo supervisado de Codex
reutilizando el `tmux_client` y `session_naming` existentes.

> Realiza la tarea historica P/0/2 con la seleccion de modelo de Stage V.

## Que hay que hacer?

Implementar `spawn` (crear sesion tmux y lanzar `codex` interactivo con
`-m/-c model_reasoning_effort/-s workspace-write/-C`), `ask` (send-keys +
capture-pane), `view` (capture-pane) y `kill` (kill-session), con policy
preflight, audit y dry-run, espejando el claude adapter.

## Pre-requisitos

- W/0/0 mergeado: headless real + config (`AGENTS_CODEX_BIN`, `AGENTS_CODEX_SANDBOX`).
- tmux helpers de H/0/1, H/0/2 disponibles (`buildNewSessionCmd`, `buildSendKeysCmd`,
  `buildCapturePaneCmd`, `buildKillSessionCmd`, `isTmuxAvailable`, `tmuxSync`).
- Detector de intervencion (R/0/1) compatible con la nueva sesion.

## Plan de implementacion paso a paso

### 1. Branch

```bash
git checkout develop && git pull --ff-only || true
git checkout -b feature/W-0-1-codex-supervised-tmux
```

### 2. spawn

Espejar `ClaudeAdapter.spawn`:

- `checkEnabled()`.
- preflight `action: "agent.spawn"` (con `model`/`reasoningEffort`).
- `assertSafeCwd`.
- `buildTmuxTarget({ traceId, agent: "codex", role, prefix })`.
- en modo real: `isTmuxAvailable()`; `new-session` en `cwd`; `send-keys` con la
  linea de arranque:
  ```js
  const launch = [codexBin,
    "-m", model,
    "-c", `model_reasoning_effort="${effort}"`,
    "-s", sandbox,
    "-C", safeCwd];
  ```
- `SESSION_STARTED` mode `supervised` con `tmuxTarget`.
- retorno `{ sessionId, tmuxTarget, attachCommand, dryRun }`.

### 3. ask / view / kill

Identicos en forma a Claude/Gemini:

- `ask`: preflight `agent.ask`, `send-keys` con el prompt, `sleep(tmuxAskDelayMs)`,
  `capture-pane`, audit `SESSION_INPUT`.
- `view`: `capture-pane`.
- `kill`: `kill-session`, `SESSION_CLOSED`.
- dry-run en los tres como en los otros adapters.

### 4. Tests

`tests/gateway/codex_supervised.test.js`:

- `spawn_dry_run_returns_attach_command`.
- `spawn_launch_line_includes_model_effort_sandbox`.
- `disabled_codex_spawn_denied`.
- `restricted_repo_spawn_denied_before_tmux`.
- `ask_view_kill_dry_run_flow`.
- (real con tmux + fake codex, solo si `AGENTS_E2E_REAL` y tmux presentes).

## Errores comunes

- Lanzar `codex exec` (no interactivo) en spawn: para tmux se usa `codex`
  interactivo.
- Olvidar el preflight de `restricted` antes de crear la sesion tmux.
- No incluir modelo/effort/sandbox en la linea de arranque.
- Romper el detector de intervencion (debe seguir siendo best-effort).
