# W/0/2 - Perfil de habilitacion de Codex

## Quick reference

| Campo | Valor |
|---|---|
| Stage | W - Codex real como coder |
| Branch | `feature/W-0-2-codex-enable-profile` |
| Depende de | W/0/1, C/0/1 (policy restricted) |
| Esfuerzo | S (1-2h) |
| Skills | registries, policy, docs |

## Por que existe?

Codex real ya funciona (W/0/0, W/0/1) pero sigue `enabled: false` en el registry
de produccion, que es lo correcto por defecto. Para el MVP2.0 el operador
necesita una forma **explicita y acotada** de habilitar Codex sin tocar el
registry base ni abrir `restricted`. Esta tarea entrega ese perfil de operador y
prueba que la habilitacion no se filtra a `restricted`.

## Que hay que hacer?

Crear un registry de habilitacion superpuesto (overlay) que el operador apunta
via `AGENTS_POLICIES_DIR` (o un override documentado), con
`codex.enabled = true` solo para `allowedClassifications: ["unrestricted", "internal"]`.
Mantener el registry base con `enabled:false`. Documentar y testear que
`restricted` sigue denegado y que el base no cambia.

## Pre-requisitos

- W/0/0 y W/0/1 mergeados.
- Confirmar como el gateway resuelve `AGENTS_POLICIES_DIR` (Stage B/D) para saber
  si el overlay es un directorio alternativo completo o un fichero adicional. Si
  no hay mecanismo de overlay, esta tarea anade el minimo: cargar un
  `agent-capabilities.operator.json` opcional que sobreescribe `enabled`.

## Plan de implementacion paso a paso

### 1. Branch

```bash
git checkout develop && git pull --ff-only || true
git checkout -b feature/W-0-2-codex-enable-profile
```

### 2. Perfil de operador

Crear `policies/profiles/mvp2/agent-capabilities.json` (directorio de policies
alternativo, copia del base) con:

```jsonc
"codex": {
  "binary": "codex",
  "models": ["gpt-5", "gpt-5-codex"],
  "defaultModel": "gpt-5",
  "reasoningEfforts": ["low", "medium", "high"],
  "defaultReasoningEffort": "medium",
  "allowedClassifications": ["unrestricted", "internal"],
  "allowedRoles": ["coder", "reviewer", "tester"],
  "enabled": true,
  "notes": "MVP2.0 operator profile. Codex coder enabled for non-restricted repos only."
}
```

El resto de agentes igual que el base. El operador lo activa con
`AGENTS_POLICIES_DIR=$PWD/policies/profiles/mvp2`.

> Si el equipo prefiere overlay por fichero en vez de directorio completo,
> implementar la carga de `agent-capabilities.operator.json` y documentarlo. La
> decision queda registrada en el PR.

### 3. Guardas

- El base `policies/agent-capabilities.json` mantiene `codex.enabled = false`.
- La policy de C/0/1 sigue prohibiendo Codex en `restricted`
  independientemente del perfil (no se relaja).

### 4. Tests

`tests/gateway/codex_enable_profile.test.js`:

- `base_registry_keeps_codex_disabled`.
- `mvp2_profile_enables_codex_for_unrestricted`.
- `mvp2_profile_still_denies_codex_on_restricted`.
- `mvp2_profile_codex_default_model_gpt5_medium`.

## Errores comunes

- Cambiar el registry base a `enabled:true` (rompe el default seguro).
- Abrir `restricted` a Codex en el perfil.
- Duplicar parcialmente el perfil y dejar registries incoherentes.

## Verificacion manual

AGENTS_POLICIES_DIR=$PWD/policies/profiles/mvp2 agent-run policy validate
AGENTS_POLICIES_DIR=$PWD/policies agent-run policy validate   # base sigue valido
