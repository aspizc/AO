## Quick reference

| Campo | Valor |
|---|---|

| Branch | `feature/P-0-2-codex-supervised-tmux` |

| Esfuerzo | M (3-5h) |

## Por que existe?

Para usar Codex como codificador practico, el operador puede necesitar una
sesion persistente igual que Gemini y Claude: arrancar Codex en tmux, enviar
prompts con `agent.ask`, capturar estado con `agent.view` y cerrar con
`agent.kill`.

## Que hay que hacer?

Implementar `spawn`, `ask`, `view` y `kill` de `CodexAdapter` usando los helpers
tmux existentes, manteniendo dry-run determinista y Codex deshabilitado por
defecto.

## Plan de implementacion paso a paso

### 1. Branch

```bash
git checkout develop && git pull --ff-only || true
git checkout -b feature/P-0-2-codex-supervised-tmux
```

### 2. Adapter supervised

Actualizar `gateway/src/adapters/codex_adapter.js`:

- `spawn`:
  - `checkEnabled`;
  - policy preflight con `agent.spawn`;
  - `assertSafeCwd`;
  - construir `tmuxTarget` con `buildTmuxTarget`;
  - en dry-run no invoca tmux y devuelve `{ sessionId, tmuxTarget,
    attachCommand, dryRun: true }`;
  - en real mode requiere tmux y lanza el binario Codex validado en P/0/1.
- `ask`:
  - policy preflight con `agent.ask`;
  - dry-run devuelve snapshot determinista;
  - real mode usa `send-keys`, espera delay configurable y `capture-pane`.
- `view`:
  - dry-run snapshot determinista;
  - real mode `capture-pane`.
- `kill`:
  - real mode `kill-session`;
  - audita `SESSION_CLOSED`.

### 3. Tests

Actualizar `tests/gateway/codex_adapter.test.js`:

- `enabled_dry_run_spawn_returns_session_info`.
- `enabled_dry_run_ask_view_kill_cycle`.
- `disabled_spawn_fails_closed`.
- `real_spawn_requires_tmux_when_not_dry_run`.
- `spawn_rejects_cwd_outside_allowlist_before_tmux`.

Si la arquitectura actual dificulta testear tmux sin invocarlo, introducir una
inyeccion pequena de cliente tmux en el adapter, siguiendo el estilo de los
tests de Gemini/Claude.

### 4. Integracion MCP

Con K/0/3 ya cerrado, verificar que:

- `agent.spawn` con `agent=codex` falla `ADAPTER_DISABLED` por defecto;
- con registry de test `enabled: true` y `AGENTS_DRY_RUN=1`, el ciclo
  `spawn -> ask -> view -> kill` funciona via MCP.

## Errores comunes

- Invocar tmux en dry-run.
- Saltarse `checkEnabled`.
- Olvidar policy preflight antes de tmux.
- Permitir Codex sobre repos `restricted`.
