# P/0/3 - Codex MCP activation workflow

## Quick reference

| Campo | Valor |
|---|---|
| Stage | P - Codex adapter |
| Branch | `feature/P-0-3-codex-mcp-activation-workflow` |
| Depende de | P/0/2, K/0/4 |
| Esfuerzo | M (4-6h) |

## Por que existe?

P/0/1 y P/0/2 hacen que Codex pueda ejecutar. Esta tarea demuestra que Codex
puede ocupar el rol practico de `coder` dentro del Gateway MCP, con un reviewer
separado, sin tocar repos `restricted` y sin activar Codex por defecto para
todos los operadores.

## Que hay que hacer?

Crear un flujo MCP dry-run donde el orchestrator asigna trabajo a
`codex/coder` sobre `sample-apps` o `developer-tools`, comparte artefactos con
`claude-code/reviewer`, y completa la orquestacion. El test debe usar una copia
temporal de policies donde Codex este `enabled: true`; la policy productiva
sigue `enabled: false`.

## Plan de implementacion paso a paso

### 1. Branch

```bash
git checkout develop && git pull --ff-only || true
git checkout -b feature/P-0-3-codex-mcp-activation-workflow
```

### 2. Policy fixture temporal

Crear helper de test que copie `policies/` a un directorio temporal y cambie
solo:

```json
"codex": { "enabled": true }
```

No modificar `policies/agent-capabilities.json` productivo para habilitar Codex
por defecto.

### 3. E2E MCP

Crear `tests/e2e/mcp_codex_coder_workflow.test.js`:

1. Arrancar Gateway MCP con:
   - `AGENTS_DRY_RUN=1`;
   - `AGENTS_POLICIES_DIR=<temp policies with codex enabled>`;
   - `AGENTS_REPO_ROOTS=<temp repos root>`.
2. `orchestration.create` con orchestrator humano-facing.
3. `task.assign` a `codex/coder` sobre `sample-apps` o `developer-tools`.
4. `agent.delegate` o `agent.spawn` Codex con `taskId`.
5. `artifact.put` de diff interno/no restringido.
6. `task.assign` a `claude-code/reviewer`.
7. `artifact.share` / `artifact.get` para reviewer.
8. `agent.delegate` reviewer.
9. `orchestration.complete`.

Assertions:

- Codex produce `SESSION_STARTED` y `SESSION_CLOSED`.
- Reviewer es una sesion/tarea separada.
- No hay repo `restricted` en el flujo.
- El mismo intento contra `cvision` devuelve `POLICY_DENIED`.

### 4. Manual real smoke opcional

Anadir documentacion para una verificacion manual que solo corre si el operador
lo solicita:

```bash
AGENTS_DRY_RUN=0 AGENTS_CODEX_BIN=codex AGENTS_POLICIES_DIR=<enabled-copy> ...
```

No meter este smoke real en CI.

### 5. Docs

Actualizar:

- `docs/adapters/codex.md` con estado: "real headless/supervised implementado,
  disabled by default".
- `docs/operator-guide.md` con una seccion opcional "Codex as coder for
  unrestricted/internal repos".
- `docs/mvp-acceptance-checklist.md` aclarando que Codex es post-MVP/optional y
  no forma parte del cierre restricted.

## Errores comunes

- Usar Codex en `restricted`.
- Hacer obligatorio Codex para el MVP restricted.
- Requerir red o Codex real en CI.

## Criterios de aceptacion

- [ ] Codex puede actuar como `coder` via MCP en repos no restricted cuando se

- [ ] Codex sigue disabled por defecto en production policies.
- [ ] El intento Codex sobre `restricted` queda denegado.
- [ ] Reviewer separado recibe solo artefactos permitidos.
- [ ] El smoke real queda documentado pero fuera de CI.
