## Por que existe?

Aunque existan el perfil MCP (X/0/0) y el system prompt (X/0/1), falta el
documento que un operador sigue de principio a fin desde la terminal. Esta tarea
entrega ese runbook reproducible: el "como pruebo el MVP2.0".

## Que hay que hacer?

Escribir `docs/mvp2-orchestrator-runbook.md`: pasos numerados desde preparar el
entorno hasta una orquestacion de 2 agentes completada, con un ensayo previo en
dry-run, el arranque real, como hacer attach a tmux, y como leer artefactos y
audit para verificar el resultado.

## Pre-requisitos

- X/0/0 y X/0/1 mergeados.
- Stages V y W completos (modelo + Codex real).

## Plan de implementacion paso a paso

### 1. Branch

```bash
git checkout develop && git pull --ff-only || true
git checkout -b feature/X-0-2-mvp2-runbook
```

### 2. Estructura del runbook

`docs/mvp2-orchestrator-runbook.md` con secciones:

1. **Prerequisitos**: `node`, `tmux`, `codex` (login hecho), `claude` (login
   hecho); repo de trabajo no-restricted.
2. **Instalacion**: venv + `pip install -e cli[dev]` + `npm --prefix gateway install`.
3. **Ensayo dry-run** (obligatorio antes del real):
   ```bash
   AGENTS_DRY_RUN=1 node scripts/smoke_mcp.mjs
   ```
4. **Configurar el perfil real**: copiar
   `client-config/profiles/codex-coder-claude-reviewer/.env.example`, fijar
   `AGENTS_REPO_ROOTS` a la ruta absoluta del repo de trabajo, mantener
   `AGENTS_POLICIES_DIR=./policies/profiles/mvp2`.
5. **Conectar el host MCP**: cargar el `mcp.json` del perfil en el host elegido y
   pegar el system prompt `prompts/orchestrator_mvp2_two_agent.md`.
6. **Lanzar la orquestacion**: dar el objetivo al host (ej.: "implementa X en el
   repo de trabajo, coder Codex, revisalo con Claude"). El host hara
   `agent.spawn` del coder y del reviewer.
7. **Observar**: `tmux ls`, `tmux attach -t ag-...-codex-coder`,
   `tmux attach -t ag-...-claude-reviewer`; o `session.attach_info` via el host.
8. **Verificar resultado**:
   - artefactos en `workspace/artifacts/` (raw vs sanitized);
   - audit en `workspace/audit/events.jsonl` (`SESSION_STARTED`/`CLOSED`,
     `model` efectivo, decisiones de policy);
   - review notes del reviewer.
9. **Troubleshooting**: Codex disabled (perfil incorrecto), cwd fuera de allowlist,
   tmux ausente, modelo no permitido, login de CLIs.

### 3. Enlaces

Enlazar el runbook desde `README.md` (seccion Documentation) y desde
`docs/operator-guide.md`.

## Errores comunes

- Saltarse el ensayo dry-run y depurar contra ejecucion real.
- No fijar `AGENTS_REPO_ROOTS` (cwd violation garantizado).
- Olvidar el login de `codex`/`claude` (fallo opaco).
- Documentar un host concreto como obligatorio (debe ser host-agnostico).

## Verificacion manual

Seguir el runbook en una maquina limpia (o describirlo paso a paso) y confirmar
que un dry-run completa y que el real spawnea ambas sesiones. Las rutas y
comandos citados deben existir tras V/W/X.
