## Por que existe?

Para "lanzar el orquestador desde una terminal" el operador necesita una
configuracion MCP lista que cablee el gateway en modo real con Codex coder
(gpt-5 medium, workspace-write) y Claude reviewer (opus-4.7). Hoy solo existe
`client-config/mcp.json.example` en dry-run y sin modelos. Esta tarea entrega el
perfil concreto del MVP2.0.

## Que hay que hacer?

Crear un perfil `client-config/profiles/codex-coder-claude-reviewer/` con un
`mcp.json` (real, apuntando al perfil de policies MVP2) y un `.env.example` con
todas las variables necesarias y comentarios. El perfil es host-agnostico.

## Pre-requisitos

- W/0/2 mergeado: existe `policies/profiles/mvp2/`.
- V/* mergeado: modelos plumbeados.
- Conocer las env vars del README (`AGENTS_*`).

## Plan de implementacion paso a paso

### 1. Branch

```bash
git checkout develop && git pull --ff-only || true
git checkout -b feature/X-0-0-two-agent-mcp-profile
```

### 2. mcp.json del perfil

`client-config/profiles/codex-coder-claude-reviewer/mcp.json`:

```jsonc
{
  "mcpServers": {
    "agents-gateway": {
      "transport": "stdio",
      "command": "node",
      "args": ["./gateway/src/mcp_server.js"],
      "env": {
        "AGENTS_WORKSPACE": "./workspace",
        "AGENTS_POLICIES_DIR": "./policies/profiles/mvp2",
        "AGENTS_DRY_RUN": "0",
        "AGENTS_REPO_ROOTS": "REEMPLAZAR_RUTA_ABSOLUTA_DEL_REPO_DE_TRABAJO",
        "AGENTS_CLAUDE_BIN": "claude",
        "AGENTS_CODEX_BIN": "codex",
        "AGENTS_CODEX_SANDBOX": "workspace-write"
      }
    }
  }
}
```

### 3. .env.example del perfil

`client-config/profiles/codex-coder-claude-reviewer/.env.example` con las mismas
variables, comentadas, mas notas:

- `AGENTS_REPO_ROOTS`: rutas absolutas permitidas; **debe** incluir el repo de
  trabajo del coder.
- recordatorio: poner `AGENTS_DRY_RUN=1` para un ensayo seguro antes del real.
- defaults de modelo vienen del perfil de policies (gpt-5/medium, opus-4.7); no
  hace falta fijarlos por env.

### 4. README del perfil

`client-config/profiles/codex-coder-claude-reviewer/README.md`: que cablea,
agentes/roles/modelos esperados, y enlace al runbook (X/0/2).

### 5. Verificacion

Validar que el JSON es parseable y que el perfil de policies referenciado existe.

## Errores comunes

- Dejar `AGENTS_DRY_RUN=1` en el perfil "real".
- Hardcodear una ruta de repo concreta del autor en `AGENTS_REPO_ROOTS`.
- Apuntar `AGENTS_POLICIES_DIR` al base (Codex disabled) en vez del perfil MVP2.
- Configurar un IDE concreto (fuera de scope).
