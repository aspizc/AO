## Por que existe?

Para lanzar el bucle desde terminal hace falta una configuracion MCP lista que
cablee el gateway con planner y coder (ambos claude-code, opus-4.7) operando sobre
este repo. Esta tarea entrega ese perfil, analogo al de X/0/0 pero para
planificacion.

## Que hay que hacer?

Crear `client-config/profiles/planner-assisted/` con `mcp.json` + `.env.example` +
`README.md`, apuntando `AGENTS_REPO_ROOTS` a este repo y usando el registry base
(no hace falta el perfil MVP2 porque el bucle no usa Codex).

## Pre-requisitos

- Z/0/0 mergeado: este repo registrado `internal`.
- Z/0/1 mergeado: prompts disponibles.
- V/0/2 mergeado: claude honra `--model`.

## Plan de implementacion paso a paso

### 1. Branch

```bash
git checkout develop && git pull --ff-only || true
git checkout -b feature/Z-0-2-planning-mcp-profile
```

### 2. mcp.json

`client-config/profiles/planner-assisted/mcp.json`:

```jsonc
{
  "mcpServers": {
    "agents-gateway": {
      "transport": "stdio",
      "command": "node",
      "args": ["./gateway/src/mcp_server.js"],
      "env": {
        "AGENTS_WORKSPACE": "./workspace",
        "AGENTS_POLICIES_DIR": "./policies",
        "AGENTS_DRY_RUN": "1",
        "AGENTS_REPO_ROOTS": "RUTA_ABSOLUTA_DE_ESTE_REPO",
        "AGENTS_CLAUDE_BIN": "claude"
      }
    }
  }
}
```

`AGENTS_DRY_RUN=1` por defecto (ensayo seguro); el operador pone `0` para real.
No se incluye Codex.

### 3. .env.example

`client-config/profiles/planner-assisted/.env.example` con las variables
comentadas y notas:

- `AGENTS_REPO_ROOTS` debe ser la ruta absoluta de `agents-orchestrator`.
- defaults de modelo (claude-opus-4-7) vienen del registry base.
- recomendar trabajar en una rama dedicada de plan antes del real.

### 4. README del perfil

`client-config/profiles/planner-assisted/README.md`: roles/modelos
(planner+coder claude-opus-4-7), enlace a los tres prompts (Z/0/1) y al runbook
(Z/0/3), y la advertencia de scope (`plan/**` + aprobacion humana + rama).

### 5. Verificacion

JSON parseable; el repo referenciado existe y esta registrado en
`repositories.json`.

## Errores comunes

- Apuntar `AGENTS_REPO_ROOTS` a otro repo (el coder no podria escribir el plan).
- Dejar el perfil en `DRY_RUN=0` por defecto.
- Incluir Codex o el perfil de policies MVP2 (innecesario aqui).
