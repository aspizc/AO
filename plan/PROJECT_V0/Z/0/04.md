| Skills | approvals, prompts, docs |

## Por que existe?

El bucle de planificacion pausa en una puerta de aprobacion humana (`plan.apply`)
antes de aceptar los diffs del coder. El operador quiere poder dejarlo correr de
forma autonoma. El mecanismo de auto-approval ya existe (Q/0/5); esta tarea solo
**define la puerta `plan.apply`** del bucle y la **suscribe** al scope autonomo,
sin reimplementar nada.

## Que hay que hacer?

Asegurar que la fase apply del bucle pide approval con `action: "plan.apply"`,
documentar que `AGENTS_AUTOAPPROVE=plan.apply` activa el modo autonomo del bucle, y
ajustar prompts/runbook. El comportamiento por defecto (humano revisa) no cambia.

## Pre-requisitos

- Q/0/5 mergeado (mecanismo de auto-approval acotada + `AGENTS_AUTOAPPROVE`).
- Z/0/1 (prompts) y Z/0/2 (perfil) mergeados.

## Plan de implementacion paso a paso

### 1. Branch

```bash
git checkout develop && git pull --ff-only || true
git checkout -b feature/Z-0-4-plan-autoapprove-scope
```

### 2. Puerta `plan.apply`

En `prompts/orchestrator_planning_loop.md` (Z/0/1): la fase apply debe solicitar
`approval.request({ action: "plan.apply", context: { repo, scope: "plan/**" } })`
antes de que el coder escriba, y esperar con `approval.wait`. Si el operador
habilito el scope, Q/0/5 lo auto-concede; si no, espera al humano.

### 3. Modo autonomo (documentar)

- `AGENTS_AUTOAPPROVE=plan.apply` activa el modo (lo pone el operador al lanzar).
- Anadir seccion **Autonomous mode** al prompt del orquestador:
  - el bucle no pausa en `plan.apply`;
  - el planner **sigue revisando** el diff y registrando `review_notes`;
  - las `OPEN DECISIONS` sin respuesta se resuelven con la opcion recomendada del
    planner, dejando constancia en review_notes y audit;
  - trabajo siempre en rama; nunca push autonomo.

### 4. Perfil y runbook

- `client-config/profiles/planner-assisted/.env.example`: documentar
  `AGENTS_AUTOAPPROVE` (default vacio; ejemplo `plan.apply`).
- `docs/planning-loop-runbook.md`: seccion "Modo autonomo": como activarlo, que
  auto-concede (`plan.apply`) y que no, y como auditar
  (`grep APPROVAL_AUTO_GRANTED`).

### 5. Tests

`tests/gateway/plan_autoapprove_scope.test.js`:

- `plan_apply_pending_when_scope_absent`.
- `plan_apply_auto_granted_when_scope_present` (audit `APPROVAL_AUTO_GRANTED`).
- `plan_apply_never_grants_protected_push_even_with_scope`.

(Reutilizan el mecanismo de Q/0/5; aqui se valida el scope concreto.)

## Errores comunes

- Reimplementar el auto-grant (vive en Q/0/5).
- Usar un `action` distinto de `plan.apply` (rompe el scope).
- Hacer el modo el default.
- Permitir push autonomo desde el bucle.
