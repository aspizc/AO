# Z/0/3 - Runbook + smoke de planificacion asistida

## Quick reference

| Campo | Valor |
|---|---|
| Stage | Z - Planificacion asistida |
| Branch | `feature/Z-0-3-planning-runbook-smoke` |
| Depende de | Z/0/2, R/0/0 (attach info) |
| Esfuerzo | M (3-5h) |
| Skills | docs, scripting, MCP stdio |

## Por que existe?

Faltan el documento que el operador sigue para usar el bucle de planificacion de
punta a punta y una prueba que valide los primitivos del bucle sin romper CI.
Esta tarea entrega ambos.

## Que hay que hacer?

Escribir `docs/planning-loop-runbook.md` (draft -> apply -> review -> escalate ->
converge) y `scripts/smoke_planning.mjs` (dry-run por defecto) que ejercita la
secuencia: delegar planner, recibir artefacto de plan con `OPEN DECISIONS`,
delegar coder de aplicacion, recibir review_notes del planner.

## Pre-requisitos

- Z/0/2 mergeado (perfil).
- Stage V completo (model selection).

## Plan de implementacion paso a paso

### 1. Branch

```bash
git checkout develop && git pull --ff-only || true
git checkout -b feature/Z-0-3-planning-runbook-smoke
```

### 2. Runbook

`docs/planning-loop-runbook.md`:

1. **Prerequisitos**: node, `claude` logueado; trabajar en rama de plan
   (`git checkout -b plan/refine-stage-<x>`).
2. **Ensayo dry-run**: `node scripts/smoke_planning.mjs`.
3. **Configurar perfil real**: copiar `.env.example`, fijar `AGENTS_REPO_ROOTS` a
   este repo, `AGENTS_DRY_RUN=0`.
4. **Conectar host + prompts**: cargar el `mcp.json` del perfil y los prompts de
   Z/0/1 (planner / coder / orquestador).
5. **Bucle**:
   - pedir al host: "refina el Stage W conmigo";
   - el planner redacta -> responde sus `OPEN DECISIONS`;
   - apruebas la aplicacion (`approval.request`) -> el coder escribe `plan/*.md`;
   - el planner revisa el diff y propone correcciones -> iteras;
   - cuando estes conforme, cierras (`orchestration.complete`).
6. **Verificar**: `git diff plan/` (solo `plan/**` tocado), review_notes en
   `workspace/artifacts/`, audit en `workspace/audit/events.jsonl` (roles
   planner/coder, modelo `claude-opus-4-7`).
7. **Seguridad/troubleshooting**: si el coder intenta tocar fuera de `plan/**`,
   abortar; nunca aprobar sin leer el `git diff`; revertir con `git checkout`.

### 3. Smoke

`scripts/smoke_planning.mjs` (espejo de `smoke_mcp.mjs`):

- conecta MCP stdio; verifica `tools/list`.
- dry-run: delegate planner (role planner, model claude-opus-4-7) -> simula
  `artifact.put.plan` con `OPEN DECISIONS` -> delegate coder (role coder) ->
  planner review -> `artifact.put.review_notes`.
- imprime resumen: roles, modelo, artefactos, audit; exit code segun exito.

### 4. Enlazar y Scope

Referenciar el runbook desde `README.md` y `docs/operator-guide.md`. Ademas,
anadir la **planificacion asistida** (bucle planner+coder, ADR-007) a la seccion
Scope/Documentation del `README.md` como capacidad disponible.

## Errores comunes

- Smoke que arranca real sin avisar (default debe ser dry-run).
- Runbook que omite la puerta de aprobacion humana o el `git diff`.
- No verificar que solo se toco `plan/**`.
- Documentar un host concreto como obligatorio (debe ser host-agnostico).
