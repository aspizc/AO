## Por que existe?

El reviewer del MVP2.0 debe correr en **Claude Opus 4.7**. El claude adapter ya
ejecuta real (`claude --print` headless y `claude` en tmux), pero **no** pasa
`--model`, asi que usa el modelo por defecto del CLI del operador. Esta tarea
hace que el adapter respete el `model` resuelto por la policy.

## Que hay que hacer?

Hacer que `ClaudeAdapter.delegate` y `ClaudeAdapter.spawn` reciban `model` y
construyan la invocacion con `claude --model <id>`. Default efectivo
`claude-opus-4-7` (proviene del registry via V/0/0; el adapter no hardcodea otra
cosa). Cubrir con tests usando binario fake que captura argv.

## Pre-requisitos

- V/0/1 mergeado: el service pasa `model` resuelto al adapter.
- Claude CLI local verificado: `claude --model` acepta alias (`opus`) o nombre
  completo (`claude-opus-4-7`). Ya validado en `claude` 2.1.150.

## Plan de implementacion paso a paso

### 1. Branch

```bash
git checkout develop && git pull --ff-only || true
git checkout -b feature/V-0-2-claude-model-select
```

### 2. Headless (`delegate`)

En `gateway/src/adapters/claude_adapter.js`, en modo real:

```js
const args = ["--print", "--output-format", "json",
  "--permission-mode", "dontAsk", "--no-session-persistence"];
if (model) args.push("--model", model);
args.push(prompt);
spawnSync(claudeBin(this.config), args, { ... });
```

El dry-run debe reflejar el modelo en su salida simulada
(`[dry-run claude model=<model>]`) para que los tests E2E lo verifiquen.

### 3. Supervised (`spawn`)

La linea de arranque en tmux debe incluir el modelo:

```js
const launch = [claudeBin(this.config)];
if (model) launch.push("--model", model);
buildSendKeysCmd({ target: tmuxTarget, line: launch.join(" ") });
```

`ask`/`view`/`kill` no cambian (operan sobre la sesion ya lanzada).

### 4. Tests

Actualizar `tests/gateway/claude_adapter.test.js`:

- `delegate_real_passes_model_flag` (binario fake captura argv incluye `--model claude-opus-4-7`).
- `delegate_without_model_omits_flag` (compat).
- `spawn_launch_line_includes_model` (dry-run inspecciona la send-keys line).
- `dry_run_delegate_reports_model`.

El binario fake es un script temporal que vuelca su argv; nunca el `claude` real
en CI.

## Errores comunes

- Hardcodear `claude-opus-4-7` en el adapter en vez de leer el resuelto.
- Pasar `--model` cuando es null (genera argv invalido).
- Olvidar el modelo en la rama supervised (solo arreglar headless).
- Usar el `claude` real en tests.
