## ¿Por que existe?

Antes de escribir el adapter, el operador necesita decidir el **modo de invocacion** soportado: ¿hay flag `--print` para headless? ¿se invoca solo como REPL en tmux? Documentarlo evita reescribir el adapter cuando descubrimos que la flag asumida no existe.

## ¿Que hay que hacer?

Crear `docs/adapters/claude-code.md` con:

1. Nombre del binario.
2. Modo headless (si existe, comando exacto; si no, anota "tmux only").
3. Modo supervisado tmux.
4. Dry-run fallback.
5. Manual checklist para verificar version del CLI.

### 2. `docs/adapters/claude-code.md`

```markdown
# Claude Code adapter

This document captures the Claude Code CLI assumptions used by the
adapter `gateway/src/adapters/claude_adapter.js`.

## Binary

- Default: `claude` (configurable via `AGENTS_CLAUDE_BIN`).
- Tested version: <fill version after running `claude --version`>.

## Headless mode

- Investigate: `claude --help | grep -E 'print|prompt|headless'`.
- If a non-interactive flag exists, document the exact command. Until
  verified, the adapter falls back to **tmux supervised** for all
  invocations.

## Supervised tmux mode

- Identical to Gemini supervised mode (H/0/0 + I/0/1).
- `claude` is launched inside a tmux session named via `buildTmuxTarget`.

## Dry-run fallback

- When `AGENTS_DRY_RUN=1`, the adapter returns deterministic mocks and
  audits `SESSION_STARTED/CLOSED`. Network and binary are not required.

## Manual verification checklist

- [ ] `claude --version` succeeds and is recorded above.
- [ ] `claude` is on PATH or `AGENTS_CLAUDE_BIN` points to it.
- [ ] tmux is available (`tmux -V`).
- [ ] Adapter dry-run tests pass (`O/0/1`).
```
