## ¿Por que existe?

V4 origina como blocking; el feedback del operador exigio un cambio: **MCP nunca debe quedar colgado** indefinidamente. La semantica final:

```text
approval.request(...)              -> { approvalId, status: "pending" }   # never blocks
approval.respond(approvalId, ...)  -> { approvalId, status: "granted"|"denied" }
approval.poll(approvalId)          -> { status }                          # cheap status read
```

`approval.wait` (Q/0/4) se construye encima usando un `EventEmitter` interno — pero solo `wait` puede bloquear, y siempre con timeout acotado por servidor.

## ¿Que hay que hacer?

`gateway/src/services/approval_service.js` con `request`, `respond`, `poll`, mas un `EventEmitter` por approval. Audit `APPROVAL_REQUIRED/GRANTED/DENIED`.

### 2. Service

```javascript
import { EventEmitter } from "node:events";
import { newApprovalId } from "../core/ids.js";
import * as repo from "../core/repositories/approval_repo.js";
import { append as auditAppend } from "../core/audit.js";

const _bus = new EventEmitter();

export const approvalBus = _bus; // exposed for Q/0/4

export function request({ traceId, action, requestedBy, context }) {
  const approvalId = newApprovalId();
  repo.createPendingApproval({
    approvalId, traceId: traceId || null, action,
    requestedBy, createdAt: new Date().toISOString(),
    payload: context ? JSON.stringify(context) : null
  });
  auditAppend({ type: "APPROVAL_REQUIRED", traceId, approvalId, action, requestedBy });
  return { approvalId, status: "pending" };
}

export function respond({ approvalId, decision, decidedBy, note }) {
  if (!["granted","denied"].includes(decision)) {
    throw new Error(`invalid decision ${decision}`);
  }
  const row = repo.getApproval(approvalId);
  if (!row) throw new Error(`approval ${approvalId} not found`);
  if (row.status !== "pending") {
    // idempotent: return current status without throwing
    return { approvalId, status: row.status };
  }
  const updated = repo.decideApproval(approvalId, decision, decidedBy, note);
  auditAppend({
    type: decision === "granted" ? "APPROVAL_GRANTED" : "APPROVAL_DENIED",
    traceId: row.trace_id, approvalId, decidedBy, note: (note || "").slice(0, 500)
  });
  _bus.emit(approvalId, { approvalId, status: decision, decidedAt: updated.decided_at });
  return { approvalId, status: decision, decidedAt: updated.decided_at };
}

export function poll({ approvalId }) {
  const row = repo.getApproval(approvalId);
  if (!row) return { error: "NOT_FOUND" };
  return { approvalId, status: row.status, decidedAt: row.decided_at };
}
```

### 3. Test

`tests/gateway/approval_service.test.js` con casos enumerados en backlog: `request_returns_pending_immediately`, `respond_grants/denies_pending_approval`, `cannot_respond_twice` (idempotente, no throw), `poll_returns_current_status`, `request_audits_approval_required`, `respond_audits_granted_or_denied`.

## Errores comunes

- ❌ Hacer `respond` que tira excepcion en double-respond. **Idempotente**: devuelve estado actual.
- ❌ Olvidar emitir en el bus. Q/0/4 depende de eso.
- ❌ Permitir respond con `decision: "expired"` desde el operador. Solo `granted|denied`.
