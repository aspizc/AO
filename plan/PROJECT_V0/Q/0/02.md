## ¿Por que existe?

Exponer el async-first approval workflow al LLM-orchestrator y al CLI del operador via MCP. Sin estas tools, el operador y el orquestador no se pueden comunicar.

## ¿Que hay que hacer?

`gateway/src/tools/approval.js` con `approval.request`, `approval.respond`, `approval.poll`. La tool `approval.wait` se anade en Q/0/4. Todas no bloquean.

### 2. Tools

```javascript
import { defineTool, z } from "./tool_helpers.js";
import * as svc from "../services/approval_service.js";

export function buildApprovalTools() {
  return [
    defineTool({
      name: "approval.request",
      description: "Create a pending approval. Non-blocking. Returns immediately with status='pending'. " +
                   "Use approval.poll or approval.wait (Q/0/4) to learn the outcome.",
      schema: z.object({
        traceId: z.string().optional(),
        action: z.string(),
        requestedBy: z.string(),
        context: z.record(z.any()).optional()
      }),
      handler: svc.request
    }),
    defineTool({
      name: "approval.respond",
      description: "Operator decides a pending approval. Idempotent on already-decided approvals.",
      schema: z.object({
        approvalId: z.string(),
        decision: z.enum(["granted","denied"]),
        decidedBy: z.string(),
        note: z.string().optional()
      }),
      handler: svc.respond
    }),
    defineTool({
      name: "approval.poll",
      description: "Cheap status read. Always non-blocking.",
      schema: z.object({ approvalId: z.string() }),
      handler: svc.poll
    })
  ];
}
```

### 3. Registrar en `tools/index.js`

```javascript
...buildApprovalTools(),
```
