## ¿Por que existe?

Algunos clientes prefieren **bloquearse** esperando una decision. Necesitamos una primitiva acotada: `approval.wait(approvalId, timeoutMs)` que:

- Devuelve inmediato si ya esta decidido.
- Suscribe al `EventEmitter` por `approvalId` (Q/0/1).
- Cae en `pending` si pasa el timeout.
- **Nunca** excede `AGENTS_APPROVAL_MAX_WAIT_MS` aunque el cliente pida mas.

Esto es la unica tool que puede bloquear, y siempre acotada.

## ¿Que hay que hacer?

Anadir `waitForDecision` al service y la tool MCP `approval.wait`.

### 2. Service `waitForDecision`

```javascript
import { approvalBus, poll } from "./approval_service.js";

export async function waitForDecision({ approvalId, timeoutMs, serverMaxMs }) {
  const cap = Math.min(timeoutMs ?? serverMaxMs, serverMaxMs);
  const current = poll({ approvalId });
  if (current.status && current.status !== "pending") {
    return { approvalId, status: current.status, decidedAt: current.decidedAt };
  }
  return await new Promise((resolve) => {
    let resolved = false;
    const onChange = (payload) => {
      if (resolved) return; resolved = true;
      clearTimeout(timer); approvalBus.off(approvalId, onChange);
      resolve(payload);
    };
    const timer = setTimeout(() => {
      if (resolved) return; resolved = true;
      approvalBus.off(approvalId, onChange);
      auditAppend({ type: "APPROVAL_WAIT_TIMEOUT", approvalId });
      const cur = poll({ approvalId });
      resolve({ approvalId, status: cur.status || "pending" });
    }, cap);
    approvalBus.on(approvalId, onChange);
  });
}
```

### 3. Tool MCP

```javascript
defineTool({
  name: "approval.wait",
  description: "Wait for an approval decision, bounded by AGENTS_APPROVAL_MAX_WAIT_MS server cap. " +
               "Returns 'pending' if cap reached. Concurrent calls are independent.",
  schema: z.object({
    approvalId: z.string(),
    timeoutMs: z.number().int().positive().optional()
  }),
  handler: ({ approvalId, timeoutMs }) =>
    waitForDecision({ approvalId, timeoutMs, serverMaxMs: config.approvalMaxWaitMs })
})
```

- `wait_audit_event_includes_outcome`: revisa `APPROVAL_WAIT_TIMEOUT` o `APPROVAL_GRANTED` segun caso.

## Errores comunes

- ❌ Olvidar `clearTimeout` y `off`. Memory leak.
- ❌ Permitir `timeoutMs` indefinido sin cap. Siempre `Math.min(_, serverMax)`.
- ❌ Bloquear el bus completo con un wait largo. Usa listener por id.
