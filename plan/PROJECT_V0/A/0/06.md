## ¿Por que esta tarea existe?

V4 lista riesgos en §29, pero quedan como prosa. Para que esos riesgos se traduzcan en **tests reales** y **controles concretos**, necesitamos un threat model formal **antes** de escribir registries y policy. Cada amenaza debe terminar con `Tested by: <test-id>` apuntando a algo verificable.

Ademas, este documento es el input directo de `U/0/4` (Bypass regression suite), donde **una amenaza == al menos un test bypass**.

## ¿Que hay que hacer?

Crear `docs/threat-model.md` con 10 categorias minimas de amenaza. Cada una con: descripcion, capacidad del atacante, control primario, defensa en profundidad y un campo `Tested by:` (puede apuntar a tests futuros). Cross-link desde `architecture.md` y `README.md`.

Categorias **obligatorias** (minimo 10):

```markdown
# Threat model

This document is the source of truth for known abuse cases of the
agents-orchestrator V4 system. Each threat references a test that
demonstrates the control works (existing or planned).

It is a **living document**: every incident, new adapter, or new tool
must add or update entries here.

## Scope

- In: Gateway, registries, adapters (Gemini/Claude/Codex), artifact store,
  sanitizer, audit log, approvals.
- Out: hosting platforms, cloud, multi-user authentication.

## Threats

### TM-01 — Prompt injection against the orchestrator-LLM

- **Description:** An attacker-controlled artifact (review notes, sanitized
  diff, message) instructs the LLM in role `orchestrator` to call tools it
  should not, e.g. `artifact.get` of a raw restricted artifact.
- **Attacker capability:** can place text inside artifacts the orchestrator
  reads. Cannot tamper with the Gateway code.
- **Primary control:** policy engine denies forbidden actions regardless of
  orchestrator intent (ADR-017 V4).
- **Defense in depth:** sanitizer redacts secrets; audit logs every denied
  attempt; bypass regression suite asserts deny.
- **Tested by:** `C/0/2` table tests, `U/0/4#prompt_injection_against_orchestrator_cannot_get_raw_restricted`

### TM-02 — Child tries to leak raw restricted in summaries

- **Description:** A `restricted-coder` produces a summary that smuggles
  raw restricted strings, hoping the orchestrator forwards it.
- **Attacker capability:** controls subprocess output.
- **Primary control:** `artifact.put` with classification `restricted`
  always triggers sanitization for raw kinds (`raw_diff`, `raw_code`,
  `raw_stacktrace`); sanitized artifact is what crosses boundaries.
- **Defense in depth:** sanitizer fail-closed; visibility matrix tests.
- **Tested by:** `M/0/2`, `M/0/3`, `U/0/4#child_summary_does_not_leak_raw_restricted_after_sanitizer`

### TM-03 — Bypass via shared filesystem

- **Description:** A child writes outside the artifact store, hoping
  another role can read it directly.
- **Attacker capability:** can write inside its `cwd` (the repo root).
- **Primary control:** the only legitimate cross-role channel is the
  artifact store. Adapters are confined to their `cwd`; sibling repo
  paths are not in any allowlist.
- **Defense in depth:** policy denies cross-trace artifact lookups;
  bypass test ensures siblings cannot see arbitrary files.
- **Tested by:** `H/0/2`, `U/0/4#filesystem_bypass_outside_artifact_store_is_not_visible_to_other_role`

### TM-04 — Bypass via direct `cwd`

- **Description:** A caller passes a `cwd` that escapes the allowed roots
  (using `..`, symlink, or absolute path).
- **Primary control:** `assertSafeCwd` resolves with `realpath` and
  checks against `AGENTS_REPO_ROOTS`. Reject before policy.
- **Defense in depth:** policy double-checks repo classification.
- **Tested by:** `H/0/2`, `U/0/4#cwd_outside_allowlist_is_rejected_before_spawn`,
  `U/0/4#cwd_symlink_escape_is_rejected`

### TM-05 — Unaudited tmux intervention

- **Description:** Operator attaches to a child tmux session and types
  commands; the system does not learn about it.
- **Primary control:** `intervention_detector` (best-effort) emits
  `HUMAN_TMUX_INTERVENTION`. `session.intervention_note` lets the
  operator record manual notes.
- **Defense in depth:** documentation explicitly classifies tmux as
  best-effort observation/intervention, not a primary control plane.
- **Tested by:** `R/0/1`, `R/0/2`, `U/0/4#tmux_intervention_is_audited_or_flagged`

### TM-06 — Sanitizer failure / partial redaction

- **Description:** A regex misses a secret, OR the sanitizer crashes.
- **Primary control:** fail-closed: if sanitizer fails, raw is NOT
  returned; cross-boundary `get` is denied.
- **Defense in depth:** sanitizer rules are versioned and tested; new
  rules require tests.
- **Tested by:** `M/0/3`, `U/0/4#sanitizer_failure_blocks_cross_boundary_get`

### TM-07 — Approval spoofing / replay

- **Description:** A caller responds with a stolen `approvalId`, OR
  replays a granted approval to escalate twice.
- **Primary control:** `approvalId` is UUID v4; transitions are
  one-shot (`pending` -> `granted|denied`); double-respond is rejected.
- **Defense in depth:** state machine tests; audit log integrity.
- **Tested by:** `Q/0/0`, `U/0/4#approval_respond_replay_does_not_grant_again`,
  `U/0/4#approval_respond_with_unknown_id_is_rejected`

### TM-08 — Artifact poisoning

- **Description:** A child publishes artifacts crafted to confuse the
  orchestrator-LLM (e.g. fake `review_notes` instructing dangerous
  actions).
- **Primary control:** orchestrator's privileges are limited (no
  `code.write`, no raw restricted). Even if confused, policy blocks.
- **Defense in depth:** sanitizer; visibility matrix; metric on denies
  per orchestrator session.
- **Tested by:** `C/0/2`, `N/0/2`, `U/0/4#prompt_injection_against_orchestrator_cannot_code_write`

### TM-09 — Cross-trace data leakage

- **Description:** A session asks for an artifact or message of another
  `traceId`.
- **Primary control:** every query in services and repositories scopes
  by `traceId`. No global lookups.
- **Defense in depth:** policy denies if requester not in same trace.
- **Tested by:** `L/0/2`, `S/0/0`, `U/0/4#cross_trace_artifact_access_denied`,
  `U/0/4#cross_trace_message_access_denied`

### TM-10 — MCP stdout corruption

- **Description:** The Gateway accidentally writes a log line to stdout,
  corrupting the MCP protocol stream.
- **Primary control:** all logs go to stderr; tests assert stdout has
  only protocol frames.
- **Defense in depth:** lint rule / smoke test in CI.
- **Tested by:** `G/0/0` smoke, `U/0/4#mcp_stdout_only_contains_protocol_frames`

### TM-11 — Approval wait DoS / hung session

- **Description:** A long approval wait freezes an MCP client.
- **Primary control:** `approval.request` is non-blocking; `approval.wait`
  is bounded by `AGENTS_APPROVAL_MAX_WAIT_MS`.
- **Defense in depth:** poll fallback; timeout audit event.
- **Tested by:** `Q/0/4`, `U/0/4#approval_wait_never_exceeds_server_cap`

## Living document

This document grows with the system. New stages must update it when
they introduce new abuse vectors. The bypass regression suite
(`tests/e2e/bypass_regression.test.js`, see U/0/4) MUST cover every
threat listed here.
```

### 4. Test estructural

`tests/structure/test_threat_model.py`:

```python
import re
from pathlib import Path

DOC = Path(__file__).resolve().parents[2] / "docs" / "threat-model.md"


def test_threat_model_doc_exists():
    assert DOC.is_file()


def test_required_categories_are_covered():
    text = DOC.read_text(encoding="utf-8")
    for tag in (f"TM-{n:02d}" for n in range(1, 12)):
        assert tag in text, f"missing threat: {tag}"


def test_each_abuse_case_has_tested_by():
    text = DOC.read_text(encoding="utf-8")
    sections = re.split(r"^### (TM-\d{2}.*)$", text, flags=re.MULTILINE)
    pairs = list(zip(sections[1::2], sections[2::2]))
    assert pairs, "no threat sections found"
    for header, body in pairs:
        assert "Tested by:" in body, f"missing Tested by in {header}"


def test_living_document_section_exists():
    text = DOC.read_text(encoding="utf-8")
    assert "Living document" in text
```
