### 3. ADR-004

`docs/adr/ADR-004-mvp-scope.md`:

```markdown
# ADR-004: MVP scope

- **Status:** Accepted
- **Date:** <today>

## Context

V4 lists many capabilities that go beyond what is strictly required to
prove "safe collaboration mediated by a local Gateway". We need to
fix the MVP perimeter to a deliverable scope.

## Decision

In MVP we deliver:

1. MCP Gateway (`agents-gateway`) over stdio (G).
2. Deterministic policy engine (C) and registries (B).
3. Append-only audit (D) + auxiliary CLI (E).
4. SQLite state, repositories (F).
5. Adapters for Gemini, Claude (DRY) and a Codex stub (I/O/P), all
   with `assertSafeCwd` and tmux supervision (H).
6. Orchestration / task / agent / artifact / approval / session /
   message tools (J/K/L/M/N/Q/R/S).
7. Async approvals with bounded `approval.wait` (Q).
8. Threat model + bypass regression suite (A/0/6 + U/0/4).
9. Operator guide + generic MCP config + orchestrator system prompt (T).

We **defer** to post-MVP:

- Postgres / Redis / event bus (V/0/0–1).
- LangGraph deterministic orchestrator client (V/0/2).
- Internal MCP servers (`mcp-jira-read`, ...) (V/0/3).
- IDE-specific configurations (Cursor, Antigravity, ...).

## Consequences

- The MVP is provable in CI without network or restricted repos.
- Future scope changes go through additional ADRs.
- Reviewers can decline PRs that reach into deferred scope without
  an updated ADR.
```
