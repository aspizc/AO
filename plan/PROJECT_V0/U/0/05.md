# U/0/5 - Operational usability gate

## Quick reference

| Campo | Valor |
|---|---|
| Stage | U - E2E and MVP closure |
| Branch | `feature/U-0-5-operational-usability-gate` |
| Depende de | K/0/4 |
| Esfuerzo | S-M (2-4h) |

## Por que existe?

U/0/4 cerro el MVP contra un E2E in-process y pruebas de bypass, pero no
garantiza que un cliente MCP real pueda usar el caso practico de
orchestrator + coder + reviewer. Despues de K/0/3 y K/0/4, necesitamos un gate
final que declare listo el flujo operacional desde la superficie MCP real.

Codex no es requisito para este gate. Si se quiere Codex como coder, P/0/3 debe
correr ademas como gate opcional.

## Que hay que hacer?

Actualizar CI, docs y checklist para que "listo para uso practico" signifique:

- `tools/list` expone `agent.*`;
- hay un E2E MCP stdio real de orchestrator + coder + reviewer;
- la guia de operador reproduce exactamente ese flujo;
- el checklist de aceptacion referencia la evidencia nueva;
- Codex queda marcado como opcional/post-MVP salvo que P/0/3 este cerrado.

## Plan de implementacion paso a paso

### 1. Branch

```bash
git checkout develop && git pull --ff-only || true
git checkout -b feature/U-0-5-operational-usability-gate
```

### 2. CI y smoke

Actualizar `scripts/ci.sh` si hace falta para ejecutar:

- `node scripts/smoke_mcp.mjs`;
- `node --test tests/e2e/mcp_two_agent_workflow.test.js`;
- todos los E2E existentes.

El smoke MCP debe fallar si `agent.spawn` o `agent.ask` no estan disponibles.

### 3. Checklist

Actualizar `docs/mvp-acceptance-checklist.md`:

- criterio 7 debe incluir `tests/gateway/tool_agent.test.js` y
  `tests/e2e/mcp_two_agent_workflow.test.js`;
- criterio 12 debe referenciar el E2E MCP real;
- criterio 15-17 deben diferenciar "adapter primitives exist" de "MCP can
  execute them";
- notas deben explicar que Codex real es opcional y se valida por P/0/3.

No marcar items `[x]` en esta tarea salvo que el reviewer lo haga
explicitamente con evidencia.

### 4. Guia de operador

Actualizar `docs/operator-guide.md`:

- primer dry-run debe usar las tools reales `agent.*`;
- incluir `taskId` en `agent.spawn`/`agent.delegate`;
- mostrar como inspeccionar audit con el `traceId`;
- mantener fuera de scope configuraciones de IDE concretos.

### 5. Regression note

Actualizar `README.md` para decir que el uso practico soportado es:

```text
human-facing orchestrator -> Gateway MCP -> coder child + reviewer child
```

Y que Codex como coder requiere completar P/0/3 o habilitacion manual
documentada.

## Errores comunes

- Declarar listo el MVP porque pasan servicios internos.
- Marcar checklist `[x]` sin reviewer/evidencia.
- Meter Codex real como requisito del MVP restricted.
- Anadir configuracion Cursor/Antigravity.
