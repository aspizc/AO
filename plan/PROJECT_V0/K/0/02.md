## ¿Por que existe?

Un agent CLI que cuelga sin timeout es un DoS local. Tambien necesitamos que los errores que llegan a MCP esten "limpios": codigo, mensaje, sin stack traces leakeados.

## ¿Que hay que hacer?

1. Anadir `AGENTS_AGENT_TIMEOUT_MS` (default 600s) al config.
2. Wrappear `delegate`/`ask` con `Promise.race(timeout, op)`.
3. Convertir errores a `{ code, message, where }` antes de devolver al cliente.

### 2. Helper `withTimeout`

`gateway/src/services/_with_timeout.js`:

```javascript
export function withTimeout(promise, ms, label) {
  let timer;
  const timeout = new Promise((_, reject) => {
    timer = setTimeout(() => {
      const err = new Error(`${label} timed out after ${ms}ms`);
      err.code = "TIMEOUT"; reject(err);
    }, ms);
  });
  return Promise.race([promise.finally(() => clearTimeout(timer)), timeout]);
}
```

### 3. Aplicar en `agent_service.js`

```javascript
import { withTimeout } from "./_with_timeout.js";
// ... within delegate():
const r = await withTimeout(adapter.delegate({...}), this.config.agentTimeoutMs || 600_000, "agent.delegate");
```

> Anadir `config.agentTimeoutMs` desde `loadConfig` (env var `AGENTS_AGENT_TIMEOUT_MS`).

### 4. Estandarizar errores en tools

En `tool_helpers.js` el catch ya devuelve `TOOL_ERROR`. Anadir codigos especificos:

```javascript
} catch (err) {
  const code = err.code || "TOOL_ERROR";
  const out = { error: code, message: String(err.message || err) };
  if (err.decision) out.decision = err.decision;
  return { content: [{ type: "text", text: JSON.stringify(out) }], isError: true };
}
```

## Errores comunes a evitar

- ❌ Olvidar `clearTimeout`. Memory leak.
- ❌ Devolver `err.stack` al cliente MCP. Leak interno.
- ❌ Hardcodear timeout. Hazlo configurable.

## Criterios de aceptacion

- [ ] Operaciones largas timeout con `code: "TIMEOUT"`.
- [ ] Respuesta MCP contiene `code` + `message`, sin stack.
- [ ] Audit `ERROR` con `where` y `error`.
