# Y/0/1 - Smoke MVP2.0 para operador

## Quick reference

| Campo | Valor |
|---|---|
| Stage | Y - E2E real + gate MVP2.0 |
| Branch | `feature/Y-0-1-mvp2-smoke` |
| Depende de | Y/0/0, X/0/2 (runbook) |
| Esfuerzo | S-M (2-4h) |
| Skills | scripting, MCP stdio |

## Por que existe?

El E2E real (Y/0/0) vive en el runner de tests. El operador necesita un comando
unico y legible para confirmar el MVP2.0 en su maquina y obtener evidencia clara
(que modelos corrieron, que artefactos se crearon, donde mirar). Esta tarea
entrega ese smoke, espejo operativo de `scripts/smoke_mcp.mjs`.

## Que hay que hacer?

Crear `scripts/smoke_mvp2.mjs`: levanta el gateway con el perfil MVP2, ejecuta un
mini-flujo de 2 agentes (dry-run por defecto; real con `AGENTS_DRY_RUN=0`), e
imprime un resumen humano: agentes/modelos, sesiones tmux, artefactos creados y
ruta del audit. Sale != 0 si algun paso clave falla.

## Pre-requisitos

- Y/0/0 mergeado.
- `scripts/smoke_mcp.mjs` como referencia de estilo.

## Plan de implementacion paso a paso

### 1. Branch

```bash
git checkout develop && git pull --ff-only || true
git checkout -b feature/Y-0-1-mvp2-smoke
```

### 2. Script

`scripts/smoke_mvp2.mjs`:

- Resuelve `AGENTS_POLICIES_DIR` al perfil MVP2 si no viene del entorno.
- Conecta como cliente MCP stdio al gateway (igual que `smoke_mcp.mjs`).
- Verifica que `tools/list` expone `agent.spawn`/`agent.ask`/`agent.view`.
- Ejecuta: spawn coder (codex gpt-5/medium) -> ask trivial -> view ->
  share sanitizado -> spawn reviewer (claude opus-4-7) -> ask review -> kill x2 ->
  complete.
- En dry-run, valida la secuencia y los modelos propagados (sin procesos reales).
- Imprime resumen:
  ```text
  MVP2.0 smoke
    coder    : codex  model=gpt-5 effort=medium  sandbox=workspace-write
    reviewer : claude-code model=claude-opus-4-7
    sessions : ag-...-codex-coder, ag-...-claude-reviewer
    artifacts: <paths>
    audit    : workspace/audit/events.jsonl
    result   : OK
  ```
- Exit code: 0 OK, !=0 si falla un paso clave.

### 3. Documentar

Referenciar el smoke en el runbook (X/0/2) y en `README.md` (Quickstart MVP2.0).

## Errores comunes

- Que el smoke real arranque sin avisar (default debe ser dry-run).
- No imprimir los modelos efectivos (resta valor de diagnostico).
- Exit code 0 aunque un paso falle.
- Dejar sesiones tmux colgando en el modo real.

## Verificacion manual

```bash
node scripts/smoke_mvp2.mjs                 # dry-run, OK
AGENTS_DRY_RUN=0 node scripts/smoke_mvp2.mjs # real (operador con CLIs+tmux)
```
