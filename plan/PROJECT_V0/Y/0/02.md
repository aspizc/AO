## Por que existe?

Falta declarar formalmente que el MVP2.0 esta listo y fijar su alcance. U/0/5
cerro el gate del MVP1 (dry-run). Esta tarea anade el gate, la checklist de
aceptacion y el ADR que documentan que Codex coder real, seleccion de modelo,
flujo supervisado de 2 agentes y launcher generico estan **in scope** y
verificados.

### 2. ADR-005

`docs/adr/ADR-005-mvp2-scope.md`:

- **Contexto**: MVP1 cerro con adapters Gemini/Claude y Codex dormido en dry-run.
- **Decision**: el MVP2.0 anade (a) seleccion de modelo por invocacion,
  (b) Codex coder real headless+supervised con `gpt-5`/`medium`/`workspace-write`,
  (c) flujo supervisado de 2 agentes via host MCP generico, (d) perfil/launcher
  y runbook.
- **Invariantes que se mantienen**: no hay proceso orquestador (ADR-002); policy
  antes de spawn (ADR-003); Codex prohibido en `restricted`; Codex disabled por
  defecto (se habilita solo via perfil MVP2); CI determinista sin red.
- **Fuera de scope**: cloud/multi-host/multi-user, Postgres/Redis/LangGraph,
  IDEs concretos.

### 3. Checklist MVP2.0

- seleccion de modelo end-to-end (tests V/0/0-V/0/2);

- perfil de habilitacion acotado, base disabled, restricted denegado (W/0/2);
- perfil MCP + system prompt + runbook (X/0/0-X/0/2);
- E2E real guardado verde para el operador (Y/0/0);
- smoke MVP2.0 OK (Y/0/1);
- CI normal sigue verde y sin red.
