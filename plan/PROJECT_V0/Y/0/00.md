## Por que existe?

El E2E existente (`tests/e2e/mcp_two_agent_workflow.test.js`, K/0/4) corre en
dry-run. El MVP2.0 exige demostrar el flujo con **ejecucion real**: Codex coder
(gpt-5 medium) + Claude reviewer (opus-4.7) supervisados en tmux, via el gateway
MCP stdio real. Esta tarea anade esa prueba, **guardada** para no romper CI.

## Que hay que hacer?

Crear `tests/e2e/mcp_two_agent_real.test.js` que solo se ejecute cuando
`AGENTS_E2E_REAL=1` y existan `tmux`, `codex` y `claude`. Si falta cualquiera,
hace `skip` con razon clara. La prueba arranca el gateway con el perfil de
policies MVP2, spawnea coder y reviewer, ejecuta una tarea minima real, comparte
artefacto sanitizado y completa la orquestacion. Verifica audit y artefactos.

## Pre-requisitos

- W/0/0, W/0/1 (Codex real), V/0/2 (Claude model), X/0/0 (perfil) mergeados.
- Operador con `codex`/`claude` logueados y `tmux` instalado.

## Plan de implementacion paso a paso

### 1. Branch

```bash
git checkout develop && git pull --ff-only || true
git checkout -b feature/Y-0-0-real-two-agent-e2e
```

### 2. Guarda de ejecucion

Al inicio del test:

```js
const REAL = process.env.AGENTS_E2E_REAL === "1";
// skip si !REAL o si falta tmux/codex/claude (which/availability check)
```

Usar el mecanismo de `skip` de `node:test` con mensaje:
`"set AGENTS_E2E_REAL=1 and install tmux/codex/claude to run"`.

### 3. Escenario

- Repo de trabajo temporal git-inicializado dentro de un `AGENTS_REPO_ROOTS`
  controlado (tmpdir), **no** un repo restricted.
- Env: `AGENTS_DRY_RUN=0`, `AGENTS_POLICIES_DIR=policies/profiles/mvp2`,
  `AGENTS_REPO_ROOTS=<tmp repo>`.
- Flujo via la superficie MCP stdio real:
  1. `orchestration.create` + `task.assign` (coder).
  2. `agent.spawn` codex coder (`model gpt-5`, `reasoningEffort medium`).
  3. `agent.ask` con una tarea trivial y verificable (p.ej. crear `HELLO.md` con
     un texto fijo).
  4. `agent.view` hasta detectar completitud (con timeout acotado).
  5. Capturar resultado como artefacto; compartir **sanitizado** al reviewer.
  6. `agent.spawn` claude reviewer (`model claude-opus-4-7`); `agent.ask` para
     revisar; recoger review notes.
  7. `agent.kill` ambas; `orchestration.complete`.

### 4. Aserciones

- El fichero esperado existe en el repo de trabajo (coder real escribio).
- Audit contiene `SESSION_STARTED`/`SESSION_CLOSED` para `codex` y `claude-code`
  con el `model` efectivo correcto.
- El reviewer solo accedio a artefacto sanitizado (no raw).
- `orchestration` queda `completed`.

Timeouts generosos pero acotados; limpiar tmux y tmpdir en `after`.

### 5. CI

`scripts/ci.sh` **no** activa `AGENTS_E2E_REAL`. Anadir nota de que esta prueba
es opcional/manual.

## Errores comunes

- Que la prueba corra (y falle) en CI por no estar bien guardada.
- Usar un repo restricted o salir del allowlist.
- Aserciones flaky por no esperar al output del agente.
- No limpiar sesiones tmux ni el tmpdir.
- Depender de salida exacta del modelo (asertar hechos verificables, no prosa).
