## ¿Por que existe?

Sanitizar bajo demanda en `get` introduce latencia y race conditions. Es mas seguro generar el sanitized **al `put`** del raw restricted: el artefacto sanitizado existe antes de cualquier consumidor, y `sanitized_from` apunta al raw para forensics.

## ¿Que hay que hacer?

Hookear sanitizer en `artifact_store.put`. Si `kind ∈ raw_*` y `classification == restricted`, generar artifact secundario `<kind>_sanitized` con `sanitized_from` apuntando al raw. Audit `SANITIZATION_APPLIED`.

### 2. Modificar `artifact_store.put`

```javascript
import { isRawKind } from "./policy_types.js";
import { sanitize } from "./sanitizer.js";

export function put({ traceId, kind, classification, producedBy, content, sanitizedFrom = null }) {
  // ... existing put logic creates the raw row first ...
  const raw = createRawRow();

  if (sanitizedFrom === null && classification === "restricted" && isRawKind(kind)) {
    const { sanitized, appliedRuleIds } = sanitize(content.toString("utf-8"), { kind });
    const sanRow = createRawRow({
      kind: `${kind}_sanitized`,
      classification: "internal",
      content: Buffer.from(sanitized, "utf-8"),
      sanitizedFrom: raw.artifactId
    });
    auditAppend({
      type: "SANITIZATION_APPLIED", traceId,
      sourceArtifactId: raw.artifactId, sanitizedArtifactId: sanRow.artifactId,
      kind, appliedRuleIds
    });
  }
  return raw;
}
```

## Errores comunes

- ❌ Recursionar la sanitizacion del sanitizado (`sanitizedFrom` evita el bucle).
- ❌ Cambiar el `kind` del raw original. Crea otro artifact, no muta.
- ❌ Marcar el sanitized como `restricted`. **internal**.
