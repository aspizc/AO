## ¿Por que existe?

Sanitizar codigo no es magia: son reglas regex versionadas que el operador puede revisar. Empezar con un registry declarativo permite tests reproducibles, auditar que se aplico, y desactivar reglas problematicas sin tocar codigo.

Cada regla tiene `id`, `pattern` (regex), `replacement`, `applies_to` (kinds), `severity`. Sin reglas, el sanitizer no hace nada.

## ¿Que hay que hacer?

Crear `policies/sanitization-rules.json` con reglas iniciales para: secrets, paths absolutos, IDs estilo UUID/customer, nombres de fichero internos.

### 2. `policies/sanitization-rules.json`

```json
{
  "version": 1,
  "rules": [
    {
      "id": "secret.token",
      "pattern": "(?i)(api[_-]?key|token|secret)[\"']?\\s*[:=]\\s*[\"']?[A-Za-z0-9._-]{12,}",
      "replacement": "$1=<REDACTED-SECRET>",
      "appliesTo": ["raw_diff","raw_code","raw_stacktrace","summary"]
    },
    {
      "id": "absolute.path",
      "pattern": "/home/[A-Za-z0-9_-]+(?:/[A-Za-z0-9_./-]*)?",
      "replacement": "<HOME>/...",
      "appliesTo": ["raw_diff","raw_code","raw_stacktrace","summary"]
    },
    {
      "id": "uuid",
      "pattern": "\\b[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}\\b",
      "replacement": "<UUID>",
      "appliesTo": ["raw_diff","raw_code","raw_stacktrace","summary"]
    },
    {
      "id": "internal.file",
      "pattern": "(internal|private)/[A-Za-z0-9_./-]+",
      "replacement": "<INTERNAL>/...",
      "appliesTo": ["raw_diff","raw_code","raw_stacktrace","summary"]
    }
  ]
}
```

### 3. Test

`tests/gateway/sanitization_rules.test.js`:

```javascript
import { test } from "node:test";
import assert from "node:assert/strict";
import fs from "node:fs"; import path from "node:path";

const RULES = JSON.parse(fs.readFileSync(path.resolve("policies/sanitization-rules.json"), "utf-8"));

test("rules_file_loads", () => {
  assert.equal(RULES.version, 1);
  assert.ok(Array.isArray(RULES.rules));
});

test("rules_have_pattern_and_replacement", () => {
  for (const r of RULES.rules) {
    assert.ok(r.id, "missing id");
    assert.ok(r.pattern);
    assert.ok(r.replacement);
    assert.ok(Array.isArray(r.appliesTo));
  }
});

test("no_real_secrets_in_rules_file", () => {
  const text = JSON.stringify(RULES);
  assert.ok(!/sk-[A-Za-z0-9]{20,}/.test(text), "OpenAI-style secret found");
});
```

## Errores comunes

- ❌ Anadir un secret real al test fixture. Usa siempre dummies.
- ❌ Reglas demasiado amplias (e.g. `[a-z]+`). Inutiles y rompen output.
- ❌ Olvidar `appliesTo`. Si vacio, la regla no se aplica.

## Criterios de aceptacion
