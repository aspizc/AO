## ¿Por que existe?

Cierra TM-06. Si el sanitizer falla (regex bad, OOM, exception), el sistema **NO** debe devolver el raw como fallback "porque mejor algo que nada". El comportamiento correcto es: deny + audit.

## ¿Que hay que hacer?

1. Capturar excepciones del sanitizer en `put`. No fallar el put del raw, pero NO crear sanitized si el sanitizer falla. Audit `SANITIZATION_FAILED`.
2. En `artifact.get`, cuando policy decide `allow_with_sanitization`, buscar el sanitized linkado. Si no existe (porque el sanitizer fallo), deniega.

### 2. `put` defensive

```javascript
try {
  const { sanitized, appliedRuleIds } = sanitize(...);
  const sanRow = createRawRow({...});
  auditAppend({ type: "SANITIZATION_APPLIED", ... });
} catch (err) {
  auditAppend({ type: "SANITIZATION_FAILED", traceId,
    sourceArtifactId: raw.artifactId, error: String(err.message || err) });
  // Do NOT throw; raw is still stored, but sanitized is missing.
}
```

### 3. `artifact.get` cross-boundary

Cuando el policy engine devuelve `allow_with_sanitization`:

```javascript
if (decision.decision === "allow_with_sanitization") {
  const sanitized = repo.findSanitizedFor(row.artifact_id);
  if (!sanitized) {
    auditAppend({ type: "SANITIZATION_MISSING_DENY", ... });
    return { error: "POLICY_DENIED",
             decision: { decision: "deny", reason: "sanitization missing or failed",
                         ruleId: "sanitization.missing" } };
  }
  return { ...sanitized, content: fs.readFileSync(sanitized.path).toString("utf-8") };
}
```

### 4. Test

`tests/gateway/sanitization_fail_closed.test.js`:

- `sanitizer_failure_blocks_cross_boundary_get`: monkey-patch sanitize to throw, put raw restricted, then `artifact.get` from reviewer → deny, raw not returned.
- `failure_is_audited`: `SANITIZATION_FAILED` event present.
- `sanitization_missing_deny_audited`: get attempt audits `SANITIZATION_MISSING_DENY`.

## Errores comunes

- ❌ Throwing del put cuando sanitizer falla. El raw sigue siendo valido y necesita persistirse.
- ❌ Devolver raw "para que el caller decida". El caller no es trustworthy.
- ❌ Olvidar logear el motivo. Audit con error message ayuda al operador a arreglar la regla.

## Criterios de aceptacion

- [ ] Sanitizer exception → raw queda guardado, sanitized NO se crea, audit `SANITIZATION_FAILED`.
- [ ] Cross-boundary get sin sanitized → deny + audit.
- [ ] Raw nunca leakea cuando policy dice `allow_with_sanitization`.
