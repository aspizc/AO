## ¿Por que existe?

La promesa de Temporal en V1 es recuperacion real ante crash. El stage no cierra sin una prueba que mate y reinicie el worker.

## ¿Que hay que hacer?

Crear test E2E que inicia workflow, mata el worker tras la primera activity, reinicia worker y verifica continuidad sin repetir la primera activity. Crear ADR-V1-05.

## Plan de implementacion

1. Instrumentar marcador tras primera activity.
2. Matar worker de test.
3. Reiniciar worker.
4. Verificar workflow completado y primera activity no duplicada.
5. Verificar que `NEVER_AUTO` no se bypassea en reintentos.
6. Crear `docs/adr/ADR-V1-05-temporal-durable-workflows.md`.

## Verificacion: Gateway contract inmutable

El ADR debe formalizar que Temporal envuelve grafos y que las actions siguen entrando por MCP Gateway.
