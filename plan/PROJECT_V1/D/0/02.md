## ¿Por que existe?

El grafo principal de Stage B necesita durabilidad: reintentos, timers y continuidad tras reinicio del worker.

## ¿Que hay que hacer?

Envolver `implement-test-review-push` como workflow Temporal que coordina activities MCP idempotentes y persiste estado en Postgres.

## Plan de implementacion

1. Definir workflow input con `task_id`, `session_id`, `trace_id` y configuracion de intentos.
2. Mapear nodos del grafo a activities deterministicas.
3. Persistir checkpoints/resultados via Gateway/repos existentes.
4. Cubrir path feliz E2E con Temporal local.
5. Cubrir fallo de test y ciclo de correccion.

## Verificacion: Gateway contract inmutable

El workflow no accede a repos directamente salvo a traves de Gateway/activities aprobadas por la arquitectura.
