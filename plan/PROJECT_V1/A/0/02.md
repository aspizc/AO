## ¿Por que existe?

Este grafo demuestra que un nodo LangGraph puede llamar `agent.delegate` y `agent.review` a traves del `GatewayClient` sin ningun cambio en el Gateway. Es la prueba de viabilidad de la arquitectura determinista.

## ¿Que hay que hacer?

Implementar `graphs/delegate_review.py`: un `StateGraph` con dos nodos (`delegate_node`, `review_node`), una arista entre ellos y modo `dry_run` con fixtures.

## Plan de implementacion paso a paso

1. Definir `DelegateReviewState` (`TypedDict`): `task_id`, `session_id`, `trace_id`, `delegate_result`, `review_result`, `status`.
2. Implementar `delegate_node(state, gateway_client)` llamando `agent.delegate`.
3. Implementar `review_node(state, gateway_client)` llamando `agent.review`.
4. Construir `START -> delegate -> review -> END`.
5. Anadir `dry_run=True`: el cliente devuelve fixtures sin Gateway real.
6. Test E2E dry-run: estado final `status == "reviewed"`.
7. Verificar que `trace_id` se propaga en cada llamada.

## Errores comunes

- Anadir logica de policy al grafo. El Gateway aplica policy.
- Ignorar `tool_error`; si el Gateway rechaza, el grafo falla.
- Hard-codear `task_id`; viene siempre del estado de entrada.

## Verificacion: Gateway contract inmutable

El grafo llama `agent.delegate` y `agent.review` existentes. No se cambia ninguna tool para este grafo.
