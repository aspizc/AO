## ¿Por que existe?

Redis Streams permite consumidores realtime sin convertir el bus en fuente de verdad ni frontera de autorizacion. JSONL audit sigue siendo el fallback principal.

## ¿Que hay que hacer?

Anadir hook opcional en `audit.append`: si `AGENTS_REDIS_URL` existe, publicar evento sanitizado en `agents:events`.

## Plan de implementacion

1. Definir envelope con `traceId`, `event_type`, `tool_name`, `actor_role`, timestamps y metadata sanitizada.
2. Reutilizar pipeline de sanitizacion/visibility matrix.
3. No publicar campos `restricted` ni raw artifacts.
4. Si Redis falla, escribir warn a stderr y continuar con JSONL.
5. Tests para publicacion, degradacion y ausencia de datos restricted.

## Verificacion: Gateway contract inmutable

El publisher observa eventos internos; no expone tools nuevas ni cambia resultados MCP.
