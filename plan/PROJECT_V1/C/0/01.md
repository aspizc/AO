## ¿Por que existe?

El cambio a Postgres solo es aceptable si los repos se comportan igual que en SQLite. La paridad evita bifurcaciones semanticas segun backend.

## ¿Que hay que hacer?

Reutilizar los tests de contrato existentes de repos y ejecutarlos contra SQLite y Postgres con `AGENTS_TEST_DB=postgres`.

## Plan de implementacion

1. Extraer suite comun de contrato por repo.
2. Parametrizar backend SQLite/Postgres.
3. Preparar setup/teardown de base Postgres de test.
4. Verificar mismos retornos, errores y ordenamientos.
5. Documentar como correr la suite Postgres.

## Verificacion: Gateway contract inmutable

Los tests validan repos internos; no dependen de modificar MCP.

## Criterios de aceptacion

- [ ] Suite de contrato corre con SQLite.
- [ ] Suite de contrato corre con Postgres.
- [ ] Fallos de Postgres no afectan default SQLite.
- [ ] CI puede activar Postgres por flag/env.
