## ¿Por que existe?

V1 necesita estado durable y consultable sin romper la interfaz de repositorios del Gateway ni abandonar SQLite como default local.

## ¿Que hay que hacer?

Crear un adapter Postgres que implemente la misma interfaz que el adapter SQLite. El factory en `gateway/src/core/state.js` elige adapter por `AGENTS_DB_URL`.

## Plan de implementacion

1. Inventariar interfaces actuales de repos.
2. Crear migrations SQL en `gateway/migrations/postgres/`.
3. Implementar adapter Postgres con mismos metodos y tipos de retorno.
4. Activar Postgres solo con `AGENTS_DB_URL=postgres://...`.
5. Mantener SQLite como default.

## Verificacion: Gateway contract inmutable

No modificar schemas MCP ni tools; solo cambia el backend interno de repositorios.
