## ¿Por que existe?

Un consumer minimo valida que los eventos sanitizados son consumibles por procesos no privilegiados y que Redis puede servir para observabilidad sin filtrar datos sensibles.

## ¿Que hay que hacer?

Crear proceso Python en `orchestrator-langgraph/src/orchestrator_langgraph/consumers/` que lee `agents:events` y emite metricas basicas a stderr.

## Plan de implementacion

1. Crear consumer con configuracion `AGENTS_REDIS_URL`.
2. Contar eventos por tipo.
3. Calcular latencia media si el evento incluye timestamps.
4. Descartar y loguear como error cualquier campo `restricted`.
5. Tests unitarios sin Redis real con fixtures.

## Verificacion: Gateway contract inmutable

El consumer solo lee eventos sanitizados; no llama ni modifica tools MCP.
