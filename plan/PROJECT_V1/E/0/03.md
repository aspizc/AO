# E/0/3 — Runbook V1

## Quick reference

| Campo | Valor |
|---|---|
| Stage | E — Observabilidad y empaquetado |
| Branch | `feature/K-0-E-0-3-v1-runbook` |
| Depende de | E/0/2 |
| Esfuerzo | S |
| Skills | Runbooks, operations, troubleshooting |

## ¿Por que existe?

El stack V1 necesita una guia operativa concreta para arrancar, verificar, diagnosticar y apagar el sistema sin conocer detalles internos del codigo.

## ¿Que hay que hacer?

Crear runbook V1 con comandos de arranque, checks de salud, ejecucion del flujo `implement-test-review-push`, validacion de trazas, troubleshooting y parada limpia.

## Plan de implementacion

1. Documentar prerequisitos locales y variables necesarias.
2. Incluir comandos para levantar el stack completo.
3. Definir checks de salud por servicio.
4. Incluir flujo smoke de `implement-test-review-push`.
5. Explicar como encontrar `trace_id` y trazas OTel.
6. Anadir troubleshooting para Postgres, Redis, Temporal, OTel y approvals.
7. Documentar parada limpia y limpieza de volumenes solo como accion explicita.

## Verificacion: Gateway contract inmutable

El runbook debe operar el sistema mediante Gateway y comandos publicos. No debe recomendar llamadas internas ni manipulacion manual de estado para completar flujos.

## Tests requeridos

- Validacion manual de comandos del runbook contra compose completo.
- Smoke de flujo V1 siguiendo solo el runbook.
- Verificacion de que las instrucciones no requieren editar policies ni contrato MCP.

## Errores comunes

- Documentar comandos que dependen de estado local no reproducible.
- Recomendar borrar volumenes como primer paso de troubleshooting.
- Saltar approvals manuales para acelerar la guia.
- Omitir como correlacionar errores con `trace_id`.

## Criterios de aceptacion

- [ ] Runbook cubre arranque, healthcheck, smoke, observabilidad, troubleshooting y parada.
- [ ] El flujo se puede ejecutar siguiendo solo la guia.
- [ ] `trace_id` queda localizable desde logs/eventos/trazas.
- [ ] No se documentan bypasses del Gateway.

## Definition of Done

- [ ] Runbook revisado contra el compose de E/0/2.
- [ ] Comandos copiados literalmente funcionan en entorno local limpio.
- [ ] Secciones de fallo comun tienen pasos de diagnostico accionables.
- [ ] No se cambian source code ni policies como parte del runbook.
