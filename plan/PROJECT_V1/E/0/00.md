# E/0/0 — OTel en Gateway

## Quick reference

| Campo | Valor |
|---|---|
| Stage | E — Observabilidad y empaquetado |
| Branch | `feature/K-0-E-0-0-otel-gateway` |
| Depende de | A |
| Esfuerzo | M |
| Skills | OpenTelemetry, MCP Gateway, trace propagation |

## ¿Por que existe?

El Gateway es el punto de entrada MCP y debe iniciar o continuar trazas para que cada tool call sea visible de punta a punta.

## ¿Que hay que hacer?

Instrumentar el Gateway con spans OTel por request/tool call, generar o aceptar `trace_id` entrante y propagarlo en respuestas, eventos y llamadas downstream sin cambiar el contrato MCP.

## Plan de implementacion

1. Anadir configuracion OTel por env con export desactivable en local/test.
2. Crear span por llamada MCP con atributos de tool, session, approval mode y resultado.
3. Aceptar `trace_id` entrante desde metadata/contexto cuando exista.
4. Generar `trace_id` cuando no exista y exponerlo en logs/eventos/respuesta compatible.
5. Propagar contexto a adapters y clientes internos.
6. Cubrir error path para que excepciones queden registradas en el span.

## Verificacion: Gateway contract inmutable

La instrumentacion no renombra tools, no cambia schemas obligatorios y no mueve logica fuera del Gateway. `trace_id` se trata como metadata compatible o campo ya permitido por el contrato aprobado.

## Tests requeridos

- Test unitario de span creado por tool call exitosa.
- Test unitario de span con status de error ante excepcion.
- Test de propagacion: `trace_id` entrante se conserva.
- Test de compatibilidad: request sin `trace_id` sigue funcionando.

## Errores comunes

- Hacer obligatorio el `trace_id` en llamadas existentes.
- Loguear datos sensibles como atributos OTel.
- Usar stdout para telemetria y romper el canal MCP.
- Crear wrappers que cambian nombres o payloads de tools.

## Criterios de aceptacion

- [ ] Gateway emite spans OTel por llamada MCP.
- [ ] `trace_id` se genera o propaga de forma deterministica por request.
- [ ] Logs siguen en stderr y stdout queda reservado para MCP.
- [ ] El contrato Gateway permanece compatible con Stage A.

## Definition of Done

- [ ] Tests requeridos verdes.
- [ ] Configuracion OTel documentada en el lugar del servicio.
- [ ] Telemetria puede desactivarse en test/local.
- [ ] Sin cambios fuera del alcance de Gateway ni del contrato MCP.
