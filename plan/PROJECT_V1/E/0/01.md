## ¿Por que existe?

Las trazas del Gateway no bastan si los nodos del grafo, activities Temporal y adapters no comparten contexto. V1 necesita correlacion completa del flujo durable.

## ¿Que hay que hacer?

Instrumentar `orchestrator-langgraph` para crear spans por workflow, nodo LangGraph y activity, propagando el `trace_id` recibido desde Gateway hasta Redis, Postgres y adapters.

## Plan de implementacion

1. Leer `trace_id` desde el input del workflow o metadata MCP.
2. Crear span raiz para `implement-test-review-push`.
3. Crear spans hijos por nodo relevante del grafo y por activity Temporal.
4. Propagar contexto OTel en llamadas a `GatewayClient`.
5. Anadir atributos de `task_id`, `session_id`, nodo, intento y resultado.
6. Registrar errores y timeouts sin auto-resolver approvals.

## Verificacion: Gateway contract inmutable

El orchestrator sigue llamando MCP via `GatewayClient`; no accede a APIs internas del Gateway ni introduce rutas alternativas. La correlacion usa metadata/contexto existente.

## Tests requeridos

- Test unitario de span raiz con `trace_id` entrante.
- Test unitario de spans por nodo/activity con atributos minimos.
- Test de propagacion hacia `GatewayClient`.
- Test de error path con span marcado como fallo.

## Errores comunes

- Crear trazas independientes por nodo y perder correlacion.
- Instrumentar dentro de workflows Temporal con llamadas no deterministicas.
- Exponer secretos, prompts completos o tokens como atributos.
- Tratar OTel como mecanismo de persistencia de estado.

## Criterios de aceptacion

- [ ] Workflow y nodos principales aparecen en la misma traza.
- [ ] Activities Temporal conservan `trace_id`.
- [ ] Errores quedan visibles sin ocultar fallos del flujo.
- [ ] `NEVER_AUTO` sigue requiriendo aprobacion humana.

## Definition of Done

- [ ] Tests requeridos verdes.
- [ ] Trazas Gateway + orchestrator correlacionadas en collector local.
- [ ] Sin bypass del Gateway.
- [ ] Configuracion OTel consistente con E/0/0.
