## ¿Por que existe?

V1 debe arrancar de forma reproducible con todos los servicios necesarios para durabilidad, eventos y observabilidad.

## ¿Que hay que hacer?

Completar `docker-compose` para levantar Postgres, Redis, Temporal, OTel collector, Gateway, orchestrator worker y adapters necesarios para ejecutar `implement-test-review-push` localmente.

## Plan de implementacion

1. Inventariar servicios existentes y variables requeridas.
2. Anadir o completar Postgres con volumen y healthcheck.
3. Anadir o completar Redis con healthcheck.
4. Anadir Temporal conectado a Postgres segun Stage D.
5. Anadir OTel collector con export local visible.
6. Conectar Gateway, orchestrator y adapters a la misma red y variables.
7. Validar orden de arranque con healthchecks, no sleeps fragiles.

## Verificacion: Gateway contract inmutable

Compose solo cablea servicios. No cambia tools MCP, schemas ni rutas internas; Gateway sigue siendo el unico punto de entrada MCP para el orchestrator.

## Tests requeridos

- `docker compose config` o equivalente pasa sin errores.
- Smoke test de arranque del stack completo.
- Healthchecks verdes para Postgres, Redis, Temporal y OTel collector.
- Ejecucion smoke de workflow usando Gateway, con trazas visibles.

## Errores comunes

- Introducir credenciales reales en compose.
- Depender de `sleep` en vez de healthchecks.
- Hacer que el orchestrator hable directo con Postgres/Redis para acciones MCP no aprobadas.
- Dejar Temporal usando almacenamiento efimero cuando el criterio exige Postgres.

## Criterios de aceptacion

- [ ] `docker-compose` levanta stack completo local.
- [ ] Temporal usa Postgres para estado durable.
- [ ] Redis queda disponible para eventos.
- [ ] OTel collector recibe trazas de Gateway y orchestrator.

## Definition of Done

- [ ] Configuracion compose validada.
- [ ] Smoke test documentado y ejecutable.
- [ ] Variables locales tienen defaults seguros o ejemplo claro.
- [ ] Sin cambios de contrato Gateway ni policies.
