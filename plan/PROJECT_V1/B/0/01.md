## ¿Por que existe?

`plan-refine` cubre el flujo determinista de generar una propuesta de plan, revisarla y refinarla antes de implementacion. Complementa al LLM-orchestrator para trabajos acotados pero todavia iterativos.

## ¿Que hay que hacer?

Crear un grafo con nodos de planificacion y revision que llamen las mismas tools MCP reales que usa el camino LLM para propuestas, artefactos y revisiones.

## Mapa de tools permitido

| Paso conceptual | Tools MCP |
|---|---|
| crear propuesta | `agent.delegate` con `role="planner"` o fixture dry-run equivalente |
| guardar propuesta | `artifact.put` con `kind="plan"` |
| revisar propuesta | `agent.delegate` con `role="planner"` para revision del plan, o `role="reviewer"` si el artifact revisado es un diff/cambio |
| guardar notas | `artifact.put` con `kind="review_notes"` |

No anadir una tool de planificacion nueva ni permisos especiales para LangGraph.

## Plan de implementacion

1. Definir estado con `task_id`, `trace_id`, `draft_plan`, `review_result`, `refinement_count` y `status`.
2. Implementar `plan_node`, `review_plan_node` y `refine_node` con `agent.delegate` + `artifact.put`.
3. Anadir arista condicional: plan aprobado -> END; cambios pedidos -> refine hasta N iteraciones.
4. Agregar fixtures dry-run y test E2E.
5. Verificar audit semanticamente equivalente al path LLM de planificacion.
