## ¿Por que existe?

Este es el flujo repetitivo principal que V1 quiere volver determinista: planificar, implementar, testear, revisar y empujar cambios, manteniendo al Gateway como frontera de enforcement.

## ¿Que hay que hacer?

Implementar un grafo LangGraph con nodos `plan_node -> implement_node -> test_node -> review_node -> push_node`. Cada nodo llama solamente tools MCP existentes mediante `GatewayClient`.

El nombre `push_node` es conceptual en B/0/0: no ejecuta `git push` real porque
el Gateway no tiene una tool MCP de push. En este task solo produce un resultado
dry-run/fixture de `push_ready` o `push_skipped_dry_run`. B/0/3 insertara
`approval.request`/`approval.wait` antes de este nodo.

## Mapa de tools permitido

| Nodo | Tools MCP |
|---|---|
| `plan_node` | `artifact.put` con `kind="plan"` para registrar el plan/intencion de ejecucion |
| `implement_node` | `task.assign` a Codex coder, luego `agent.delegate` con `role="coder"` |
| `test_node` | `task.assign` a tester, luego `agent.delegate` con `role="tester"` |
| `review_node` | `task.assign` a Claude reviewer, luego `agent.delegate` con `role="reviewer"` |
| `push_node` | dry-run fixture; opcionalmente `artifact.put` con `kind="push_intent"` |

No usar `agent.review` ni `artifact.store`: no existen en el Gateway actual.

## Plan de implementacion

1. Definir estado del flujo:
   - `trace_id`, `root_task_id`, `repo`, `cwd`, `target_branch`.
   - `subtask_ids` por nodo.
   - `plan_result`, `implement_result`, `test_result`, `review_result`, `push_result`.
   - `attempt`, `max_attempts` y `status`.
2. Implementar `plan_node` registrando el plan/intencion con `artifact.put`.
3. Implementar `implement_node` con `task.assign` + `agent.delegate` como Codex coder.
4. Implementar `test_node` con `task.assign` + `agent.delegate` como tester.
5. Anadir arista condicional desde `test_node`: si el resultado de test falla,
   volver a `implement_node` hasta `max_attempts`; si agota intentos, terminar
   con `status="failed_tests"`.
6. Implementar `review_node` con `task.assign` + `agent.delegate` como Claude reviewer.
7. Implementar `push_node` solo como dry-run/fixture, registrando
   `push_result.status` sin ejecutar Git.
8. Cubrir orden de calls, propagacion de `trace_id`, uso de `GatewayClient` y limite de intentos.
