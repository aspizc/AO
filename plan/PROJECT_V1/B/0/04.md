## ¿Por que existe?

El stage necesita cerrar con una prueba integrada del modelo hibrido y una decision formal que preserve al LLM-orchestrator para flujos abiertos.

## ¿Que hay que hacer?

Crear smoke E2E que ejecute un flujo con LangGraph y otro con LLM segun selector. Crear ADR-V1-02 sobre el modelo hibrido.

El smoke de Stage B valida seleccion, llamadas MCP, artifacts y approvals. No
debe requerir un `git push` real, porque Stage B no introduce una tool MCP de
push.

## Plan de implementacion

1. Test E2E con `AGENTS_ORCHESTRATOR_IMPLEMENT_TEST_REVIEW_PUSH=langgraph`.
2. Test E2E/default para flow no configurado usando `llm`.
3. Verificar decision estructurada del selector (`selected=langgraph|llm`) y
   que el caller LangGraph use las mismas tools MCP.
4. Crear `docs/adr/ADR-V1-02-hybrid-orchestrator-selector.md`.
5. Documentar criterios de cuando usar LangGraph vs LLM.

## Verificacion: Gateway contract inmutable

El ADR debe explicitar que el selector esta fuera del Gateway y que ambos callers usan las mismas MCP tools.
