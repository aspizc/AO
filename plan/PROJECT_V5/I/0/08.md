## Problem

LangGraph and Temporal expose duplicate implement-test-review-push paths, the
selector can preserve silent fallback, and accepted ADRs do not identify one
candidate-tested production architecture. Separately, no planned owner
introduces the public MCP protocol `0.2` endpoint/schema behind a flag, proves
all consumers migrated, or atomically retires public `0.1`; those two cutovers
must resolve to one candidate and rollback boundary.

## Scope

- Introduce the MCP protocol `0.2` endpoint/schema behind a disabled version
  flag while keeping `0.1` as the default. The version is negotiated/selected
  explicitly; an old `0.1` client against `0.2`, a `0.2` client against `0.1`,
  an absent version, or an unsupported version receives one stable explicit
  version-mismatch error before any tool handler or mutation.
- Maintain a machine-readable consumer matrix covering every MCP client,
  Gateway registry/stdio entry point, CLI/script, Python/non-V1 client,
  prompt/example, runbook, integration fixture, and the I/0/06 worker shim.
  Each row binds expected schema/version, migration commit, snapshot/contract
  evidence, owner, and rollback compatibility to the candidate; unregistered
  or mixed-version consumers fail closed.
- After the complete matrix, migration/backup verification, I/0/06 pending-
  history shim, full-stack gate, and independent review pass, activate `0.2`
  as server default and remove the public `0.1` endpoint in one atomic
  candidate manifest. No intermediate tree may advertise a default unsupported
  by any registered consumer.
- Bind protocol activation/retirement and schema/data migration to I/0/03's
  common rollback point: server, clients, and DB return to the same last
  compatible tree/schema or remain failed closed; partial rollback and silent
  downgrade are forbidden.
- Select the I/0/02 Temporal workflow and I/0/06 worker as the only production
  ITRP after their candidate passes I/0/07 and the independent review gate.
- Add explicit opt-in, migration, drain, rollback, and no-fallback semantics;
  existing histories finish on their compatible worker build.
- Remove production imports/entry points/tests/docs for the duplicate LangGraph
  ITRP while preserving its independent plan-refine capability.
- Make the preserved plan-refine parser accept only the closed JSON verdict
  enum `approved|changes_requested`; negation, free text, unknown fields,
  parse/transport error, or ambiguous output is `changes_requested`.
- Reconcile ADR-001/002 and V1 ADRs with the as-built selector, workflow,
  Gateway ownership, public MCP version/default, consumer matrix, stores,
  worker packaging, both retirement decisions, and common rollback.

## Non-scope

- No change to I/0/02 envelope/KO/replay semantics, rewrite of existing Temporal
  histories, removal of LangGraph plan-refine, second public MCP compatibility
  shim after retirement, assignment of new behavior to already-complete
  C/0/01, real remote push, or release/tag publication. C/0/01 remains only the
  generated contract source; D/0/00 supplies authority and I/0/06 owns the
  pending-history worker shim.

## Acceptance criteria

- [ ] MCP `0.2` is testable behind a flag while `0.1` remains the default, and
      every old/new/absent/unknown version mismatch fails before dispatch.
- [ ] The candidate-bound consumer matrix is complete and every consumer has
      migrated schema/version snapshots plus one compatible rollback point.
- [ ] Mixed-version startup/runtime fails closed; activation of `0.2` and
      retirement of public `0.1` are atomic with no fallback window.
- [ ] Server, clients, and DB roll back together to the last compatible
      tree/schema, never independently.
- [ ] Exactly one production ITRP entry point and selector target remains.
- [ ] Cutover requires the reviewed candidate and full-stack evidence.
- [ ] Existing histories drain; new runs cannot enter the retired path.
- [ ] Rollback is explicit, version-compatible, and never a silent fallback.
- [ ] Preserved plan-refine verdict parsing is closed and fail-safe.
- [ ] Accepted ADRs and shipped docs describe the same runtime topology.
