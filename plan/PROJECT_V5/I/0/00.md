## Problem

Crashes around database commit, process/tool invocation, event publication, or
client ACK can duplicate or lose externally visible effects.

## Scope

- Derive durable operation IDs/request hashes from principal, workflow/trace,
  logical action, business attempt, target, and change/evidence digest.
- Atomically persist lifecycle/domain result references and outbox records.
- Dispatch idempotently with claim/lease, retry classification, reconciliation,
  and exact-result replay.

## Non-scope

- No global idempotency forever, retry of changed request, raw payload in outbox
  metadata, or assumption that Redis/event publication is the database commit.

## TDD RED

Crash before/after state commit, outbox claim, external effect, publish, and
ACK; retry same/different hash; race dispatchers; expire claim; and restart.

## TDD GREEN

Add operation/outbox schemas, transaction APIs, dispatcher, result-reference
store, and reconciliation hooks.

## Acceptance criteria

- [ ] Same operation/hash returns one effective result across crash/retry.
- [ ] Same ID/different hash conflicts.
- [ ] State and outbox intent commit atomically.
- [ ] Dispatcher recovery cannot lose or duplicate the semantic effect.

## Verification

Run operation/outbox transaction, crash-window, dispatcher-race, and restart
tests with migration rollback; then `bash scripts/ci.sh` and
`git diff --check`.
