## Problem

The product lacks end-to-end retention/deletion/export semantics and a release
gate proving that one reproducible candidate is secure, recoverable, and
operable.

## Scope

- Define retention/legal-hold/classification policy for control records,
  artifacts, audit, coordination metadata, backups, and workflow histories.
- Define and enforce each store's at-rest contract: owner-only filesystem
  permissions where applicable, encryption mode, key identifier/rotation,
  backup protection, and fail-closed startup when a profile requires a
  protection the store cannot prove.
- Implement synthetic-subject inventory/export/erase with referential
  tombstones and verifiable completion across live stores, mirrors, workflow
  histories, and restored backups; never use real personal data in tests.
- Produce a reproducible deployable profile, dependency locks/SBOM/provenance,
  required live-lane and recovery evidence, migration/rollback manifest, and
  candidate-digest release decision.
- Consume H/0/01's script-disabled lock-graph materialization, then build every
  required native Node add-on from source with network denied. For
  `better-sqlite3`, require `npm_config_build_from_source=true`,
  `npm_config_offline=true`, verified `npm_config_nodedir` headers, and a real
  `new Database(":memory:").close()` smoke bound to the candidate.
- Record exact Node/npm, CPython, uv, make, C/C++ compiler, Node-header digest,
  OS/architecture, and Darwin SDK/Xcode identity where applicable. A prebuilt
  binary download, unknown header origin, unobserved egress, or unfixed
  toolchain is a release failure, not reproducibility evidence.
- Consume `I/0/09`'s data catalog, destination, lineage, audit-integrity, and
  quality evidence; no release-local substitute or weaker duplicate is valid.
- Enforce an exact `reviewed=candidate=main=tag=published` full-object identity:
  the independently reviewed commit/tree, candidate manifest, `main`, peeled
  tag, and published provenance/source digest must all resolve to the same
  immutable candidate.

## Non-scope

- No claim of universal regulatory compliance, erase that breaks required audit
  integrity, raw export through public MCP, mixed-candidate evidence, or
  automatic production deployment.

## TDD RED

Exercise retention/hold conflicts, cross-store synthetic subject, partial erase
crash/resume, unauthorized export, backup/history residue, mixed SHA/image/lock
evidence, weak filesystem permissions, forbidden plaintext persistence, stale
or unknown key identifiers, restore under the wrong protection profile,
reviewed/candidate/main/tag/published mismatch, missing SBOM/live lane/restore,
a native install script downloading outside the lock graph, direct or
unobserved build egress, mismatched Node headers, unknown compilers/SDKs, a
source build that cannot run the in-memory SQLite smoke, and rollback
incompatibility.

## TDD GREEN

Add governance inventory/jobs/receipts, per-store at-rest policy enforcement,
synthetic fixtures, release manifest validator, reproducible packaging profile,
an offline native source-build harness/toolchain manifest, and explicit
promotion/rollback gate.

## Acceptance criteria

- [ ] Retention and erase/export behavior is explicit per data class/store.
- [ ] Every persistent store documents and enforces its permissions, encryption
      and key-rotation mode; required protection fails closed and secrets never
      enter manifests, logs, artifacts, or test evidence.
- [ ] Backups and restores preserve the selected at-rest protection profile and
      reject weaker or unknown-key restores.
- [ ] Synthetic erase is idempotent, resumable, authorized, and evidenced.
- [ ] Lifecycle completion covers live stores, mirrors, histories, and backups.
- [ ] Release evidence binds one tree, locks, images, schemas, and profile.
- [ ] Every required native add-on is built from source with fixed verified
      headers/toolchain and denied egress; the candidate passes its real native
      smoke without downloading an untracked prebuild.
- [ ] `reviewed=candidate=main=tag=published` holds for one full commit/tree.
- [ ] Required security, live, restore, governance, and independent-review gates pass.
- [ ] Rollback compatibility and operator steps are tested before promotion.

## Verification

Run synthetic governance/export/erase and release-manifest/SBOM/provenance
tests, the denied-egress offline native source build and SQLite smoke, all
required live/recovery/adversarial lanes, `bash scripts/ci.sh`, and
`git diff --check`.
