# I/0/06 — Portable Temporal worker and server-bound task identity

## Problem

Temporal stages reuse one task identity across different agents/roles, workers
depend on the source checkout/current directory, and activity clients can
create a Gateway per call. Even after I/0/02 freezes truthful workflow
semantics, that runtime is neither attributable nor portable.

## Scope

- Consume, without redefining, I/0/02's real-envelope, KO/nonzero fail-closed,
  approval, review-digest, replay, and opaque-history contract.
- Allocate distinct server-bound task identities for implement, test, and
  review, each tied to its actual agent/role, durable operation, and trace.
- Package an installed worker that resolves declared resources without the
  source checkout or caller cwd and owns one authenticated long-lived internal
  Gateway channel for its lifetime.
- Provide the compatibility transport shim for captured pending V1 Temporal
  activities: preserve activity names, task queue, inputs, outputs, and replay
  semantics while routing their old worker call shape through that one internal
  Gateway channel. The shim exposes no public MCP `0.1` endpoint and creates no
  second Gateway, direct DB writer, or direct audit writer.
- Bind that channel to one Gateway audience/boot and fail closed on recursive
  startup, second writer, stale identity, or unavailable control plane.
- Drain and close the worker channel deterministically across success, failure,
  cancellation, worker restart, and version upgrade.

## Non-scope

- No reimplementation of I/0/02 result/replay semantics, public MCP protocol
  version/default/retirement decision (owned by I/0/08), full disposable stack,
  selector cutover, legacy workflow removal, rewrite of existing histories,
  workflow-side DB/audit access, or real remote push.

## Acceptance criteria

- [ ] Implement, test, and review use distinct server-bound task/agent/role IDs.
- [ ] An installed worker runs from a foreign cwd/home without the source tree.
- [ ] One worker owns one authenticated Gateway channel, never one per activity.
- [ ] A captured pending V1 history completes through the compatibility shim
      with unchanged activity/task-queue/input/output/replay semantics.
- [ ] The shim uses the single internal channel and no public MCP `0.1`, direct
      DB/audit writer, or second Gateway.
- [ ] Recursive/second Gateway startup and stale audience/boot fail closed.
- [ ] Channel shutdown/restart leaves no orphan process or duplicate operation.
- [ ] I/0/02 remains the single owner of envelope, KO, approval, and replay truth.
