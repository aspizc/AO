## Problem

The optional PostgreSQL scaffold synchronously interpolates values into SQL and
invokes `psql`, so it lacks bound parameters, pool lifecycle, transactional
parity, and credible live-backend evidence.

## Scope

- Replace subprocess SQL execution with an asynchronous maintained PostgreSQL
  driver/pool and bound parameters for every data value; dynamic identifiers
  come only from closed server-owned allowlists.
- Implement the same repository/transaction/outbox contracts as SQLite,
  including atomic migration markers, advisory locking/version checks,
  rollback, typed errors, and explicit fail-fast backend selection.
- Keep credentials out of argv/logs/errors, bound connection and query
  timeouts, implement the canonical E/0/04 `stateStore` sampler and allowlisted
  PostgreSQL USE source, and close/drain the pool deterministically.
- Add a required disposable PostgreSQL live lane with schema/repository parity,
  concurrency, migration, fault, restart, and cleanup coverage; no skip may
  masquerade as pass.

## Non-scope

- No silent fallback to a second store, production HA/multi-region claim,
  arbitrary SQL console, or migration against shared/live data.

## TDD RED

Use quote/comment/encoding injection canaries, identifier substitution,
transaction rollback and crash, concurrent migration, unavailable/restarted
server, pool exhaustion, stale/current health evidence mapping, credential
leak, missing `psql` binary, and a skipped live lane.

## TDD GREEN

Add the driver-backed pool/transaction adapter, parameterized repositories and
migrator, E/0/04 state-store/metric adapters, typed readiness/error mapping,
and ephemeral PostgreSQL CI harness.

## Acceptance criteria

- [ ] No production query interpolates a data value or invokes `psql`.
- [ ] SQLite and PostgreSQL satisfy the same repository/outbox contract suite.
- [ ] Migrations and markers commit atomically under one migration owner.
- [ ] Backend failure is explicit; it never silently creates/switches stores.
- [ ] PostgreSQL readiness and USE data conform to E/0/04 without redefining
  its component, reason, freshness, or label contract.
- [ ] The required live lane runs with zero unexpected skips and cleans up.

## Verification

Run injection and repository parity suites, transactional migration/fault and
pool lifecycle tests, the disposable PostgreSQL lane twice, credential
canaries, `bash scripts/ci.sh`, and `git diff --check`.
