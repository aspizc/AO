## Problem

Unit/fake lanes cannot prove that PostgreSQL, Redis, Temporal, one Gateway, an
installed worker, and protected providers interoperate with the same candidate
or clean up reliably.

## Scope

- Ship a portable disposable stack with PostgreSQL, Redis, Temporal, exactly
  one Gateway, and the installed I/0/06 worker, using explicit service
  identities, private networks, health/readiness gates, and digest-pinned inputs.
- Run the E/0/04 manager-attested watchdog/probe and disposable OTLP backend;
  gate on the canonical health projection and observability evidence rather
  than container/process existence.
- Run the real Gateway envelope/replay contracts from I/0/02, PostgreSQL
  contracts from I/0/05, Redis races from G/0/00, and the protected provider
  proof from H/0/05 without redefining their assertions.
- Make the selected live lane required, candidate-bound, zero-unexpected-skip,
  timeout-bounded, and fail-closed when a dependency or capability is absent.
- Inject service restart, delayed readiness, broken auth, network loss, worker/
  Gateway crash, and cleanup failure; retain only allowlisted diagnostics.

## Non-scope

- No production HA/multi-region claim, shared/live service mutation, personal
  data, permanent credentials, remote push, or replacement of each component's
  focused contract owner.

## TDD RED

Run the candidate with a missing/skipped service, wrong digest, duplicate
Gateway, forged service identity, stale observer, stalled Gateway,
delayed/broken dependency, cross-run data, crash/restart, exporter gap, secret
canary, leaked process/network/volume, and second cleanup.

## TDD GREEN

Add the digest-pinned stack manifest, isolated networks/volumes/identities,
E/0/04 watchdog and observability services, readiness orchestrator,
required-lane aggregator, fault harness, safe evidence bundle, and idempotent
teardown attestation.

## Acceptance criteria

- [ ] One candidate boots PostgreSQL, Redis, Temporal, Gateway, and worker.
- [ ] Exactly one Gateway owns control state throughout every fault scenario.
- [ ] Required component contracts pass with zero unexpected skips.
- [ ] Health gates distinguish stale observer, dead process, stalled loop, and
  not-ready state and export the required E/0/04 SLO evidence.
- [ ] Broken auth/readiness/restart fails or recovers with a bounded outcome.
- [ ] Teardown twice leaves no process, port, network, volume, data, or credential.

## Verification

Run the full stack twice, each dependency/Gateway/worker fault, candidate-digest
and skip sentinels, protected-provider evidence, leak scans, and teardown
attestation; then `bash scripts/ci.sh` and `git diff --check`.
