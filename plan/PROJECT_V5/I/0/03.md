## Problem

Schema migrations and state/artifact loss cannot be safely operated without a
tested, consistent backup boundary and restore/reconciliation procedure.

## Scope

- Define consistent backup manifests for control DB, committed artifact store,
  configuration/schema versions, and required durable workflow metadata.
- Encrypt/protect operator-managed backups, verify checksums, and restore only
  into an owned stopped/new instance.
- Reconcile operations/outbox/artifacts/process/workflow state after restore and
  measure recovery objectives.

## Non-scope

- No credential/token export, backup of ephemeral Redis presence/inboxes as
  authoritative state, restore over a live writer, or untested vendor promise.

## TDD RED

Test torn/mismatched DB-artifact snapshot, corrupt/missing object, wrong
schema/key, live-writer restore, interrupted restore, repeated restore, and
post-restore outbox/workflow/process reconciliation.

## TDD GREEN

Add versioned manifest/backup/restore commands, verification, atomic destination
swap, and synthetic recovery drill.

## Acceptance criteria

- [ ] Backup set is versioned, checksummed, and internally consistent.
- [ ] Restore fails safely on corruption/mismatch and never overwrites live state.
- [ ] Restored state reconciles without duplicate external effects.
- [ ] Documented RPO/RTO are measured by an automated synthetic drill.

## Verification

Run backup/restore corruption/interruption/reconciliation tests and full
disaster-recovery drill on disposable state; then `bash scripts/ci.sh` and
`git diff --check`.
