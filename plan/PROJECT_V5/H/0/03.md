## Problem

KYA-specific names, paths, models, prompts, and closure behavior can accidentally
become product defaults and hide missing generic contracts.

## Scope

- Express KYA entirely as inputs to the canonical profile/sample runner.
- Remove special-case runtime/prompt/closure branches and owner-personal
  defaults from active configuration/docs.
- Verify another synthetic profile follows the identical lifecycle/gates.

## Non-scope

- No deletion of useful historical context, KYA-exclusive authority, personal
  repository auto-detection, or silent selection by hostname/user.

## TDD RED

Scan for active KYA/personal conditionals and defaults; run KYA plus a second
profile to expose different tool/lifecycle/gate behavior.

## TDD GREEN

Move KYA values into a versioned example profile and route both examples through
the generic runner.

## Acceptance criteria

- [ ] KYA needs no product code branch.
- [ ] No personal path/model/agent default ships.
- [ ] KYA and the synthetic profile use identical typed gates.
- [ ] Historical docs remain clearly marked non-authoritative.

## Verification

Run two-profile contract/hero-flow tests and repository-wide personal/special
case structure scans; then `bash scripts/ci.sh` and `git diff --check`.
