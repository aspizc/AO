## Problem

Models, capabilities, tool guidance, role behavior, and review/closure rules are
duplicated across registries, prompts, runbooks, and personal examples.

## Scope

- Define one versioned orchestrator profile contract generated/verified against
  model/capability and tool catalogs.
- Ship canonical prompts for plan, execute, coordinate, review, recovery, and
  completion with typed artifact/tool references.
- Keep environment-specific model selection explicit and capability-validated.

## Non-scope

- No personal path/model/profile default, prompt-only authority, hidden tool,
  or separate KYA completion semantics.

## TDD RED

Detect stale model/tool ID, missing capability, prompt/schema argument drift,
unsupported profile override, personal path/name default, and prose bypass of a
typed gate.

## TDD GREEN

Add the profile schema/registry, prompt projections, and bidirectional
catalog/profile/prompt validators.

## Acceptance criteria

- [ ] One profile explains supported roles, models, tools, and gates.
- [ ] All shipped prompt examples validate against current schemas.
- [ ] Unsupported model/capability combinations fail before launch.
- [ ] No owner-personal default appears in product surfaces.

## Verification

Run registry/profile/prompt/schema parity and personal-default structure scans;
then `bash scripts/ci.sh` and `git diff --check`.
