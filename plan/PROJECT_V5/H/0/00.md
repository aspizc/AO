## Problem

Models, aliases, reasoning effort, service tier, capabilities, tool guidance,
role behavior, and workflow guidance are duplicated across registries, prompts,
runbooks, adapters, and personal examples. A caller or adapter can therefore
observe a different effective selection from policy or audit.

## Scope

- Define one versioned orchestrator profile contract generated/verified against
  model/capability and tool catalogs.
- Make that contract the only source and resolver for provider, canonical
  `model`, `reasoningEffort`, and `serviceTier`. Model resolution is an
  explicit canonical ID/exact alias, then the agent default. Effort/tier
  resolution is explicit request, selected-model profile default, then agent
  default; undeclared values never fall back to environment or adapter
  defaults.
- Emit one immutable `EffectiveAgentSelection` containing canonical agent/
  provider, canonical model, nullable effective effort/tier, resolution source,
  and registry digest. Policy, dry-run, audit, delegate, and spawn consume the
  same object; audit records only those effective non-secret values and the
  digest, never a raw alias or rejected caller payload.
- Extend canonical tool guidance with machine-readable risk, destructive,
  idempotency, retry, and protected-effect metadata for every mutation.
- Ship canonical prompts for plan, execute, coordinate, review, recovery, and
  completion with typed artifact/tool references. Later review/completion gate
  IDs may be referenced as unavailable prerequisites, never projected as
  implemented by this sheet.
- Keep environment-specific model selection explicit and capability-validated.
  Unknown provider/model/alias and unsupported effort/tier combinations fail
  before adapter selection or child creation.

## Trial 3 authority hardening

`EffectiveAgentSelection` is now an in-process capability. The canonical
resolver is the only code that records selections in a module-private
authority set, after freezing the exact top-level and `resolutionSource` data
shapes. Every assert/consume boundary requires that provenance, the exact
digest and sources, and frozen data-only properties. Structural or frozen
clones, JSON rehydration, Proxies, extra/source-tampered objects, and objects
from another module instance fail before policy or execution effects.

Service calls pass adapters only that selection object, never parallel raw
model, effort, or tier fields. Direct adapters resolve once when no selection
is supplied; when a genuine selection is supplied, any simultaneous raw field
is rejected. Codex and Claude derive every provider argument from the consumed
selection. Gemini remains registry-only and cannot reach cwd, lifecycle,
session, tmux, provider, or child behavior.

Delegate and spawn adapter results have a closed, data-only contract. The
service rejects missing/replaced/cloned selections, unknown or contradictory
selection fields, Proxies, and accessors. It validates exact `===` identity and
the safe projection before successful model audit or session persistence, then
returns a closed copy carrying the authoritative reference. Adapter-controlled
aliases or replacement objects therefore cannot diverge policy, audit,
dry-run, service, or tool output.

The Trial 3 probes retain binding-first D/0/00 behavior, one resolution per
operation, actor/target policy separation, safe rejection bodies/JSONL, and
zero lifecycle effects for forged selections. Shared suite inventories remain
owned by the integration lane and are not changed here.

## Trial 4 closed adapter-result contracts

The service now treats an adapter result as untrusted input and admits one
exact data-only shape for each executable provider and operation. Codex
delegate results require strings for stdout/stderr, a process exit code in
`-1..255`, a boolean dry-run flag, the exact selected model/effort/tier, the
authoritative selection identity, and a non-empty sandbox string.
Claude delegate results require the same common fields and exact model/effort,
but reject Codex-only tier and sandbox fields. Both spawn contracts require
non-empty session, target, attach, and launch strings, a boolean dry-run flag,
the exact selection, and `sessionId === tmuxTarget`. Registry-only providers
have no result contract.

Validation rejects missing, additional, undefined, null, boxed, nested,
proxied, accessor-backed, callable, symbol, bigint, non-finite, fractional,
and out-of-range values before session persistence or successful model audit.
It reads only top-level data descriptors, never coerces an adapter-owned
value, and returns a new frozen DTO containing validated primitives plus the
same canonical selection. A nested `sessionId` Proxy with `toJSON` therefore
cannot execute or reach JSONL/tool serialization.

Trial 4 retains legitimate Codex and Claude dry-run/process results, including
non-zero and `-1` exits, null and persisted task flows, D/0/00 binding-first
authority, and the registry-only Gemini denial. The two historical H fake
adapters were updated only to emit the already-shipped legitimate result
shapes. Shared suite inventories remain integration-owned and are unchanged.

## Trial 5 semantic result-envelope hardening

The Codex sandbox returned by an adapter is authoritative only when it is one
of `read-only`, `workspace-write`, or `danger-full-access` and exactly matches
the effective `createAgentService` configuration. An omitted setting has the
explicit `workspace-write` default. An invalid Codex configuration fails
before adapter lookup for both delegate and spawn; unknown, whitespace, or
mismatched delegate results fail before persistence and successful audit.

Spawn identity and command fields now have field-specific contracts:

- `sessionId` and `tmuxTarget` are identical canonical lowercase ASCII tmux
  targets, start with an alphanumeric character, contain only alphanumerics
  and hyphens, and are bounded to 96 characters;
- `attachCommand` is exactly `tmux attach -t <tmuxTarget>`;
- `launchCommand` is non-empty, trim-stable, NFC-stable, bounded to 8,192
  UTF-16 code units, and contains no Unicode control, format, line-separator,
  or paragraph-separator character.

The launch-command check validates only the closed result envelope. It does
not parse or reconstruct provider argv, which remains exclusive to D/0/01.
Legitimate internal spaces and NFC Unicode paths remain accepted. NUL, tabs,
newlines, other controls, whitespace-only values, noncanonical normalization,
arbitrary attach text, and overlong values fail with the existing stable
allowlisted selection denial before session persistence,
`AGENT_MODEL_RESOLVED`, or MCP success serialization.

Trial 5 preserves Trial 4's nested Proxy/toJSON guarantee: rejected nested
values execute no traps, disclose no sentinel, and produce no successful
audit or session record. Shared suite inventories remain integration-owned and
unchanged.
