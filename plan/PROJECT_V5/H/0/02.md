## Problem

The product lacks one reproducible path that demonstrates planning, execution,
coordination, operator approval, independent review, recovery, and honest
completion without hidden manual state edits.

## Scope

- Add a one-command dry-run over the sample repo using the same public
  lifecycle, overview, approval, review, coordination, and completion contracts.
- Make the output visibly trace one real policy decision, restricted
  sanitization/projection decision, approval preview/sign/consume sequence, and
  corresponding allowlisted audit event IDs without exposing raw content.
- Emit an outcome summary with stable IDs/digests and explicit gate decisions.
- Support pause/resume and a documented injected-failure recovery path.

## Non-scope

- No real repository push/merge, autoapproval, raw model output, service mocks
  that bypass public boundaries, or claim of real-mode containment from dry-run.

## TDD RED

Fail on missing doctor prerequisite, skipped gate, false completion, unsigned
approval, stale review, duplicate resume, coordination outage, and injected
crash without recovery; also fail if policy, sanitization, approval consumption,
or audit linkage is bypassed or absent from the visible evidence.

## TDD GREEN

Implement the profile-driven runner/CLI composition and deterministic dry-run
fixtures through actual service/tool boundaries.

## Acceptance criteria

- [ ] One command reaches honest completion on the sample.
- [ ] Approval/review/completion gates are real and inspectable.
- [ ] Policy, sanitization, approval, and audit decisions are visibly linked.
- [ ] Resume/recovery does not duplicate effective work.
- [ ] Failure output directs the operator to overview/status/remediation.

## Verification

Run the hero flow clean and with each injected failure/resume/bypass scenario,
evidence-linkage and CLI goldens, full E2E, `bash scripts/ci.sh`, and
`git diff --check`.
