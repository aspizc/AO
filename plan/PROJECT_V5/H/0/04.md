| Review id | `H_0_4` |

## Problem

Test pass counts do not show whether users finish work, why they block, how long
recovery takes, or whether the operator can restore service safely.

## Scope

- Define metadata-only outcome metrics for start-to-complete, blocker/gate
  reason, approval/review latency, retries/recovery, coordination backlog, and
  terminal outcome.
- Register those outcome sources against E/0/04's closed metric/export
  contract and SLO recording rules; do not create a parallel exporter or
  durable cursor.
- Include Gateway liveness/readiness, event-loop stall detection, time to detect,
  outage duration, recovery start, ready-again time, and explicit RTO target/
  breach reason from the canonical health signals.
- Add a repeatable operator drill for coordination outage, process crash,
  event-loop stall, Gateway restart/reconciliation, pending approval, stale
  review, and resume.
- Bind promotion evidence to one tree/profile/environment digest.

## Non-scope

- No prompt/source/body/user-content telemetry, vanity success metric, mixed
  build evidence, or automatic destructive remediation.

## TDD RED

Inject every failure and assert metric correctness, no sensitive fields,
deterministic drill steps, stale/missing health signal, measured RTO breach, and
invalid mixed-digest promotion evidence.

## TDD GREEN

Add E/0/04-allowlisted metric mappings, outcome report/validator, and scripted
synthetic recovery drill.

## Acceptance criteria

- [ ] Metrics explain success, block, failure, and recovery without raw data.
- [ ] Gateway death/stall and ready-again time produce a measured RTO outcome.
- [ ] An operator can execute the documented drill from shipped tooling.
- [ ] Evidence is candidate-digest consistent and machine-validated.
- [ ] Recovery regressions fail the promotion gate.

## Verification

Run metric leak/mapping tests and the complete Gateway stall/kill/recovery drill
twice with RTO assertions; then `bash scripts/ci.sh` and `git diff --check`.
