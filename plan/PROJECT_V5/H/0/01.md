## Problem

Users cannot tell whether dependencies, agent login, config, repository,
policy, runtime isolation, and Redis coordination are ready before starting a
workflow.

## Scope

- Ship a minimal synthetic sample repository/plan/profile with no personal data.
- Provide one documented lock-only bootstrap that succeeds from a clean
  checkout with no existing `node_modules`, virtualenv, generated files,
  owner-local paths, or undeclared tools.
- Add `doctor` checks for supported runtime/dependencies, model CLI/login,
  config paths, canonical repository binding, policy/profile, isolation, state
  ownership, Redis status/scope, and required ports/services.
- Produce safe human and JSON diagnostics with remediation links.

## Non-scope

- No credential display/upload, automatic login, mutation of personal config,
  shared service restart, or “green” for an untested required dependency.

## TDD RED

Fixture each missing/wrong dependency, stale login, unsafe repo/runtime overlap,
bad policy/profile, unreachable/wrong-scope Redis, second writer, secret-bearing
error, dirty/preinstalled dependency reliance, owner-local path, and all-good
clean-checkout bootstrap/sample.

## TDD GREEN

Implement the read-only preflight command/check registry and deterministic
sample harness.

## Acceptance criteria

- [ ] Doctor distinguishes pass/warn/fail with actionable checks.
- [ ] It verifies coordination status without registering a participant.
- [ ] It never prints tokens, credentials, raw config, or personal paths.
- [ ] The documented bootstrap uses reviewed locks and no pre-existing install.
- [ ] The sample is portable and passes from a clean checkout.

## Verification

Run doctor fixture/golden/JSON/leak tests and bootstrap plus sample preflight in
a fresh checkout/home with empty dependency caches; then `bash scripts/ci.sh`
and `git diff --check`.
