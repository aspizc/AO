## Problem

`artifact.get` requires a requester agent and role while `artifact.list`
previously did not. A caller can therefore list successfully and fail on the
next read, and artifact metadata could be enumerated without the policy check
used for content access.

## Scope

- Require `requesterAgent` and `requesterRole` on `artifact.list`, matching
  the existing transitional `artifact.get` call shape.
- Evaluate the dedicated `artifact.list` policy action before returning
  metadata and deny unknown principals.
- Record `POLICY_DECIDED` in the local JSONL audit only so this correction does
  not add or change records in the shared `agents:events` Stream.
- Migrate first-party smoke callers and document that both fields are legacy
  caller assertions pending server-derived `RequestContext` in D/0/00.

## Non-scope

- No claim that caller-supplied identity authenticates a principal.
- No `artifact.get`, artifact-store, sanitization, `agents:events`,
  coordination-stream, `message.*`, or policy-registry semantic change.

## TDD RED

Fail listing without either requester field, listing as an unknown principal,
and a publisher-spy assertion when the new list policy event reaches
`agents:events`.

## TDD GREEN

Use the strict requester schema and existing policy engine, return no metadata
on deny, append the allowlisted decision through the JSONL-only audit path,
and update every first-party caller.

## Acceptance criteria

- [x] `artifact.list` and `artifact.get` require the same requester fields.
- [x] Unknown requester identity receives `POLICY_DENIED` before metadata.
- [x] The local audit contains one `artifact.list` policy decision.
- [x] A configured legacy Redis audit publisher receives zero new list events.
- [x] Smoke callers and public documentation use the new shape.
