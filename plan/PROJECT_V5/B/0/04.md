## Problem

Unit parity cannot prove that two independent orchestrators remain mutually
visible and exchange auditable decisions across Redis and process restarts.

## Scope

- Exercise two isolated Gateway/direct-client instances against an ephemeral
  Redis 7 service and the same default scope.
- Cover register/discover, bidirectional notice exchange, decision artifact
  verification, restart/re-register, stale lease rejection, reclaim, and ACK.
- Record only synthetic IDs/digests and deterministic test evidence.

## Non-scope

- No use, restart, flush, or reconfiguration of the shared development Redis or
  MCP server; no real repository mutation.

## TDD RED

The lane must fail when scopes diverge, a stale incarnation reads/ACKs, restart
duplicates a consumer result, or a decision artifact/digest is missing.

## TDD GREEN

Create an isolated service harness with separate clients/process state,
ephemeral namespace, bounded waits, cleanup, and explicit no-skip sentinel.

## Acceptance criteria

- [ ] Both default participants discover one another without caller scope.
- [ ] Restart converges without stale-token access or duplicate decision use.
- [ ] Decision evidence survives transport retry and is verified before use.
- [ ] The required lane cannot pass by skipping Redis or running zero tests.

## Verification

Run the isolated two-orchestrator Redis acceptance lane twice, the full
Gateway/E2E suites, `bash scripts/ci.sh`, and `git diff --check`.
