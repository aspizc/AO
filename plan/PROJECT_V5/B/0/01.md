## Problem

Reasonable but different caller-chosen scopes make healthy orchestrators
invisible to one another, while the channel cannot be health-checked without a
blind registration attempt.

## Scope

- Configure one canonical scope per Gateway instance, defaulting to
  `agents-orchestrator`; omitted caller scope resolves to it and mismatches fail
  explicitly.
- Add read-only `coordination.status`, backed by Redis `PING`, reporting
  readiness, effective scope, namespace/group, and lease limits.
- Include `PING` in the documented least-privilege Redis ACL command
  inventory.
- Keep status free of registration, domain-event, and legacy audit-stream
  writes.

## Non-scope

- No cross-scope discovery, public scope enumeration, or implicit scope join.
- Tool discovery still requires the normal MCP reconnect after deploying a new
  server binary; this sheet does not interrupt a running shared server.

## Acceptance criteria

- [x] Two default clients share the configured canonical scope.
- [x] An explicit different scope fails with `COORDINATION_SCOPE_MISMATCH`.
- [x] Status performs no registration or coordination-stream write.
- [x] Disabled/unreachable Redis remains `COORDINATION_UNAVAILABLE`.
- [x] The least-privilege ACL inventory includes every status command.
