## Frozen Option 1 topology

Persistent port executions use exactly this topology:

```text
Gateway process
  |
  | fd 0: bounded provider-data-free JSON lifecycle commands
  | fd 3: bounded provider-data-free JSON lifecycle transcript
  | fd 4/5: private bounded binary session-port request/response sideband
  v
D helper/reaper + terminal broker (owns helper lease, PTY master, and operation queue)
  |\
  | \ direct fork: setsid + controlling PTY slave + dup2(0/1/2)
  |  \____________________________________________________________
  |                                                               v
  |                                              literal provider `execve(argv)`
  |
  +-- private 0700 runtime directory / 0600 relay socket
          ^
          | raw terminal output; operator input returns through the same
          | identity-checked broker queue
          |
  tmux session `<tmuxTarget>` (fixed 120x40 pane)
          |
          +-- direct-argv configured-runtime relay; never a provider launcher,
              never a shell command, never `send-keys`
          ^
          |
  local operator runs exactly `tmux attach -t <tmuxTarget>` (interactive R/W authority)
```

Normative coexistence rules:

1. The helper/reaper allocates the PTY. The literal provider is its supervised descendant and
   retains the existing direct `execve(launch["argv"][0], launch["argv"], launch["env"])`
   ownership. Provider argv is never a tmux command or a joined command string.
2. Tmux owns only the outer presentation pane. It launches the configured-runtime relay with
   tmux's direct multi-argument command form; the implementation rejects a tmux runtime without
   direct-argv support. The relay connects only to the private helper socket. It neither launches
   the provider nor holds the programmatic capability.
3. Programmatic prompt bytes travel on fd 4 to the broker and are written to the inner PTY
   master. Tmux command input is never used. The broker also linearly orders explicit operator
   keystrokes arriving from the relay, but that local OS/tmux authority is separate from the
   Gateway capability.
4. Provider output is incrementally UTF-8-normalized by the broker, backpressured through the
   relay, and rendered by the fixed tmux pane. No unbounded output copy is accumulated. Port
   snapshot requests barrier the relay and capture that pane using direct argv.
5. A lost relay, changed pane, closed PTY, helper loss, utility exit, or tmux-session replacement
   revokes the port and enters the existing termination/settlement path.
6. Port-enabled persistent starts accept no caller `stdout` or `stderr` destination: the terminal
   is their sole output boundary. One-shot starts and the existing
   `createProcessSupervisor(...)` API retain their reviewed stream behavior unchanged.

The future splice must construct the existing public spawn fields without alteration:

```js
{
  sessionId: tmuxTarget,
  tmuxTarget,
  attachCommand: `tmux attach -t ${tmuxTarget}`,
  launchCommand,      // existing display field; never the execution substrate
  dryRun,
  effectiveSelection,
}
```

The target remains the existing safe 1–96 byte
`[a-z0-9][a-z0-9-]*` value. Returning attach metadata does not attach a client. Running the
literal command is an intentional local-operator act that can both observe and write, matching
today's supervised intervention semantics. Programmatic `agent.ask` will use the capability;
`agent.view` will use its bounded snapshot; neither will run attach or `send-keys`.

## Frozen internal issuance and capability API

### Factory and consumer handoff

`gateway/src/adapters/process_supervisor.js` adds one named internal-composition factory while
leaving `createProcessSupervisor(...)` unchanged:

```js
const {
  supervisor,
  sessionPortIssuer,
} = createProcessSupervisorSessionPortFactory(options);

const execution = await supervisor.start(persistentRequest);
const issued = await sessionPortIssuer.claim({ execution });
```

The factory returns one frozen plain object with exactly `supervisor` and `sessionPortIssuer`.
The composition root passes `supervisor` through the ordinary execution dependency and injects
`sessionPortIssuer` only into the future serialized `D_0_1_SPLICE` consumer. Neither the issuer,
an issuer method, a capability, a descriptor, nor a sideband stream appears on the supervisor,
start request, execution, utility identity, completion, queue, audit record, or any exported
prototype.

`claim` accepts one exact plain data argument with the sole own enumerable field `execution`.
The value must be the exact frozen execution object created by the same factory. It waits through
bootstrap, returns the same issued object on an idempotent repeat by that issuer/execution pair,
and rejects a one-shot or foreign execution. It never mints a second port for one execution.

### Exact immutable shapes

| Surface | Exact input | Frozen result |
|---|---|---|
| `sessionPortIssuer.claim` | `{execution}` | `{port, observation}` |
| `port.writePrompt` | `{prompt}`; exact plain data object | `{sequence, acceptedBytes}` |
| `port.snapshot` | `{}`; no own keys | `{sequence, snapshot, snapshotBytes, truncated}` |
| `observation` | no method; issued DTO | `{sessionId, tmuxTarget, attachCommand}` |

`sequence` is a positive safe integer assigned at FIFO operation admission and is scoped to one
port. `acceptedBytes` is the prompt's UTF-8 byte count, excluding framing. `snapshotBytes` is the
UTF-8 byte count of the returned string, including any truncation marker. Every result and the
observation DTO has `Object.prototype`, own enumerable data fields only, and is recursively
frozen.

The port is a frozen null-prototype object with exactly two own, non-configurable methods.
Module-private method implementations authenticate their exact `this` receiver through a
`WeakMap`; detaching/copying a method and calling it without the original receiver returns
`SESSION_PORT_UNAUTHORIZED`. There is no exported port class or prototype. Supplying extra
argument keys, accessors, proxies, symbols, a foreign session identifier, or a replacement
prototype fails validation before a sideband/descriptor operation.

The port deliberately has no `attach`, `attachInfo`, `cancel`, descriptor, token, target, or
arbitrary-write method. Snapshot is capability-bound read authority. The separately returned
observation is inert public metadata; executing its attach command requires the existing local
tmux socket/OS operator authority and is outside the programmatic port.

### Normative `ASP1` request/response codec

Fd 4 is parent-to-helper request only and fd 5 is helper-to-parent response only. Both are
byte streams framed with this exact 48-byte header. Multi-byte integers are unsigned
**network byte order (big-endian)**; no native-endian struct layout is permitted.

| Offset | Bytes | Field | Exact rule |
|---:|---:|---|---|
| 0 | 4 | magic | ASCII bytes `41 53 50 31` (`ASP1`) |
| 4 | 1 | version | `01` |
| 5 | 1 | opcode | exact direction-specific value below |
| 6 | 2 | reserved | `00 00`; any other value is malformed |
| 8 | 4 | sequence | uint32-BE, `1..0xffffffff`; starts at 1 and increases by exactly 1 |
| 12 | 4 | payload length | uint32-BE exact payload byte count; bounded by the opcode |
| 16 | 32 | binding tag | raw 32-byte HMAC result defined below |

There are no flags, padding, optional fields, native integers, JSON, or text numbers in this
codec.

| Direction | Opcode | Decimal | Payload | Successful JS interpretation |
|---|---:|---:|---|---|
| request | `0x01` `WRITE_PROMPT` | 1 | strict UTF-8 prompt bytes followed by one `0d`; total `2..65,537` bytes | operation begins only after complete validation |
| request | `0x02` `SNAPSHOT` | 2 | exactly zero bytes | barrier/capture operation |
| response | `0x81` `WRITE_OK` | 129 | exactly one uint32-BE prompt-byte count, excluding the CR; it must equal request length minus 1 | `{sequence,acceptedBytes}` |
| response | `0x82` `SNAPSHOT_OK` | 130 | exact canonical UTF-8 snapshot, `0..65,536` bytes | `{sequence,snapshot,snapshotBytes:length,truncated:false}` |
| response | `0x83` `SNAPSHOT_TRUNCATED` | 131 | exact marked canonical UTF-8 snapshot, `43..65,536` bytes | `{sequence,snapshot,snapshotBytes:length,truncated:true}` |
| response | `0xff` `ERROR` | 255 | exactly four provider-free bytes: uint16-BE error id, uint8 phase id, then `00` | fixed public error below; never a partial result |

`WRITE_PROMPT` rejects an absent CR, an earlier CR, invalid strict UTF-8, empty prompt,
U+0000, a surrogate, or more than 65,536 bytes before the final CR. A response sequence must
equal its sole in-flight request. The largest request is 65,585 bytes
(`48 + 65,536 + 1`); the largest response is 65,584 bytes (`48 + 65,536`).

Phase ids are exact: `0x01=claim`, `0x02=validation`, `0x03=identity`, `0x04=write`,
`0x05=snapshot`, and `0x06=lifecycle`.

| Error id | Public code | Permitted phase id and source |
|---:|---|---|
| `0x0001` | `SESSION_PORT_INVALID_ARGUMENT` | `0x02`; malformed caller input or request frame |
| `0x0002` | `SESSION_PORT_NOT_PERSISTENT` | `0x01`; parent-side claim only |
| `0x0003` | `SESSION_PORT_UNAUTHORIZED` | `0x01` for claim/receiver authority; `0x03` for tag, replay, or frame authority |
| `0x0004` | `SESSION_PORT_REVOKED` | `0x06`; operation admitted after revocation |
| `0x0005` | `SESSION_PORT_CANCELLED` | `0x06`; cancel wins and zero terminal bytes/result commit |
| `0x0006` | `SESSION_PORT_PROMPT_TOO_LARGE` | `0x02`; parent-side bound check only |
| `0x0007` | `SESSION_PORT_IDENTITY_CHANGED` | `0x03`; live process/helper binding mismatch |
| `0x0008` | `SESSION_PORT_NOT_FOREGROUND` | `0x03`; foreground equation mismatch |
| `0x0009` | `SESSION_PORT_TERMINAL_CHANGED` | `0x03`; PTY/pane/relay identity or dimension mismatch |
| `0x000a` | `SESSION_PORT_TERMINAL_CLOSED` | `0x06`; known PTY/relay/tmux close before commit |
| `0x000b` | `SESSION_PORT_WRITE_ABORTED` | `0x04`; dispatched write lacks authenticated success |
| `0x000c` | `SESSION_PORT_SNAPSHOT_FAILED` | `0x05`; barrier/capture/decoder/response failure |

The receiver validates in this precedence order so a multiply-invalid frame still has one
disposition: (1) complete header, magic/version/reserved, and global length; (2) constant-time
tag; (3) exact next sequence; (4) direction opcode and opcode-specific payload. The helper
never performs a PTY/capture operation until all four pass.

| Frame condition | Exact disposition | Named test |
|---|---|---|
| Bad magic/version/reserved, impossible length, invalid `WRITE_PROMPT` payload, or unknown request opcode | if a full header exists, `ERROR(0x0001,0x02)` echoes its decoded sequence; then revoke/close with zero terminal access | `rejects malformed ASP1 header and payload before terminal access`; `rejects unknown ASP1 request opcode before terminal access` |
| Binding-tag mismatch | `ERROR(0x0003,0x03)` then revoke/close with zero terminal access | `rejects an ASP1 binding-tag mismatch in constant time` |
| Request sequence `0`, lower than expected (duplicate), or higher than expected (gap/out of order) | `ERROR(0x0003,0x03)` then revoke/close with zero terminal access | `rejects duplicate ASP1 request sequence and revokes`; `rejects out-of-order ASP1 request sequence and revokes` |
| EOF/timeout before a complete request header/payload | no response is possible; revoke/close; a wholly dispatched write maps to `SESSION_PORT_WRITE_ABORTED`, a snapshot to `SESSION_PORT_SNAPSHOT_FAILED`, otherwise the not-yet-dispatched operation maps to `SESSION_PORT_TERMINAL_CLOSED` | `maps an incomplete ASP1 request by the dispatch interval` |
| Response has bad tag/sequence, a duplicate/gap, unknown opcode/error/phase, or a payload inconsistent with its request | revoke/close; a dispatched write maps only to `SESSION_PORT_WRITE_ABORTED`, and a snapshot maps only to `SESSION_PORT_SNAPSHOT_FAILED`; no supplied bytes/result escape | `maps malformed or unknown write response to WRITE_ABORTED`; `maps malformed or unknown snapshot response to SNAPSHOT_FAILED`; `rejects duplicate or out-of-order ASP1 response and revokes` |
| Complete valid `ERROR` with a permitted code/phase pair | construct only the fixed public error; discard operation buffers; apply its stated revoke rule | `maps every ASP1 error id to the exact provider-free public error` |

After any terminal disposition, trailing bytes are discarded rather than treated as a new
channel. A valid completed operation increments the next expected sequence; no retry reuses a
sequence.

### Exact 32-byte binding-tag construction

Inputs are validated as exactly 64 lower-case hexadecimal characters before decoding:

```text
K = hexDecode(leaseNonce)                  // 32 bytes; generated at launch
L = hexDecode(bindingDigest)               // 32-byte launch digest
H = SHA-256(K)                             // 32 bytes; exact leaseDigest
Q = helper CSPRNG terminal nonce           // 32 bytes, never leaves helper memory
N = SHA-256(Q)                             // 32-byte terminalNonceDigest
D = ASCII("agents.process-supervisor.session-port.binding-tag.v1\0")
bindingTag = HMAC-SHA-256(key=K, data=D || L || H || N)
```

The HMAC output is used as 32 raw bytes, never hex/base64 text. `N` is the only new terminal
nonce value in provider-data-free readiness metadata; `Q` is never sent. The parent already
owns `K` and `L`, verifies `H`, receives exact `N`, and independently derives the same tag.
Changing any input or its order changes the tag. The domain constant includes the shown final
NUL byte and no length prefix; all following values are fixed 32-byte fields.

Node compares a received 32-byte value with `crypto.timingSafeEqual`; Python uses
`hmac.compare_digest` on two 32-byte `bytes` objects. Length is checked before the primitive,
and no byte-by-byte/hex string comparison or early mismatch branch is allowed. `K`, `Q`, and
temporary tag buffers are overwritten on retirement where their mutable runtime permits; no
secret enters an error, log, transcript, audit, argv, or observation DTO.

### Cross-platform exact-relay authentication

Modes `0700`/`0600` provide filesystem isolation but are **not** relay-instance
authentication. The helper additionally binds one socket connection to the exact tmux pane
process and a single-use nonce proof before the relay reads fd 0 or any operator byte enters
the broker queue.

The relay key is domain-separated from the sideband tag:

```text
R = HMAC-SHA-256(
      key=K,
      data=ASCII("agents.process-supervisor.session-port.relay-key.v1\0")
           || L || H || N
    )                                      // exactly 32 bytes
```

The helper creates a new regular key file containing only `R`, with `O_CREAT|O_EXCL`,
owner equal to the helper euid, mode `0400`, size 32, and no symlink traversal. Tmux receives
the socket path and key-file path only as literal direct argv to the configured-runtime relay.
The relay opens with `O_RDONLY|O_CLOEXEC|O_NOFOLLOW`, verifies owner/mode/type/size, reads
exactly 32 bytes, closes and unlinks the file, and never places `R` in argv, environment,
stdout, stderr, or tmux history. Key-file secrecy is not the sole check: another same-user
process that learns `R` still has the wrong kernel peer PID.

After direct-argv pane creation, while broker output is paused, the helper runs direct argv
equivalent to:

```text
tmux display-message -p -t <tmuxTarget> \
  "#{pid}\t#{session_id}\t#{pane_id}\t#{pane_pid}\t#{pane_width}\t#{pane_height}"
```

It records the exact tmux server/session/pane ids and the pane PID, then reads and binds that
PID's start token, executable, NUL-delimited argv, cwd, pgid, and sid with the same platform
readers used for utility identity. The relay must remain the direct pane process: it may not
fork, daemonize, or hand the socket to a child.

For each accepted Unix-socket fd, the helper obtains this kernel evidence and fails closed if
any field is unavailable, short, malformed, or changes on the immediate fresh reread:

| Platform | Mandatory peer evidence | Exact acceptance |
|---|---|---|
| Linux | `getsockopt(SOL_SOCKET, SO_PEERCRED)` yielding kernel `pid,uid,gid` | uid/gid equal helper effective uid/gid; peer PID equals recorded `pane_pid`; fresh `/proc/<pid>/stat`, `exe`, NUL `cmdline`, and `cwd` equal the recorded relay identity |
| Darwin | `getpeereid(fd)` yielding effective uid/gid plus `getsockopt(SOL_LOCAL, LOCAL_PEERPID)` yielding kernel peer PID | uid/gid equal helper effective uid/gid; peer PID equals recorded `pane_pid`; fresh `proc_pidinfo`, `getsid`, `proc_pidpath`, `KERN_PROCARGS2`, and `PROC_PIDVNODEPATHINFO` equal the recorded relay identity |

The authenticated handshake uses a separate fixed binary envelope:

| Offset | Bytes | Rule |
|---:|---:|---|
| 0 | 4 | ASCII `ASR1` |
| 4 | 1 | version `01` |
| 5 | 1 | message type |
| 6 | 2 | reserved `00 00` |
| 8 | 4 | uint32-BE payload length |

| Type | Decimal | Payload |
|---:|---:|---|
| `0x01` `CHALLENGE` | 1 | exactly 32 fresh CSPRNG bytes `C` |
| `0x02` `PROOF` | 2 | uint64-BE relay `getpid()` followed by 32-byte proof |
| `0x03` `ACCEPT` | 3 | zero bytes |
| `0x7f` `REJECT` | 127 | uint16-BE reject id from the table below |

The relay proof is exactly:

```text
P = HMAC-SHA-256(
      key=R,
      data=ASCII("agents.process-supervisor.session-port.relay-proof.v1\0")
           || C || uint64BE(relay_getpid)
    )
```

The helper first verifies kernel peer evidence, then sends one fresh challenge, requires one
well-formed proof whose PID equals both the kernel peer PID and recorded pane PID, and compares
`P` in constant time. The connection-to-proof deadline is 2,000 ms on a monotonic clock.
`C` and `R` are single-use. Only then does it send `ACCEPT`, mark the relay active, unpause
broker output, and let the relay poll/read fd 0. No pre-`ACCEPT` terminal input is read,
buffered by the relay, or enqueued.

| Reject id | Cause and public disposition | Named test |
|---:|---|---|
| `0x0001` | malformed/version/length/order proof → `SESSION_PORT_UNAUTHORIZED` | `rejects malformed or out-of-order relay proof before operator input` |
| `0x0002` | Linux `SO_PEERCRED` or Darwin `getpeereid`/`LOCAL_PEERPID` unavailable or malformed → `SESSION_PORT_UNAUTHORIZED` | `rejects relay when Linux peer evidence is unavailable`; `rejects relay when Darwin peer evidence is unavailable` |
| `0x0003` | peer uid/gid mismatch → `SESSION_PORT_UNAUTHORIZED` | `rejects relay with a different kernel uid or gid` |
| `0x0004` | peer PID differs from recorded pane PID → `SESSION_PORT_UNAUTHORIZED` | `rejects same-user relay with the wrong kernel peer pid` |
| `0x0005` | fresh start/executable/argv/cwd/pgid/sid differs or is unreadable → `SESSION_PORT_TERMINAL_CHANGED` | `rejects relay whose live pane identity changed` |
| `0x0006` | PID field or nonce proof mismatch → `SESSION_PORT_UNAUTHORIZED` | `rejects relay with the wrong nonce proof` |
| `0x0007` | replayed challenge/proof or second connection → `SESSION_PORT_UNAUTHORIZED` | `rejects replayed relay proof`; `rejects a duplicate relay connection` |
| `0x0008` | connection/proof deadline → `SESSION_PORT_TERMINAL_CLOSED` | `rejects relay handshake timeout before operator input` |

The positive tests are named
`accepts the exact Linux relay peer and nonce proof before operator input` and
`accepts the exact Darwin relay peer and nonce proof before operator input`.
Every reject sends `REJECT` only when the envelope is safe to write, then closes the candidate,
revokes the port, closes every component-owned retained descriptor, and enters the same terminal
cleanup ledger used by ordinary revocation. The one-time relay key is `RETIRED` only when its
pre-`ACCEPT` consumption already occurred; after `V`, an extant owned or replacement
key/socket/directory entry is `PRESERVED` without `unlink` or `rmdir`. Exact process and owned
pane/session targets become `RETIRED` or `PRESERVED` under their sealed-authority rules, while
the shared tmux server/socket is always preserved. Every reject also proves the broker
operator-input counter remains zero. A transport close that prevents `REJECT` retains the same
public disposition.

The lifecycle is:

```text
BOOTSTRAPPING --validated utility exec + foreground PTY + exact tmux relay--> ACTIVE
      |                                                                  |
      +--any bootstrap/loss/exit/cancel----------------------------------+
                                                                         v
                                                                    REVOKING
                                                                         |
                                     retained descriptors closed; cleanup targets
                                                RETIRED or PRESERVED
                                                                         v
                                                                     REVOKED
                                                                         |
                                               existing cleanup and public settlement
                                                                         v
                                                                     SETTLED
```

- `claim` during `BOOTSTRAPPING` waits. `ACTIVE` begins only after direct provider exec,
  authenticated fresh identity, foreground PTY ownership, fixed terminal dimensions, and exact
  relay/tmux identity are all acknowledged by provider-data-free metadata. No method is usable
  earlier.
- `writePrompt` and `snapshot` share one FIFO per-session queue. Arguments are synchronously
  validated and copied before admission. Only one operation crosses the helper sideband/broker
  at a time.
- `execution.cancel()` sets `REVOKING` before sending termination. Utility exit, bootstrap
  failure, helper/reaper/supervisor loss, transcript/control loss, PTY/relay/tmux loss, and
  identity or terminal failure do the same. New and queued operations reject; an in-flight
  operation follows the race table below.
- Capability revocation, closure of all component-owned retained descriptors, and terminal
  `RETIRED`/`PRESERVED` disposition of every sealed cleanup target occur before the ordinary
  completion resolves or rejects. Completion does not wait for an empty namespace: absent
  external removal, the relay socket pathname and runtime directory remain `PRESERVED`.
  Public settlement remains exactly once; repeated cancel returns the same completion promise.
  `SETTLED` retains only the provider-free revoked tombstone plus the terminal provider-free
  cleanup ledger needed to reject stale capabilities and prove the selected outcomes.
- A capability from another factory/session has no target parameter with which to redirect an
  operation. A stale, forged, proxy-wrapped, prototype-replaced, copied-method, or cross-session
  attempt cannot select or reach a channel or descriptor.

### CORE data boundary

Prompt and terminal bytes are bounded but provider-bearing, so they travel only on the private
binary sideband, PTY, relay socket, and the authorized method result. They never enter:

- the one-MiB JSON lifecycle command frames
  (`gateway/src/adapters/process_supervisor.js:365-375`);
- the 16,384-character JSON transcript parser
  (`gateway/src/adapters/process_supervisor.js:662-729`);
- readiness/terminal identity records, binding/lease digests, completion values, public errors,
  audit events, log output, or attach metadata.

Binary-sideband errors map only to the fixed table above. The implementation must discard
provider-bearing buffers when each operation settles and before public completion. The future
splice may audit operation type/outcome and byte counts, but must not copy raw prompts or
snapshots into audit.

## Normative terminal and snapshot contract

| Property | Frozen rule |
|---|---|
| Terminal model | Provider uses a real POSIX PTY; presentation is tmux's `tmux-256color`/UTF-8 terminal renderer. No raw-output-history interpretation substitutes for current screen state. |
| Dimensions | Exactly 120 columns × 40 rows on both inner PTY and outer tmux pane. |
| Scrollback | Exactly 400 physical tmux history lines plus the 40-row visible pane, matching today's `capture-pane -S -400` intent. |
| Capture argv | After the configured tmux executable, the direct argument vector is exactly `["capture-pane","-p","-N","-T","-t",tmuxTarget,"-S","-400"]`; never `-e` and never a shell. Tmux 3.6 `-N` preserves rendered trailing space characters, while `-T` excludes trailing cell positions that do not contain a character, so unused pane padding remains distinguishable. Wrapped physical lines remain separate (no `-J`). |
| Metadata argv | While relay output is paused at the barrier, direct argv equivalent of `tmux display-message -p -t <target> "#{history_size}\t#{pane_height}\t#{cursor_y}"`; exact ASCII decimal/tab parsing only. |
| Encoding | Broker uses one streaming UTF-8 decoder with deterministic replacement. Each maximal invalid input sequence becomes one U+FFFD before rendering; split valid multibyte sequences are reassembled. Snapshot output is valid UTF-8 with LF separators. |
| ANSI/control | Tmux interprets xterm/tmux terminal controls. Capture omits escape sequences (`-e` absent), so only their rendered cell effects appear. OSC/DCS payloads and raw ANSI bytes are never returned. |
| Snapshot cap | At most 65,536 UTF-8 bytes, after rendering and encoding normalization. |
| Truncation | If over cap, discard the oldest prefix, prepend the exact 43-byte marker `"[... older terminal content truncated ...]\n"`, and retain the longest newest suffix that keeps marker + suffix ≤65,536 bytes. Start the suffix on a Unicode scalar boundary. |
| Resize | No port resize method. Tmux uses manual window size with aggressive resize disabled. An operator client is letterboxed; any observed inner/outer size drift is `SESSION_PORT_TERMINAL_CHANGED`, revokes, and cancels. |
| Concurrency point | Snapshot takes the next FIFO sequence, waits for all earlier accepted port writes, drains terminal bytes already readable, sends a relay flush barrier, and pauses broker-to-relay forwarding until metadata plus capture finish. Provider/operator bytes arriving after that barrier belong to a later snapshot. |
| Failure | A failed barrier/capture/decode returns no partial snapshot. Terminal disappearance uses `SESSION_PORT_TERMINAL_CLOSED`; other capture failure uses `SESSION_PORT_SNAPSHOT_FAILED`; both revoke and cancel. |

### Normative byte-for-byte capture canonicalization

The input is exactly stdout from the fixed capture argv after a zero exit, taken while
broker-to-relay forwarding remains paused. Stderr must be empty. The algorithm is:

1. Parse the paired metadata stdout as exactly three base-10 ASCII integers separated by two
   tab bytes and followed by one LF: `history_size`, `pane_height`, `cursor_y`. Reject signs,
   leading/trailing whitespace, extra fields, overflow, `pane_height != 40`, or
   `cursor_y < 0 || cursor_y >= 40` as `SESSION_PORT_SNAPSHOT_FAILED` (dimension drift already
   observed as 120×40 mismatch is `SESSION_PORT_TERMINAL_CHANGED`).
2. Let `h = min(history_size, 400)`. Require capture stdout to end in one LF and split it at
   every LF into exactly `h + 40` physical row byte strings, excluding the delimiter from each
   row. A missing final LF, invalid UTF-8, extra/fewer rows, NUL, or bytes after the expected
   final LF is `SESSION_PORT_SNAPSHOT_FAILED`; return no partial snapshot.
3. The first `h` rows are captured history. Retain **all** of them in order, including empty
   history rows. The final 40 rows are the visible pane.
4. For the 40 visible rows, let `emitted_extent` be zero if every row has zero bytes; otherwise
   it is one plus the greatest zero-based row index whose emitted byte string is nonempty. Let
   `used_visible = max(cursor_y, emitted_extent)`. Retain exactly visible rows
   `[0, used_visible)`. Thus completed empty rows above the cursor and any nonempty row below a
   moved cursor remain meaningful; only empty rows below both evidence bounds are proven unused
   pane padding.
5. Concatenate every retained history row and retained visible row in order, appending exactly
   one LF byte after **each** retained row. If no row is retained, return the zero-byte string.
   Do not `trim`, `trimEnd`, `rstrip`, normalize whitespace, collapse blank rows, join wrapped
   rows, or remove the last LF.
6. Preserve every byte tmux emitted inside a row, including any trailing U+0020 or tab bytes.
   The fixed command requires both `-N` and `-T`: `-N` keeps rendered trailing space
   characters, and `-T` omits trailing cell positions that contain no character. The
   canonicalizer neither reconstructs cell padding tmux did not emit nor removes row-end bytes
   that tmux did emit.
7. Decode/validate the retained bytes as UTF-8, then apply the 65,536-byte cap and exact
   oldest-prefix marker rule. Truncation is the only later byte removal.

This rule discards no emitted byte from a retained row and no blank history/completed row. Its
only pre-cap discard is a suffix of zero-byte visible rows proven unused by both the cursor and
last-emitted-row evidence.

Exact snapshot oracles:

| Case | Raw derivation and expected result |
|---|---|
| Untouched pane | Under the exact `-p -N -T -t <target> -S -400` flags, metadata is `0\t40\t0\n` and capture is exactly 40 LF bytes; `h=0`, `emitted_extent=0`, `used_visible=0`; `snapshot === ""`, `snapshotBytes === 0`, `truncated === false` |
| Positive three-row pane | Under the exact flags, metadata is `0\t40\t3\n`; capture is 61 bytes: exact bytes `ready\nstatus\nack:status\n` plus 37 LF bytes. Retain the first three rows and their LFs, yielding exactly 24 bytes `ready\nstatus\nack:status\n` |
| One intentional completed blank row | visible content equivalent to `A\n\n` with `cursor_y=2`; retain two rows and yield exactly `A\n\n`, not `A\n` |
| Content below a moved cursor | any nonempty emitted row below `cursor_y` raises `emitted_extent`; retain through that row and its LF |
| Real tmux row-end spaces | render exact rows `edge  ` and `next` with `cursor_y=2`; the exact flags produce 50 capture bytes: `edge  \nnext\n` plus 38 LF bytes. Retain two rows and yield exactly 12 bytes `edge  \nnext\n`; the two row-end U+0020 bytes are content, while all unused trailing cell positions and rows remain empty |
| Other emitted row-end spaces/tabs | preserve those bytes exactly; no per-row trimming |
| Exactly 65,536 ASCII bytes | byte-for-byte same string, `snapshotBytes === 65536`, `truncated === false` |
| 65,537 ASCII bytes | exact marker plus newest 65,493 input bytes, `snapshotBytes === 65536`, `truncated === true` |
| Bytes `41 ff 42` | rendered `A\uFFFDB`, `snapshotBytes === 5`, `truncated === false` |
| `A\u001b[31mB\u001b[0mC` | rendered `ABC`, no U+001B in the result |
| Inner or outer resize to 121×40 (or 120×41) | reject `SESSION_PORT_TERMINAL_CHANGED`; no capture payload; revoke/cancel |

Named tests are
`canonicalizes an untouched 120x40 pane to zero bytes`,
`preserves the exact 24-byte rendered snapshot and one final LF`,
`preserves completed blank rows above the cursor`,
`preserves blank history and nonempty content below the cursor`,
`preserves emitted row-end spaces and tabs byte for byte`, and
`rejects capture metadata or physical-row-count drift instead of guessing`.

The separate host test
`preserves two rendered row-end spaces through real tmux capture-pane -N -T`
must start an isolated-socket tmux 3.6 pane, render the exact `edge  \nnext\n` case, invoke the
frozen direct argument vector, and assert the 50-byte capture and 12-byte canonical result
above. Supplying synthetic capture bytes does not satisfy this test. The untouched and

## Normative prompt framing

| Property | Frozen rule |
|---|---|
| Argument | Non-empty JavaScript string containing only paired Unicode scalar values; U+0000 and U+000D are rejected. LF is preserved as prompt content. |
| Prompt maximum | 65,536 bytes after strict UTF-8 encoding; the boundary is accepted and one byte over is rejected before queue/channel access. |
| Terminal frame | Exact UTF-8 prompt bytes followed by one carriage return byte `0d`; no interpolation, shell quoting, key-name parsing, or retry at the API level. |
| Binary request maximum | 65,585 bytes: 48-byte sideband header + 65,536 prompt bytes + one CR. Snapshot request has zero payload. |
| Binary snapshot maximum | 65,584 bytes: 48-byte header + at most 65,536 snapshot bytes. |
| Result | Success only after every terminal-frame byte is accepted and the operation sequence commits; result reports prompt bytes only. |

The 65,536-byte prompt produces `{sequence: n, acceptedBytes: 65536}`. A 65,537-byte prompt
rejects `SESSION_PORT_PROMPT_TOO_LARGE` with zero sideband/PTY writes and leaves the active port
usable. A lone surrogate, U+0000, U+000D, empty prompt, accessor, proxy, or extra field rejects
`SESSION_PORT_INVALID_ARGUMENT` with zero channel access.

## Verified write state machine

### Authoritative identity readers

| Platform | PID/start/PGID/SID | Executable/argv/cwd | Foreground/terminal |
|---|---|---|---|
| Linux | `/proc/<pid>/stat`: parsed PID, pgrp field 5, session field 6, starttime field 22, extending the existing reader at `gateway/src/adapters/process_supervisor.js:183-217` | `readlink(/proc/<pid>/exe)`, NUL-delimited bytes from `/proc/<pid>/cmdline`, and `readlink(/proc/<pid>/cwd)` | `tcgetpgrp(retainedSlaveFd)` plus `fstat`/`TIOCGWINSZ` on the retained PTY slave |
| Darwin | `libproc` `proc_pidinfo(PROC_PIDTBSDINFO)` PID/start timeval/PGID plus `getsid(pid)`, extending the existing helper reader at `gateway/src/adapters/process_supervisor_helper.py:103-159` | `proc_pidpath`, `sysctl(CTL_KERN,KERN_PROCARGS2,pid)`, and `proc_pidinfo(PROC_PIDVNODEPATHINFO)` | `tcgetpgrp(retainedSlaveFd)` plus `fstat`/`TIOCGWINSZ` on the retained PTY slave |

When the component is otherwise proven live and none of the loss classes below is true,
unreadable, partial, malformed, permission-denied, or undecodable process/launch/helper
identity data fails closed as `SESSION_PORT_IDENTITY_CHANGED`; the corresponding
PTY/pane/relay identity or dimension data fails as `SESSION_PORT_TERMINAL_CHANGED`. There is no
fallback to PID alone. An identity read made impossible by proven helper/control loss or
terminal-component disappearance is classified as that loss, not as an identity mismatch.
Expected filesystem paths are realpath-normalized at launch, and argv is compared as the exact
NUL-delimited byte vector. The required foreground equation is:

```text
fresh.pid/startToken/pgid/sid == issued utility identity
fresh executable/argv/cwd/session digest == launch bindingDigest
fresh.pgid == fresh.pid
fresh.sid == fresh.pid
tcgetpgrp(retainedSlaveFd) == fresh.pgid
fresh terminal/helper/tmux facets == issued binding
```

### Per-write algorithm

1. Validate/copy the argument and encode the complete prompt frame before FIFO admission.
2. At the FIFO head, fail if state is not `ACTIVE`; reserve the sequence.
3. Under the broker's single mutation lock, re-read and compare every bound identity and the
   foreground equation.
4. Call `os.write(ptyMaster, remainingFrame)` only after that comparison. `EINTR` and
   `EAGAIN` wait/retry only after another full identity/foreground/cancel check.
5. A positive short write records the accepted prefix, re-verifies all bindings, and writes the
   remainder. No second public prompt operation is created.
6. After the final byte, encode `WRITE_OK`; success is not public yet. Commit the public result
   only when the parent validates the complete authenticated response under the port settlement
   lock. Otherwise use the exact interval below, revoke, and enter existing cleanup.

### Mutually exclusive linearization intervals

The parent has one port settlement lock. Raw detector callbacks do not receive cause ordinals.
They first enter the disjoint physical-event classifier below. Only its normalized cause (or a
validated sideband response) takes the lock and receives one monotonic ordinal. The lowest
ordinal is the sole winning cause; later callbacks and teardown effects cannot replace its
outcome.

Write cancellation has two and only two commit points:

1. Before `D`, the parent can prove that it dispatched no request bytes. It commits cancel
   locally under the settlement lock, assigns the cancel ordinal, and returns
   `SESSION_PORT_CANCELLED`.
2. At or after `D`, recording or sending a cancel request is only pending intent: it takes no
   ordinal and has no public result. The helper checks that intent under its mutation lock. It
   may emit authenticated `ERROR(0x0005,0x06)` only if no positive PTY write `F` occurred. The
   parent commits cancel only when it validates that complete response; that validation is the
   authenticated zero-terminal-byte proof and the cancel ordinal point. If the
   helper/control/response path is lost first, the loss receives the ordinal and the write is
   `SESSION_PORT_WRITE_ABORTED`. After `F`, the helper cannot emit `CANCELLED`; an abort response
   is `ERROR(0x000b,0x04)`.

If `WRITE_OK` was fixed and validated before the helper processes pending cancel, success wins
at `R`. Snapshot cancel is different because no prompt bytes can escape: it still commits
locally whenever it wins the parent lock in `[A,R)`, discards any capture, and needs no helper
zero-byte proof.

Use these points:

```text
A = FIFO admission/sequence allocation
D = parent finishes dispatching the complete authenticated request frame
F = helper's first positive PTY os.write return
L = helper's positive write of the final terminal-frame byte
B = snapshot relay barrier acknowledges and forwarding is paused
R = parent validates the complete authenticated response and commits public result
```

Intervals are half-open: `[A,D)`, `[D,F)`, `[F,L)`, `[L,R)`, and `[R,∞)`. `F` or `L` does
not commit public success; only `R` does. For snapshot, `B` divides work but not settlement:
`[A,B)`, `[B,R)`, and `[R,∞)`.

### Disjoint physical-event classification

For one in-flight operation and bound component generation, the first raw detector callback
enters the settlement lock and evaluates the following ranks in order. The first true predicate
is stored with the operation sequence and receives the sole ordinal. Before closing dependent
descriptors, the helper/broker must record under its mutation lock whether teardown originated
from its own generation or from a utility/PTY/relay/tmux generation; that origin accompanies the
authenticated error response when the helper remains live. Its lower-rank symptoms and later
teardown callbacks are aliases of that incident and receive no ordinal. If that response path
is independently lost before validation, the parent has no origin proof and uses the
unattributed transport-loss row.

| Rank and exclusive predicate | Normalized cause | Exact operation result before `R` |
|---|---|---|
| 1. The exact bound helper/reaper/supervisor generation is proven dead. | Helper-origin loss. Its induced control EOF, unreadable helper identity, utility/PTY teardown, and relay close are aliases. | Write after `D`: `SESSION_PORT_WRITE_ABORTED`, whether the unknowable PTY count is zero, partial, or full. Snapshot: `SESSION_PORT_SNAPSHOT_FAILED`. |
| 2. Rank 1 is false, and the still-live broker records utility exit, PTY EOF/HUP, authenticated relay-socket close, or tmux pane/session absence before it fails the barrier or retires sideband descriptors. | Terminal-component-origin close. Its induced barrier/capture, identity-read, and later control/sideband failures are aliases. | Write `[D,F)`: `SESSION_PORT_TERMINAL_CLOSED`; write `[F,R)`: `SESSION_PORT_WRITE_ABORTED`; snapshot `[A,R)`: `SESSION_PORT_TERMINAL_CLOSED`. |
| 3. No rank-1/2 origin was validated before fd 4, fd 5, or the lifecycle control channel reports EOF, HUP, ERR, `EPIPE`, or `ECONNRESET`. The authenticated relay socket is not a control channel. | Unattributed helper/control/response loss. | Write after `D`: `SESSION_PORT_WRITE_ABORTED`, whether the PTY count is zero, partial, or full. Snapshot: `SESSION_PORT_SNAPSHOT_FAILED`. |
| 4. Ranks 1–3 are false, the relevant component is proven live, every authoritative identity field is readable, and at least one complete value differs. | Readable mismatch: process/launch/helper, PTY/pane/relay/dimension, or foreground. | Before `F`, respectively `SESSION_PORT_IDENTITY_CHANGED`, `SESSION_PORT_TERMINAL_CHANGED`, or `SESSION_PORT_NOT_FOREGROUND`; after `F`, `SESSION_PORT_WRITE_ABORTED`. Snapshot uses the corresponding identity/terminal code. |
| 5. Ranks 1–4 are false, retained liveness handles prove the component is live, but an authoritative identity read is partial, malformed, permission-denied, or undecodable. | Live-but-unreadable identity; never a close/loss alias. | Process/launch/helper: `SESSION_PORT_IDENTITY_CHANGED`; PTY/pane/relay/dimension: `SESSION_PORT_TERMINAL_CHANGED`; after `F`, a write is `SESSION_PORT_WRITE_ABORTED`. |
| 6. Ranks 1–5 are false and a snapshot barrier, capture, canonicalization, decode, or response validation fails. | Generic snapshot failure; it cannot absorb a relay disappearance or helper/control loss. | `SESSION_PORT_SNAPSHOT_FAILED`; no partial payload. |

Thus helper death before `F` is rank 1, not unreadable helper identity; relay disappearance
during a snapshot is rank 2 and is recorded before the broker fails the barrier, so it is not
terminal-identity drift, generic barrier failure, or the broker's later sideband teardown. A
complete readable mismatch is reachable only while all three loss ranks are false.

|---|---|---|

| Rank-2 known PTY/relay/tmux close or utility exit | write `[D,F)`; helper proves zero terminal bytes | `SESSION_PORT_TERMINAL_CLOSED`; revoke/cancel |
| Parent validates authenticated `ERROR(0x0005,0x06)` generated before `F` | write after `D`; this response is the cancel linearization point and proves zero terminal bytes | `SESSION_PORT_CANCELLED`; revoke; no retry |
| Explicit cancel, identity/foreground/terminal change, or known close after a positive write | write `[F,R)`; stop all further writes | `SESSION_PORT_WRITE_ABORTED`; revoke/cancel; never report accepted |
| Rank-1 helper-origin or rank-3 unattributed control/response loss after full request dispatch but before a valid response | write `[D,R)`; actual PTY count may be zero, partial (`F..L`), or full (`L..R`) and is not safely recoverable; an earlier pending cancel request has no ordinal | `SESSION_PORT_WRITE_ABORTED`; revoke/cancel; this row expressly covers zero, partial, and full terminal write before response |
| Valid `WRITE_OK` wins the settlement lock | write at `R`; helper count equals request prompt bytes | exact `{sequence,acceptedBytes}` succeeds; a later cancel/loss revokes only later operations |
| Explicit cancel wins the settlement lock | snapshot `[A,R)`, whether before or after `B`; captured bytes are discarded | `SESSION_PORT_CANCELLED`; no snapshot result; revoke |
| Process/launch/helper identity classification wins with ranks 1–3 false | snapshot `[A,R)` | `SESSION_PORT_IDENTITY_CHANGED`; no payload; revoke/cancel |
| PTY/pane/relay identity or dimension classification wins with ranks 1–3 false | snapshot `[A,R)` | `SESSION_PORT_TERMINAL_CHANGED`; no payload; revoke/cancel |
| Rank-2 known PTY/relay/tmux close or utility exit wins | snapshot `[A,R)` | `SESSION_PORT_TERMINAL_CLOSED`; no payload; revoke/cancel |
| Rank-1 helper-origin or rank-3 unattributed control/response loss wins | snapshot `[A,R)` | `SESSION_PORT_SNAPSHOT_FAILED`; no payload; revoke/cancel |
| Rank-6 barrier, capture, canonicalization, decode, or malformed-response failure wins | snapshot `[A,R)` | `SESSION_PORT_SNAPSHOT_FAILED`; no payload; revoke/cancel |
| Valid `SNAPSHOT_OK`/`SNAPSHOT_TRUNCATED` wins the settlement lock | snapshot at `R` | exact snapshot result succeeds; later cancel/loss revokes only later operations |
| Concurrent writes/snapshots | FIFO admission only; one request in `[D,R)` | monotonically sequenced results; no interleaved prompt frames or captures |

The contract promises zero bytes for every pre-write identity/foreground rejection. POSIX PTY
writes cannot roll back an already accepted prefix; therefore a post-short-write race is
explicitly an aborted operation followed by forced teardown, never a false “no partial write”
or an automatic prompt retry. Loss after `D` is conservatively aborted because a full or partial
terminal write cannot be disproved without the authenticated response. A barrier or completed
capture similarly never outranks a cancel that wins before snapshot `R`.
