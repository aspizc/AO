## Problem

Project-level MCP discovery, inherited environment/configuration, or an
overlapping runtime can let an untrusted child start another fully privileged
Gateway and reopen the parent's control state.

## Scope

- Build child environments and mounts from an allowlist that excludes project
  MCP auto-discovery, operator settings/keys/socket, control credentials, and
  parent state/audit/artifact paths for every supported adapter.
- Require the control runtime to be outside canonical repository/task roots and
  bind each Gateway boot, workspace lock, and internal endpoint to a
  server-owned instance/audience.
- Make recursive or second-writer Gateway startup fail before opening control
  stores, including attempts from child worktrees and installed workers.
- Inventory parent/child process lineage and prove one effective control
  Gateway across `confined`, `workspace-yolo`, and explicitly consented
  `host-unconfined` launches.

## Non-scope

- No claim that a same-UID `host-unconfined` child cannot inspect other host
  files, no deletion of operator-local configuration, and no prompt-only guard.

## TDD RED

Launch each adapter from a child worktree with MCP/settings/env canaries; try
recursive boot against the parent and symlinked runtime; race two boots; and
attempt to discover control tools, sockets, keys, or stores.

## TDD GREEN

Centralize the child env/config/mount builder, add boot lineage/audience guards,
and enforce the ownership lock before any registry or store is opened.

## Acceptance criteria

- [ ] No child inherits or auto-discovers the parent's MCP control plane.
- [ ] A recursive/second Gateway cannot open the parent's workspace or stores.
- [ ] Runtime/repository overlap blocks real execution with an actionable error.
- [ ] Process inventory demonstrates one writer and no privileged child Gateway.
- [ ] `host-unconfined` risk is explicit and never represented as isolation.

## Verification

Run config/env/mount canaries, recursive-boot and concurrent-lock E2E for every
adapter/mode, process cleanup checks, `bash scripts/ci.sh`, and
`git diff --check`.
