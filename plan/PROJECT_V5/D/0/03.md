## Problem

Multiple writers and crashes between lifecycle/process operations can leave
duplicate sessions, orphaned state, or incorrect terminal outcomes.

## Scope

- Enforce one long-lived Gateway writer per control store/runtime root.
- Reconcile `starting`, `running`, `cancelling`, exited children, and cleanup
  idempotently on boot and explicit recovery.
- Persist bounded before/after metadata without raw child content.

## Non-scope

- No direct CLI/worker database writes, automatic deletion of diagnostic
  worktrees, or unbounded PID reuse assumptions.

## TDD RED

Start two writers; crash at every reserve/spawn/persist/cancel/exit boundary;
simulate stale PID/lock; and reboot twice to expose duplication or divergence.

## TDD GREEN

Add an auto-releasing ownership lock, process identity evidence, and a
versioned reconciliation service over the lifecycle reducer.

## Acceptance criteria

- [ ] A second writer fails safely before state mutation.
- [ ] Restart converges without duplicate launch/terminal transition.
- [ ] Stale locks recover only after verified owner death.
- [ ] Reconciliation outcomes appear in overview/blockers.

## Verification

Run single-writer, fault-injection, reboot-idempotency, lifecycle, and
concurrency tests; then `bash scripts/ci.sh` and `git diff --check`.
