## Problem

Even a correct gate is ineffective unless orchestration drives remediation,
reruns stale review, and blocks completion for review-required flows.

## Scope

- Add a supervised review/remediation runner with bounded trials and explicit
  human escalation.
- Integrate the valid gate ID/version into typed completion blockers.
- Prove digest change reruns both reviewers and raw source never crosses
  MCP/workflow/audit.

## Non-scope

- No reviewer-caused merge/push/approval, automatic acceptance after trial
  exhaustion, or legacy free-text verdict fallback.

## TDD RED

Exercise KO/remediation, changed digest between reviews, transport loss,
duplicate runner start, open disposition, exhausted trials, and completion
without/current-vs-stale gate.

## TDD GREEN

Implement the reducer-driven runner, idempotent operation keys, completion
integration, and isolated dual-review E2E fixtures.

## Acceptance criteria

- [ ] Review-required completion demands the exact current successful gate.
- [ ] Changed code/evidence reruns A and B before a new gate.
- [ ] KO remains blocked and escalates after the configured trial limit.
- [ ] No raw review input/output leaks through public/control surfaces.

## Verification

Run review-runner fault/retry/completion tests and dual-review external E2E in
both model orders; then `bash scripts/ci.sh` and `git diff --check`.
