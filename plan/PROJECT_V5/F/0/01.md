## Problem

Review and approval cannot bind to “the change” without a canonical manifest of
base/head/diff/spec/tests; caller summaries can become stale or omit evidence.

## Scope

- Derive an immutable change manifest from the bound repository/worktree,
  approved requirements, and authoritative test evidence.
- Canonicalize and digest base/head, changed-path/diff identity, spec inputs,
  test commands/results, and relevant artifact lineage.
- Expose only safe summaries while reviewers resolve source through isolated
  read-only mounts.

## Non-scope

- No caller-authored “tests passed”, raw diff in public MCP/history, or manifest
  reuse after head/spec/test evidence changes.

## TDD RED

Cover dirty/stale head, changed base/spec/test evidence, omitted paths, symlink
repo mismatch, caller digest override, nondeterministic ordering, and raw leak.

## TDD GREEN

Implement canonical manifest collection/serialization/digest and artifact
creation through the server-owned catalog.

## Acceptance criteria

- [ ] Same repository/evidence yields the same digest.
- [ ] Any relevant change invalidates the digest.
- [ ] Manifest origin and lineage are server-verifiable.
- [ ] Public projections contain no raw diff/source/output.

## Verification

Run manifest canonicalization/change-detection/repository-binding/leak tests
against disposable repos; then `bash scripts/ci.sh` and `git diff --check`.
