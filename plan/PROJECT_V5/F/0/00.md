## Problem

Caller-selected artifact kind, producer, classification, trace, or lineage can
make untrusted content appear authoritative and leak raw restricted data.

## Scope

- Define closed artifact kinds with server-derived producer, trace/task/session,
  classification, lineage, content digest, and lifecycle status.
- Enforce append-only-at-the-Gateway-API records plus deterministic restricted
  projection.
- Require requester identity/policy consistently for list/get and future
  evidence operations.

## Non-scope

- No WORM/cryptographic immutability claim, public raw restricted read, caller
  lineage override, or filesystem path as authority.

## TDD RED

Try unknown kind, fake producer/classification/lineage, cross-trace access,
changed-content reuse, raw projection, unauthorized list/get, and hostile
metadata fields.

## TDD GREEN

Add the artifact catalog, derivation service, content-addressed metadata,
policy-aware projections, and compatible migration.

## Acceptance criteria

- [ ] Kind, producer, classification, trace, and lineage are server-owned.
- [ ] Same identity/different content conflicts; exact retry is idempotent.
- [ ] Restricted public views expose only deterministic safe fields.
- [ ] Artifact list/get apply consistent requester policy and audit decisions.

## Verification

Run artifact catalog/lineage/idempotency/policy/projection tests and migration
round-trip; then `bash scripts/ci.sh` and `git diff --check`.
