## Problem

Audit logs explain failures after the fact, but operators cannot distinguish a
ready Gateway from a dead process, blocked event loop, saturated executor, or
instance still requiring reconciliation. An in-process health handler cannot
detect its own stalled event loop, and the current per-connection stdio server
cannot be treated as the identity of the single privileged Gateway daemon
defined by D/0/05.

This sheet is also the complete disposition of audit finding A-08. It owns the
base health projection, bounded metric pipeline, durable exporter cursor,
recording and alert rules, SLO definitions, and operator dashboard. Later
consumers add allowlisted metric sources; they do not redefine health.

## Normative V1 schema

`agents.gateway.health.v1` is the only canonical Gateway health projection.
The watchdog owns the stored safe snapshot; the trusted local probe owns only
the freshness overlay and final response. Neither an agent nor a caller can
author either input. All objects have `additionalProperties: false`; all
listed fields are required, including fields whose value can be `null`. JSON
numbers are safe integers. Unknown enum members, duplicate array members,
non-finite numbers, and values outside the bounds below invalidate the
watchdog input and fail closed as `HEALTH_OBSERVER_STALE`.

Common scalar types are frozen as follows:

| Type | Exact V1 constraint |
|---|---|
| opaque ID | 1–128 ASCII bytes matching `^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$` |
| UTC display time | 20–32 ASCII bytes, canonical RFC 3339 UTC with `Z` |
| monotonic time or duration | integer `0..9_007_199_254_740_991` milliseconds |
| bounded age | integer `0..86_400_000`; older evidence serializes as `86_400_000` |
| sequence | integer `0..9_007_199_254_740_991` |
| reason code | exactly one code in the reason-precedence table below |

The top-level object has exactly these fields:

| Field | Type and bound | Owner and invariant |
|---|---|---|
| `schemaVersion` | constant `agents.gateway.health.v1` | watchdog |
| `instanceId` | opaque ID | service manager; stable for one configured instance |
| `bootId` | opaque ID | service manager; rotates for every daemon generation |
| `watchdogBootId` | opaque ID | service manager; rotates for every watchdog generation |
| `clockBootId` | opaque ID | kernel boot identity independently read by manager and watchdog |
| `watchdogSnapshotSeq` | sequence | watchdog-owned publication sequence; `0` only for probe-synthesized unavailable state before any valid snapshot |
| `daemonTransitionSeq` | sequence or `null` | daemon-owned safe-projection sequence; `null` before the first accepted frame |
| `observation` | closed observation object | watchdog |
| `overallState` | `healthy`, `degraded`, `blocked`, or `recovery-required` | total reducer below; there is no `unknown` aggregate |
| `live` | closed live object | external evidence reducer |
| `ready` | closed ready object | total reducer |
| `controlReady` | boolean | true only while the authenticated ping path is current |
| `executionAdmission` | `open`, `pressure`, or `closed` | D/0/06 count reducer below |
| `recovery` | closed recovery object | watchdog recovery recorder |
| `primaryReason` | reason code or `null` | lowest-ranked active code; `null` iff `reasonCodes` is empty |
| `reasonCodes` | unique array of `0..28` reason codes | strictly sorted by rank |
| `components` | closed component map | fixed eleven keys below |

The closed `observation` object has exactly:

| Field | Type | Rule |
|---|---|---|
| `state` | `current`, `stale`, or `unavailable` | `current` only after all watchdog validations pass |
| `observedAt` | UTC display time | probe evaluation wall time; display only |
| `evaluatedMonotonicMs` | monotonic time | probe `CLOCK_BOOTTIME` evaluation time |
| `watchdogPublishedMonotonicMs` | monotonic time or `null` | last valid watchdog publication; null only when unavailable before a valid snapshot |
| `daemonSampleReceivedMonotonicMs` | monotonic time or `null` | watchdog receipt time of the last accepted daemon projection |
| `heartbeatReceivedMonotonicMs` | monotonic time or `null` | watchdog receipt time of the last accepted main-loop heartbeat |
| `snapshotAgeMs` | bounded age or `null` | probe-computed publication age; null iff watchdog publication is null |

`current` means a valid publication whose computed age is at most the
freshness threshold. `stale` means the last publication remains structurally
valid and boot-matched but is older than the threshold. `unavailable` means
there is no valid boot-matched publication. A stale response retains its last
positive `watchdogSnapshotSeq`; an unavailable response uses zero.

The closed `live` and `ready` objects have exactly:

| Object | Fields and invariants |
|---|---|
| `live` | `state` is `live`, `dead`, `stalled`, or `unknown`; `value` is respectively `true`, `false`, `false`, or `null`; `since` is UTC time or `null`; `sinceMonotonicMs` is monotonic time or `null`. The two `since` fields are both null only for `unknown`. |
| `ready` | `value` is boolean; `since` is UTC time; `sinceMonotonicMs` is monotonic time. Both `since` values identify the latest transition into the current boolean value. |

`watchdogSnapshotSeq` starts at `1`, increments by exactly one on every
scheduled atomic watchdog publication even when the daemon projection is
unchanged, and resets only when `watchdogBootId` changes. A probe may therefore
observe a gap but rejects a decrease or the same sequence with different
stored bytes. `daemonTransitionSeq` starts at `0`, increments by exactly one
only for each semantic daemon safe-projection transition, and resets only when
`bootId` changes; repeated identical daemon samples preserve it and all
`since` fields. The watchdog rejects a daemon-sequence gap, decrease,
duplicate with different bytes, or wrong boot ID. Neither sequence is compared
across its owning boot identifier.

### Closed component map

`components` contains all and only these keys:

`eventLoop`, `controlLoop`, `writer`, `stateStore`, `auditWriter`,
`reconciliation`, `supervisor`, `admissionBudget`, `operatorTransport`,
`coordinationRedis`, and `observabilityExporter`.

Every value is the same closed object:

| Field | Type and invariant |
|---|---|
| `criticality` | `required` or `optional`; server profile owned |
| `state` | `ok`, `warning`, `pending`, `failed`, `stale`, or `disabled` |
| `observedMonotonicMs` | monotonic time or `null`; null iff no sample exists |
| `ageMs` | bounded age or `null`; null iff no sample exists |
| `reasonCode` | reason code or `null`; null iff `impact=none` |
| `impact` | `none`, `degraded`, `blocked`, or `recovery-required` |

`eventLoop`, `controlLoop`, `writer`, `stateStore`, `auditWriter`,
`reconciliation`, `supervisor`, `admissionBudget`, and `operatorTransport`
are always required. `coordinationRedis` and `observabilityExporter` are
always optional to base Gateway readiness. `disabled` is valid only for an
optional component and has `impact=none`. Required `pending`, `failed`, or
`stale` inputs cannot be healthy. An optional failure is degraded unless its
specific reason is integrity-related.

| Component | Authoritative bounded input | Exact readiness rule |
|---|---|---|
| Event loop | non-overlapping `monitorEventLoopDelay` windows plus external heartbeat receipt | warning degrades; expired external heartbeat blocks |
| Control loop | watchdog nonce/ACK receipt latency | timeout blocks; high current latency degrades |
| Writer | D/0/03 ownership generation and manager-attested process identity | current matching ownership is required |
| State store | bounded backend probe, supported schema range, integrity result, and write capability | unavailable/read-only blocks; integrity or schema ambiguity is recovery-required |
| Audit writer | bounded local-writer probe | unavailable blocks new effects, never the health probe itself |
| Reconciliation | D/0/03 lifecycle/process reconciliation state | pending blocks; failed or ambiguous is recovery-required |
| Supervisor | D/0/01 cached supervisor state | initialized and responsive is required |
| Admission/budget | one atomic D/0/06 count snapshot | pressure degrades; saturation blocks new execution |
| Operator transport | E/0/00 local server state | bound authenticated transport is required |
| Coordination Redis | existing `coordination.status` projection | optional; absence degrades only when configured |
| Observability exporter | cursor, spool, and last successful backend acknowledgement | optional; stale, failed, or gapped export degrades and alerts |

Component probes update a cache and never run inline in an operator health
request. Current evidence older than `dependencyEvidenceFreshnessMs` becomes
`DEPENDENCY_EVIDENCE_STALE`. `ageMs` is
`min(nowMonotonicMs - observedMonotonicMs, 86_400_000)` after proving the same
`clockBootId`; a negative difference or different clock boot invalidates the
observation rather than being clamped.

### Closed recovery object

The `recovery` object always has exactly these fields:

| Field | Type |
|---|---|
| `state` | `none`, `open`, `recovering`, `stabilizing`, or `closed` |
| `recoveryEpisodeId` | opaque ID or `null` |
| `initialReason` | reason code or `null` |
| `clockQuality` | `same-boot-comparable`, `host-reboot-incomparable`, or `null` |
| `episodeClockBootId` | opaque ID or `null` |
| `failureBoundaryMonotonicMs` | monotonic time or `null` |
| `detectedMonotonicMs` | monotonic time or `null` |
| `recoveryStartedMonotonicMs` | monotonic time or `null` |
| `firstGoodMonotonicMs` | monotonic time or `null` |
| `readyConfirmedMonotonicMs` | monotonic time or `null` |
| `detectedAt` | UTC display time or `null` |
| `readyConfirmedAt` | UTC display time or `null` |
| `goodSamples` | integer `0..10` |
| `requiredGoodSamples` | integer `1..10` |
| `timeToDetectMs` | monotonic duration or `null` |
| `timeToRecoverMs` | monotonic duration or `null` |
| `outageDurationMs` | monotonic duration or `null` |

For `none`, every nullable field is null and `goodSamples=0`. For a
`same-boot-comparable` open episode, the episode ID, initial reason, episode
clock, failure boundary, detection time, and display detection time are
present; recovery start may be null. `recovering` additionally requires a
recovery-start time. `stabilizing` requires a first-good time and
`1..requiredGoodSamples-1` good samples. `closed` requires
`goodSamples=requiredGoodSamples`, first-good and ready-confirmed times, and
display ready time. When the configured good-sample count is one, the first
good observation closes directly without emitting `stabilizing`.

For a `host-reboot-incomparable` episode, `episodeClockBootId`, every
monotonic landmark, and every duration are null; only the episode ID, initial
reason, display detection/ready times, state, and good-sample counts remain.
This prevents a consumer from combining landmarks from different monotonic
epochs. A failed sample before closure resets `goodSamples` and, for a
same-boot episode, `firstGoodMonotonicMs`, but retains the episode ID and
initial reason. A reason change or daemon/watchdog restart does not create a
second episode. The last closed episode remains in the projection until the
next episode opens; the journal remains the historical source.

For a same-boot closed episode all three duration fields are present and obey
the formulas below. Before closure they are null.

## Total reducer and reason predicates

The reducer evaluates one injected `CLOCK_BOOTTIME` sample and applies these
steps in order:

1. The probe validates the watchdog snapshot, boot identifiers, schema,
   publication sequence, and monotonic freshness. If evidence is unavailable
   or stale, it uses only the closed manager bootstrap manifest to synthesize
   a safe response: the active set is exactly `HEALTH_OBSERVER_STALE`,
   liveness is unknown, readiness and control readiness are false, admission
   is closed, required components are stale, optional components are disabled,
   and the aggregate is blocked. Cached daemon reasons and recovery durations
   are not recomputed. A previously journal-attested recovery object may be
   carried byte-for-byte as historical evidence; without one it is `none`.
   If even the manager manifest is invalid, the probe returns exit 3 and no
   JSON projection.
2. Reduce manager-attested process evidence. Exactly one of
   `PROCESS_IDENTITY_MISMATCH`, `PROCESS_STOPPED`, `PROCESS_DEAD`,
   `HEARTBEAT_MISSING`, `EVENT_LOOP_STALLED`, or the zero-heartbeat
   pre-grace form of `BOOTING` can be active. When one is active,
   daemon/component reasons are discarded as stale, liveness is the exact
   table value below, and the aggregate is blocked.
3. With a current matching live process, reduce ping, daemon phase, and all
   component inputs. Determine each active reason and impact from the table;
   no arrival-order or caller-provided severity is accepted.
4. Sort active reasons by rank. If any current reason has
   `recovery-required` impact, aggregate to `recovery-required`; otherwise if
   any has blocked impact, aggregate to `blocked`; otherwise if any has
   degraded impact, aggregate to `degraded`; otherwise aggregate to healthy.
5. `controlReady=true` iff the observation and heartbeat are current, at least
   one valid ping ACK exists for the current boot, and no ping is overdue.
   `ready=true` iff live and control-ready are true, admission is open, every
   required component is `ok`, and no blocked or recovery-required reason is
   active. A degraded optional dependency or warning may remain ready.

### External liveness output table

The following table is exhaustive and is evaluated top to bottom. `since`
uses the watchdog wall sample at the first reduction that changes
`live.state`; `sinceMonotonicMs` uses the stated watchdog
`CLOCK_BOOTTIME` landmark. If a later reason has the same `live.state` and
`value`, both `since` fields are retained. A state/value change replaces both.

| Current external input | Active external reason | `live.state` / `value` | `sinceMonotonicMs` | Live-probe exit |
|---|---|---|---|---:|
| observer stale/unavailable/protocol-invalid, including any otherwise unlisted external-state combination, but manager manifest valid | `HEALTH_OBSERVER_STALE` | `unknown` / `null` | `null` | `3` |
| expected identity alive and matching, zero accepted heartbeat, `now < attestedStartMonotonicMs + initialHeartbeatGraceMs` | `BOOTING` | `unknown` / `null` | `null` | `3` |
| desired running and independently observed identity differs from manager attestation | `PROCESS_IDENTITY_MISMATCH` | `dead` / `false` | first mismatch reduction | `2` |
| desired stopped and no expected process | `PROCESS_STOPPED` | `dead` / `false` | first stopped reduction | `2` |
| desired running, identity matched, pidfd signalled exit | `PROCESS_DEAD` | `dead` / `false` | pidfd signal landmark | `2` |
| expected identity alive/matching, zero accepted heartbeat, `now >= attestedStartMonotonicMs + initialHeartbeatGraceMs` | `HEARTBEAT_MISSING` | `stalled` / `false` | `attestedStartMonotonicMs + initialHeartbeatGraceMs` | `2` |
| expected identity alive/matching, at least one heartbeat, `now > lastHeartbeatReceiptMonotonicMs + heartbeatStaleThresholdMs` | `EVENT_LOOP_STALLED` | `stalled` / `false` | `lastHeartbeatReceiptMonotonicMs + heartbeatStaleThresholdMs` | `2` |
| expected identity alive/matching and heartbeat current | none of ranks 1–6 | `live` / `true` | receipt of the first current heartbeat after the prior non-live state | `0` |

For `unknown`, both `since` fields are null. For every other row they are
non-null. At the exact no-first-heartbeat `>=` boundary the serialized output
is therefore `stalled/false`, never `unknown`. A fresh heartbeat plus
`CONTROL_CALL_TIMEOUT`, or any daemon/component-only reason, retains
`live/true`; it changes control/readiness but live-probe exit remains zero.

Thus a state-store schema incompatibility blocks readiness but its aggregate
is unambiguously `recovery-required`, never `blocked`. `blocked` is a temporary
or liveness condition; `recovery-required` means the live daemon cannot
resolve an integrity ambiguity safely without operator action. External
observer/liveness failure masks, but does not erase, an already-open recovery
episode.

Reason ordering and predicates are a versioned total order:

| Rank | Impact | Stable V1 reason code | Exact activation predicate |
|---:|---|---|---|
| 1 | blocked | `HEALTH_OBSERVER_STALE` | snapshot missing/invalid, watchdog not manager-attested, clock boot differs, or `evaluatedMonotonicMs - watchdogPublishedMonotonicMs > watchdogSnapshotFreshnessMs` |
| 2 | blocked | `PROCESS_IDENTITY_MISMATCH` | desired state is running and the independently observed `daemonIdentity` tuple/digest differs from the manager-attested tuple/digest |
| 3 | blocked | `PROCESS_STOPPED` | manager desired state is stopped and no expected process exists |
| 4 | blocked | `PROCESS_DEAD` | desired state is running, identity matched, and the pidfd signalled exit |
| 5 | blocked | `HEARTBEAT_MISSING` | expected identity is alive, no valid heartbeat was accepted, and `now >= attestedStart + initialHeartbeatGraceMs` |
| 6 | blocked | `EVENT_LOOP_STALLED` | expected identity is alive, a heartbeat was accepted, and `now > lastHeartbeatReceipt + heartbeatStaleThresholdMs` |
| 7 | blocked | `CONTROL_CALL_TIMEOUT` | heartbeat is fresh and either the sole outstanding ping lacks a valid ACK at `pingSent + controlPingTimeoutMs` or the last ACK is older than `controlPingIntervalMs + controlPingTimeoutMs` |
| 8 | recovery-required | `WRITER_OWNERSHIP_LOST` | ownership was held and the current D/0/03 generation/token no longer matches this boot |
| 9 | recovery-required | `STATE_STORE_INTEGRITY_FAILED` | the bounded integrity probe reports corruption or contradictory durable state |
| 10 | recovery-required | `STATE_STORE_SCHEMA_INCOMPATIBLE` | durable schema is outside the executable's closed supported range |
| 11 | recovery-required | `RECONCILIATION_FAILED` | lifecycle reconciliation is terminal `failed` or `ambiguous` |
| 12 | recovery-required | `BUDGET_LEDGER_INCONSISTENT` | atomic D/0/06 counts violate non-negative, ordering, or hard-limit invariants |
| 13 | blocked | `STATE_STORE_UNAVAILABLE` | current bounded probe times out or fails after ranks 9–10 are excluded |
| 14 | blocked | `STATE_STORE_READ_ONLY` | current store is readable but cannot accept required Gateway writes |
| 15 | blocked | `AUDIT_WRITER_UNAVAILABLE` | current bounded append probe fails or times out |
| 16 | blocked | `SUPERVISOR_UNAVAILABLE` | D/0/01 cached supervisor state is absent, failed, or not responsive |
| 17 | blocked | `OPERATOR_TRANSPORT_UNAVAILABLE` | E/0/00 transport is not bound, peer-verified, and accepting local control calls |
| 18 | by criticality | `DEPENDENCY_EVIDENCE_STALE` | `now > observedMonotonicMs + dependencyEvidenceFreshnessMs` for a previously sampled component |
| 19 | blocked | `SHUTTING_DOWN` | daemon phase is drain/cleanup before its planned process stop |
| 20 | blocked | `BOOTING` | desired identity is alive/matching and either no heartbeat has been accepted while `now < attestedStart + initialHeartbeatGraceMs`, or a heartbeat is accepted but boot prerequisites have not all produced a current result |
| 21 | blocked | `WRITER_OWNERSHIP_PENDING` | writer acquisition is pending and ranks 8–10 are absent |
| 22 | blocked | `RECONCILIATION_PENDING` | lifecycle reconciliation is running and rank 11 is absent |
| 23 | blocked | `BUDGET_RECONCILIATION_PENDING` | D/0/06 reservation reconciliation is running and rank 12 is absent |
| 24 | blocked | `ADMISSION_SATURATED` | server-owned `saturationLatched=true`, from first hard-limit sample through the last required clear sample; mutually exclusive with pressure |
| 25 | degraded | `EVENT_LOOP_LAG_HIGH` | the lag hysteresis state is warning while heartbeat remains fresh |
| 26 | degraded | `CONTROL_LATENCY_HIGH` | ping-latency hysteresis is warning and latency remains below the timeout |
| 27 | degraded | `ADMISSION_PRESSURE` | pressure hysteresis is active while `hardLimitReached=false` |
| 28 | by criticality | `DEPENDENCY_UNAVAILABLE` | a current negative dependency sample has no more specific reason; required blocks, optional degrades |

The state-store predicates at ranks 9, 10, 13, and 14 are mutually exclusive
in that order. Writer lost/pending, reconciliation failed/pending,
admission saturated/pressure, and control timeout/high latency are likewise
mutually exclusive. `DEPENDENCY_EVIDENCE_STALE` is evaluated only when a
prior sample exists; an optional component never sampled is `disabled` or
`DEPENDENCY_UNAVAILABLE`, and a required component never sampled is `BOOTING`.

Graceful shutdown sets readiness false before drain begins, continues the
heartbeat during bounded cleanup, and reports `SHUTTING_DOWN`. Only after the
manager records desired state stopped and the process exits does it become the
distinct `PROCESS_STOPPED`.

`monitorEventLoopDelay` is reset at each non-overlapping
`eventLoopWindowMs` boundary. Warning enters after the configured number of
consecutive closed windows whose p99 is at or above the warning threshold and
clears after the same number strictly below the clear threshold. Values in the
middle retain the prior state. A partial window never clears a warning.
Control-latency hysteresis uses the same consecutive-sample rule; timeout is
immediate and does not wait for hysteresis.

D/0/06 supplies one atomic closed aggregate with exactly
`generation`, `reconciliationState`, `limitingScopeClass`,
`limitingDimension`, `limitingUsed`, `limitingHardLimit`,
`maxUtilizationBasisPoints`, `hardLimitReached`, `reservedControlInUse`, and
`reservedControlLimit`. Generation is a sequence; reconciliation is `pending`,
`consistent`, or `inconsistent`; scope class is `global`, `principal`,
`repository`, or `trace`; and dimension is exactly `processes`, `sessions`,
`calls`, `output_bytes`, `artifact_bytes`, `audit_bytes`,
`runtime_disk_bytes`, `provider_requests`, `provider_tokens`, or
`provider_cost_micros`. Counts are safe non-negative integers, hard limits are
at least one, basis points are `0..10_000`, and the reserved control limit is
at least five with in-use not above limit. No concrete principal, repository,
or trace identifier is projected.

D/0/06 computes each dimension ratio with integer/BigInt arithmetic,
`min(10_000, floor(10_000 * used / hardLimit))`, selects the greatest ratio
and the lowest fixed-enum scope class then dimension on a tie, and sets
`hardLimitReached` if any scoped dimension has `used >= hardLimit`. Invalid
counts, an inconsistent reconciliation state, or a claimed aggregate that
does not match its atomic dimension snapshot activates
`BUDGET_LEDGER_INCONSISTENT`; pending activates
`BUDGET_RECONCILIATION_PENDING`.

The reducer owns `saturationLatched` and `saturationClearSamples`.
`hardLimitReached=true` sets the latch immediately and resets the clear count
to zero. While latched, each consecutive current valid false sample increments
the count; the latch remains true for counts below
`admissionHysteresisSamples` and clears before projecting the sample that
reaches the configured count. A true, stale, missing, pending, or invalid
sample resets the clear count to zero, and every such case preserves an
already-set latch. Rank 24 is active iff `saturationLatched=true`, not merely
when the current raw sample is true.

While saturation is latched, `executionAdmission=closed`, the
`admissionBudget` component is `failed` with
`ADMISSION_SATURATED`/`blocked`, pressure counters reset, readiness is false,
and the aggregate is blocked unless a higher recovery-required reason exists.
For the default three-sample clear sequence with utilization zero, samples one
and two therefore remain `closed`/blocked with rank 24; sample three clears
the latch, removes rank 24, projects `open`, and may be healthy/ready when all
other inputs are good.

After saturation clears, its clearing sample is eligible as pressure-entry
sample one and counts only when it meets the pressure threshold. Pressure
enters after `admissionHysteresisSamples` consecutive unsaturated samples
satisfying
`maxUtilizationBasisPoints >= 100 * pressureEnterPercent`; it clears after
that many satisfying
`maxUtilizationBasisPoints <= 100 * pressureExitPercent`. The middle band
retains the prior open/pressure state. A pending aggregate closes admission
with rank 23; invalid/inconsistent closes it with rank 12; otherwise admission
is pressure iff pressure is latched and open iff neither latch is active.
There is no floating-point rounding or reachable closed admission with an
empty blocking/recovery reason set.

With defaults, stall detection is bounded by the 5-second stale deadline plus
one 500-millisecond watchdog observation interval.

### Reserved control lane

The daemon reserves exactly five independent single-worker control-lane
queues. Capacity counts waiting slots and excludes the one in-flight worker.
The ten configuration keys are the settings-table keys above:

| Class | Capacity key / default / min / max | Freshness key / default / min / max | Serialized entry maximum |
|---|---|---|---:|
| `health_status` | `healthStatusQueueCapacity` / 8 / 8 / 64 | `healthStatusQueueFreshnessMs` / 500 / 50 / 500 ms | 4,096 bytes |

Each slot has a fixed 256-byte metadata/accounting allowance. At all maximum
settings, waiting arenas are bounded to 2,179,072 bytes and the five in-flight
slots to 34,048 bytes, for an exact logical control-lane bound of
2,213,120 bytes. Serialization above a class entry maximum is rejected before
enqueue with `CONTROL_LANE_ENTRY_TOO_LARGE`. The five arenas and five workers
are allocated once at boot; there is no implicit growth, borrowing, shared
overflow queue, runtime reload, or fallback to the general admission queue.
Changing a valid key requires a daemon restart.

Queue admission completes within 50 ms. A full class queue returns
`CONTROL_LANE_SATURATED` without waiting and cannot consume another class's
capacity. Each accepted entry stores watchdog-comparable enqueue monotonic
time. If service has not begun before its class freshness deadline, it is
removed and returns `CONTROL_LANE_EXPIRED`; its policy/approval/cancellation/
audit effect is never executed. Cache-only health/status and cancellation
admission queue wait plus service p99 must remain at or below 500 ms under
maximum execution/output load; policy, approval persistence, and audit append
must begin within 500 ms, while human decision time is outside the budget.
The watchdog heartbeat and nonce ACK run on the daemon main loop and use
neither the general queue nor these workers. The TDD load fixture saturates
and expires every class independently and jointly and proves the fixed arena
accounting.

## Manager-attested watchdog bootstrap

The bootstrap protocol is `agents.gateway.health-bootstrap.v1`, with fixed
audience `agents-gateway-health`. The trusted service manager is the issuer;
neither the daemon nor the watchdog may assert its own expected identity.

For every daemon generation the manager:

1. obtains two independent 32-byte Ed25519 signing seeds and two 128-bit
   one-use challenges from the OS CSPRNG, then assigns `instanceId`, new
   `bootId`, current kernel `clockBootId`, and a strictly increasing manager
   generation;
2. creates separate manager-to-daemon and manager-to-watchdog
   `SOCK_SEQPACKET` bootstrap channels plus the daemon/watchdog health
   socketpair; every process receives only its intended endpoints;
3. sends each process a different sealed anonymous role bundle with
   `SCM_RIGHTS`: its outbound private signing seed, the peer's public
   verification key, its challenge, the fixed audience, and all boot IDs;
4. spawns the daemon, obtains its pidfd, kernel process-start token, and
   executable-device/inode digest independently, then passes the pidfd with
   `SCM_RIGHTS` and a closed manager attestation to the watchdog; and
5. waits for both signed challenge acknowledgements and the watchdog identity
   acknowledgement before the daemon may leave `BOOTING`.

The closed attestation contains only schema, audience, instance ID, daemon
boot ID, watchdog boot ID, clock boot ID, manager generation, attested start
monotonic time, peer verification keys, the closed `daemonIdentity` tuple, and
`daemonIdentityDigest`. The identity tuple has exactly:

| Field | Exact type |
|---|---|
| `pid` | integer `1..4_194_304` |
| `processStartTicks` | 1–20 decimal ASCII digits, no leading zero |
| `executableDevice` | 1–20 decimal ASCII digits, no leading zero |
| `executableInode` | 1–20 decimal ASCII digits, no leading zero |
| `clockBootId` | the attested opaque kernel boot ID |

`daemonIdentityDigest` is exactly `sha256:` followed by the lower-case hex
SHA-256 of
`ASCII("agents-gateway-daemon-identity-v1\0") || RFC8785(daemonIdentity)`.
The manager obtains the tuple after spawn. The watchdog independently reads
the same fields through the transferred pidfd and kernel process metadata and
recomputes the digest before accepting a heartbeat. Rank 2 activates only
when this independently observed tuple/digest differs from the manager
attestation while desired state is running. A signed frame that merely carries
the wrong digest is rejected as a protocol frame; it cannot assert rank 2.

Every ID uses the common bound; a verification key is exactly `ed25519:` plus
64 lower-case hexadecimal characters. After spawn, the daemon receives the
attested digest over its retained inherited manager channel only so it can
echo it; it never supplies the expected value. The private capability and
challenge are never serialized
into the attestation, placed in argv or the environment, written to a named
file, audit, snapshot, or journal.

Each one-use challenge must be signed by its intended role and is then wiped.
The role-specific signing seed is retained only inside that process's health
module until rotation; because peers receive only public verification keys,
neither can forge the other's direction. Sealed bundle descriptors are closed
and their mapped bytes wiped immediately after loading.

### Canonical heartbeat, ping, and ACK wire schemas

One `SOCK_SEQPACKET` datagram contains one UTF-8 JSON object with no BOM or
trailing bytes. Every frame object has `additionalProperties: false` and all
fields are required. The common fields are:

| Field | Exact type/value |
|---|---|
| `schemaVersion` | frame-specific constant below |
| `audience` | constant `agents-gateway-health` |
| `instanceId` | attested opaque ID |
| `bootId` | attested daemon boot ID |
| `watchdogBootId` | attested watchdog boot ID |
| `clockBootId` | attested kernel boot ID |
| `managerGeneration` | integer `1..9_007_199_254_740_991` |
| `frameSeq` | integer `1..9_007_199_254_740_991` |
| `daemonIdentityDigest` | exact manager-attested `sha256:` digest |
| `signature` | 86-character unpadded base64url Ed25519 signature |

Frame-specific fields are exactly:

| Frame | Schema constant | Additional fields |
|---|---|---|
| heartbeat | `agents.gateway.heartbeat.v1` | `sentMonotonicMs` (monotonic integer), `daemonTransitionSeq` (sequence), `phase` (`booting`, `running`, or `shutting-down`), `components` (closed daemon component subset below), `admissionAggregate` (the closed D/0/06 aggregate below) |
| ping | `agents.gateway.health-ping.v1` | `pingId` (exactly 32 lower-case hex characters), `sentMonotonicMs` (watchdog monotonic integer) |
| ACK | `agents.gateway.health-ack.v1` | `pingId` (exactly echoes the outstanding ping), `pingFrameSeq` (exactly echoes that ping's `frameSeq`) |

Heartbeat `components` contains all and only `eventLoop`, `writer`,
`stateStore`, `auditWriter`, `reconciliation`, `supervisor`,
`operatorTransport`, and `coordinationRedis`. Every value is a closed
daemon-sample object with exactly `state` (`ok`, `warning`, `pending`,
`failed`, `stale`, or `disabled`), `observedMonotonicMs` (monotonic integer or
null), and `reasonCode` (allowed code below or null). `ok` requires a sample
time and null reason; warning/pending/failed/stale require a sample time and
non-null reason; `disabled` is allowed only for coordination Redis and has
both nullable fields null. The watchdog supplies fixed criticality, derives
age and impact, and never accepts those as frame fields.

Allowed non-null reason codes are constrained per key: event loop
`EVENT_LOOP_LAG_HIGH`; writer
`WRITER_OWNERSHIP_LOST|WRITER_OWNERSHIP_PENDING|DEPENDENCY_EVIDENCE_STALE`;
state store
`STATE_STORE_INTEGRITY_FAILED|STATE_STORE_SCHEMA_INCOMPATIBLE|STATE_STORE_UNAVAILABLE|STATE_STORE_READ_ONLY|DEPENDENCY_EVIDENCE_STALE`;
audit writer `AUDIT_WRITER_UNAVAILABLE|DEPENDENCY_EVIDENCE_STALE`;
reconciliation
`RECONCILIATION_FAILED|RECONCILIATION_PENDING|DEPENDENCY_EVIDENCE_STALE`;
supervisor `SUPERVISOR_UNAVAILABLE|DEPENDENCY_EVIDENCE_STALE`; operator
transport `OPERATOR_TRANSPORT_UNAVAILABLE|DEPENDENCY_EVIDENCE_STALE`; and
coordination Redis `DEPENDENCY_UNAVAILABLE|DEPENDENCY_EVIDENCE_STALE`.
`controlLoop` is derived only from ping/ACK,
`admissionBudget` only from `admissionAggregate`, and
`observabilityExporter` only from exporter state, so none can be asserted in a
heartbeat.

RFC 8785 JSON Canonicalization Scheme bytes are normative. For signing, remove
the `signature` member, canonicalize the remaining object, and sign exactly:

```text
ASCII("agents-gateway-health-frame-v1\0") ||
UTF8(RFC8785(unsignedFrame))
```

The received full object, including `signature`, must itself equal its RFC
8785 encoding byte-for-byte. Signature verification uses the manager-attested
public key for the sending role. Heartbeat and ACK share one
daemon-to-watchdog `frameSeq`; ping has the independent watchdog-to-daemon
sequence. Both start at one after any role rotation and increase by exactly
one across frame types. The receiver rejects before reduction any oversized,
non-canonical, unknown-field, wrong-version/audience/boot/generation/digest,
gap, duplicate, replay, out-of-order, bad-signature, or invalid-enum frame.
Rejected frames never update heartbeat, ping, component, or identity evidence.

At most one ping is outstanding. Control latency is watchdog
`ACK-receiptMonotonicMs - ping.sentMonotonicMs`; no daemon time is trusted.
An ACK with a prior/unknown `pingId` or wrong `pingFrameSeq` is rejected.

Implementation must check in deterministic test-only vectors at
`gateway/testdata/health-wire/v1/golden/heartbeat.json`,
`golden/ping.json`, `golden/ack.json`, and `golden/vectors.json`. Fixed public
test seeds produce the exact unsigned canonical hex, signature, and complete
datagram bytes. Vectors include: attested digest accepted; validly signed
wrong digest rejected without rank 2; manager-attested tuple versus
independently observed tuple mismatch producing rank 2; omitted/extra field;
non-canonical key order; sequence replay; and ACK bound to the wrong ping.

The manager starts the watchdog before the daemon and may keep it across
daemon generations. On daemon restart it first invalidates the old session,
rotates boot ID, both role bundles, challenges, and keys over the retained
manager bootstrap channels, transfers the new pidfd identity, resets all
directional sequences, and requires the complete handshake. Old frames remain
invalid even if a PID is reused. On watchdog restart the manager similarly
rotates `watchdogBootId` and every role bundle/key, delivers the daemon's new
bundle over its retained manager channel, re-attests the current daemon pidfd,
and blocks readiness until both directions acknowledge. The new watchdog
resumes an open same-host recovery episode from the atomic journal but resets
`watchdogSnapshotSeq` to one.

Manager generation starts at one and is advanced by atomic replace/fsync in
the protected runtime manifest before a role bundle is delivered. A missing
or corrupt manifest forces a new `instanceId` and invalidates every prior
snapshot/session; generation is never guessed or reset under the old
instance. Inherited manager channel identity plus OS peer credentials is the
watchdog's trust root for the attestation, not any field sent by the daemon.

Runtime directory ownership is the dedicated service UID with mode `0700`;
socket, snapshot, journal, cursor, and lock files are regular files or sockets
with mode `0600`. Creation uses descriptor-relative no-follow operations,
rejects symlinks and repository/task-root overlap, and verifies owner/device
before every reopen. Manager bootstrap channels stay open only in the manager
and each intended health module so rotation can occur; all other descriptors
are close-on-exec except during one intended transfer and are closed before
any agent child is created. Every health/bootstrap descriptor is absent from
child environments and mounts.

The watchdog is health-only: it has no policy, operator-key, control-store,
audit-store, repository, artifact, approval, Redis, or mutation capability.
D/0/05's same-UID `host-unconfined` limitation remains explicit; this plan
does not claim resistance to a host-unconfined process running as the service
operator.

## Probe and external observation

The one-shot probe reads the bounded atomic snapshot and independently checks
its owner, schema, clock boot, size, sequence, and monotonic age. It never
calls the daemon. Separate `--mode live` and `--mode ready` requests have the
hard configured deadline and these stable exits:

| Exit | Meaning |
|---:|---|
| `0` | requested condition is current: live for live mode, ready for ready mode |
| `1` | observation is current and live, but requested readiness is false |
| `2` | observation proves the expected daemon identity mismatched, stopped, dead, heartbeat-missing, or stalled |
| `3` | liveness remains unproven before first-heartbeat grace, or observer evidence is unavailable/stale/protocol-invalid/unsupported |

The richer cached projection is available only over the E/0/00 local operator
transport after peer and version checks. There is no MCP health tool, public
HTTP endpoint, or unauthenticated network listener.

## Monotonic recovery timing

The watchdog is the sole authority for recovery landmarks. It reads Linux
`CLOCK_BOOTTIME` and the kernel boot ID; daemon monotonic values are
informational until the watchdog proves the same `clockBootId`. Wall time is
display-only and is never subtracted.

An episode opens on the first unplanned current transition from ready to
not-ready or recovery-required. `SHUTTING_DOWN` followed by the manager's
planned `PROCESS_STOPPED` does not open an outage. Cold boot opens a `BOOTING`
episode at the manager-attested daemon start. The exact
`failureBoundaryMonotonicMs` is:

| Initial condition | Failure boundary |
|---|---|
| observer/watchdog exit | service-manager pidfd exit time, supplied to the replacement watchdog |
| process exit | daemon pidfd signal time recorded by the watchdog |
| no first heartbeat | `attestedStartMonotonicMs + initialHeartbeatGraceMs` |
| stalled event loop | `lastHeartbeatReceiptMonotonicMs + heartbeatStaleThresholdMs` |
| control timeout | `pingSentMonotonicMs + controlPingTimeoutMs` |
| stale dependency | `lastComponentSampleMonotonicMs + dependencyEvidenceFreshnessMs` |
| cold boot | manager `attestedStartMonotonicMs` |
| current negative component, integrity, or saturation | watchdog receipt/evaluation time of the first activating current sample |

Manager-supplied start/exit landmarks are accepted only over the inherited
attested channel with the same kernel `clockBootId`; otherwise the episode is
immediately host-reboot-incomparable.

`detectedMonotonicMs` is the first watchdog reduction at or after that
boundary that activates the condition. `recoveryStartedMonotonicMs` is the
watchdog receipt time of the first manager-attested restart-start event or
authenticated operator recovery command accepted after detection, whichever
occurs first; supplied caller timestamps are ignored and it may remain null.
`firstGoodMonotonicMs` and `readyConfirmedMonotonicMs` are watchdog reduction
times. Good samples are counted only at distinct
`watchdogSnapshotIntervalMs` ticks with a complete current ready projection;
multiple daemon frames inside one interval count once.

For one unchanged `clockBootId`, closed-episode formulas are exact:

```text
timeToDetectMs = detectedMonotonicMs - failureBoundaryMonotonicMs
timeToRecoverMs = readyConfirmedMonotonicMs - detectedMonotonicMs
outageDurationMs = readyConfirmedMonotonicMs - failureBoundaryMonotonicMs
```

Negative results invalidate the observation. A daemon restart or watchdog
restart on the same kernel boot remains comparable. If the kernel
`clockBootId` changes while an episode is open, the replacement watchdog
retains the episode ID and display chronology, sets
`clockQuality=host-reboot-incomparable`, clears the episode clock, all
monotonic landmarks, and all duration fields to null, and never subtracts
values across boots. It may close the episode after the configured good
samples, but cannot manufacture TTD, TTR, or outage time.

### Bounded durable evidence

The watchdog writes one atomic snapshot of at most 64 KiB and an append-only
transition journal. A journal record is at most 4 KiB; a segment seals at 8
MiB or 10,000 records, whichever occurs first. The active segment plus seven
sealed segments are retained, bounding the journal to 64 MiB and 80,000
records. Snapshot replacement, segment sealing, and cursor replacement use
write/fdatasync/rename/fsync-directory order.

Sealed segments older than the durable exporter cursor may be removed. If the
eight-segment bound is reached while the cursor still references the oldest
segment, the watchdog writes a fixed `JOURNAL_GAP` marker to the atomic
snapshot, increments `agents_gateway_health_journal_gap_total`, marks the
observability exporter component degraded, then removes the oldest segment.
Loss is therefore bounded and explicit, never silent or allowed to exhaust
disk. Journal records and cursor files use a version, segment ID, record
sequence, checksum, instance ID, and watchdog boot ID; corrupt or mismatched
records are rejected.

When export was explicitly disabled before boot, there is no delivery
contract: the exporter component is `disabled`, and sealed segments rotate at
the same bound using a local retention watermark without a gap alert. Enabling
export requires a new validated configuration generation and creates the
durable cursor at the oldest retained record. A configured exporter can never
silently fall back to disabled retention.

### Metric transport and durable cursor

The health exporter is a separate health-only worker. It consumes the bounded
journal in `(segmentId, recordSeq)` order and stores a durable exporter cursor
under the health runtime root. Optional source adapters have independent
closed cursors in the same protected root. A cursor advances only for a full
ACK or an explicitly marked singleton permanent loss under the table below,
using atomic replace and directory fsync.
Export is at least once: retries may resend the last unacknowledged batch, so
metric points use cumulative temporality, stable start timestamps, and stable
point timestamps rather than increment-on-receive deltas. Retries use bounded
exponential backoff of 1, 2, 4, 8, 16, then 30 seconds with at most one batch
in flight. A batch contains contiguous records from exactly one source and at
most 512 records or 256 KiB.

At every export interval, each enabled source also contributes one fixed
source-liveness point. For an empty but successfully polled source, its sample
timestamp is the completed bounded poll time; a full backend ACK therefore
initializes and refreshes `last_ack` without inventing or advancing a source
record cursor. Failure to poll or export that point leaves both timestamps
stale. Thus an idle enabled source has a deterministic freshness signal
instead of permanent `no_data`.

OTLP acknowledgement and cursor behavior is exact:

| Export result | Exact classification | Cursor/retry action |
|---|---|---|
| full ACK | gRPC `OK` or HTTP `2xx`, valid response, and `partial_success` absent or `rejected_data_points=0` | atomically persist/fsync the cursor through the whole contiguous batch; a non-empty warning string is discarded |
| ambiguous partial | successful transport with `0 < rejected_data_points <= sentDataPointCount` | advance nothing; retry the identical batch `exportAmbiguousAttemptsBeforeSplit` times, then split by source-record midpoint and process the left half first |
| retryable transport | gRPC `CANCELLED`, `DEADLINE_EXCEEDED`, `RESOURCE_EXHAUSTED`, `ABORTED`, `OUT_OF_RANGE`, `UNAVAILABLE`, or `DATA_LOSS`; HTTP `408`, `429`, `500`, `502`, `503`, or `504` | advance nothing and retry the identical batch with the bounded backoff |
| operator-blocked transport | gRPC `UNAUTHENTICATED`, `PERMISSION_DENIED`, `NOT_FOUND`, or `UNIMPLEMENTED`; HTTP `401`, `403`, `404`, `405`, or `501` | advance nothing, alert, and retry every 30 seconds until operator configuration changes |
| record-permanent rejection | gRPC `INVALID_ARGUMENT`, `ALREADY_EXISTS`, or `FAILED_PRECONDITION`; HTTP `400`, `409`, or `422` | split immediately by source-record midpoint; do not advance over an unexamined record |
| invalid/unknown response | malformed body, negative or over-counted rejection, unknown status, or timeout beyond `exportTimeoutMs` | protocol/retryable; advance nothing |

Splitting recurses in source order. A one-record partial or record-permanent
rejection is the only intentional skip: before advancing past it, the exporter
fdatasyncs an `EXPORT_PERMANENT_REJECT` marker containing source/cursor,
closed error category, point count, and canonical mapped-record SHA-256 but no
raw payload/error text; increments
`agents_gateway_exporter_data_loss_total`; then fsyncs the cursor. Accepted
points from a partial response can be resent because
cumulative points retain identical start/point timestamps. No partial cursor
advance, guessed rejected index, or retry re-observation is allowed.
Retryable/operator-blocked retention pressure follows the already-defined
explicit journal/Redis gap path; it never silently advances a cursor.

The inherited one-shot Python metrics reader is replaced by a long-running
allowlisted source adapter with a local durable Redis stream cursor. Its first
requested ID is `0-0`, never `$`; each `XREAD` is bounded to 512 entries and a
one-second block. It extracts only closed numeric/category fields, exports,
then persists the last acknowledged stream ID. It does not create a consumer
group, acknowledge, trim, publish, or otherwise mutate `agents:events`. If
retention has advanced beyond its cursor, it records and alerts an explicit
source gap before resuming at the first retained ID. Redis absence disables
this optional adapter without changing base Gateway readiness or Redis
semantics. A retained record that cannot validate against the closed source
mapping is handled like a singleton permanent rejection: fsync an
`INVALID_SOURCE_RECORD` marker/digest, increment data loss with
`invalid_source_record`, then advance past that record without storing its raw
content.

The production interface is OpenTelemetry OTLP metrics to one server-owned,
allowlisted TLS endpoint. Endpoint, CA, and client credential references are
deployment configuration, never tool/caller input or health payload data. The
implementation uses the maintained OpenTelemetry SDK/OTLP exporter, not the
inherited no-op or stderr exporters. The required disposable integration lane
supplies an OpenTelemetry Collector, Prometheus recording/alert rules, and a
Grafana-compatible dashboard. The Gateway itself opens no network listener.
Development may disable export; a configured exporter that is stale, failed,
or has a journal gap degrades but does not block base Gateway readiness.

#### Zero-event loss-counter population

The two loss counters have exactly the following five series. This is a
closed population, not a Cartesian product; every other
instrument/source/reason combination is rejected:

| Instrument | `source` | `data_loss_reason` | Initial value | Increment event |
|---|---|---|---:|---|
| `agents_gateway_health_journal_gap_total` | `health_journal` | `journal_retention` | 0 | one `JOURNAL_GAP` transition |
| `agents_gateway_health_journal_gap_total` | `agents_events` | `redis_retention` | 0 | one detected Redis cursor/retention gap |
| `agents_gateway_exporter_data_loss_total` | `health_journal` | `permanent_otlp_rejection` | 0 | number of health-journal source records skipped after durable `EXPORT_PERMANENT_REJECT` markers |
| `agents_gateway_exporter_data_loss_total` | `agents_events` | `permanent_otlp_rejection` | 0 | number of Redis source records skipped after durable `EXPORT_PERMANENT_REJECT` markers |
| `agents_gateway_exporter_data_loss_total` | `agents_events` | `invalid_source_record` | 0 | number of Redis source records skipped after durable `INVALID_SOURCE_RECORD` markers |

The gap pairs are exactly `health_journal` / `journal_retention` and
`agents_events` / `redis_retention`; the three remaining rows are the only
data-loss pairs.

Installation provisioning creates manager-owned
`metric-generation.v1.json` and stable `metric-generation.lock` files in the
protected service-manager state root, outside replaceable per-instance state,
before the service can start. The lock file is never renamed, replaced, or
deleted. Provisioning uses create-once/no-follow semantics and refuses to
truncate, reset, or recreate either file when any manager state exists. The
allocation record is a closed object with exactly
`schemaVersion=agents.gateway.metric-generation.v1`,
`lastAllocatedGeneration=0`, and `checksum`; the checksum is lower-case
64-hex SHA-256 of
`ASCII("agents-gateway-metric-generation-v1\0") || RFC8785` of the first two
fields. The manager never reconstructs a missing record or lock. Before
assigning each new `instanceId`, it takes an exclusive OFD lock on the stable
lock file before opening the allocation record. While holding that lock it
validates owner/mode/schema/checksum and an integer generation in
`0..9_007_199_254_740_990`, increments it exactly once, then
write/fdatasync/rename/fsync-directory replaces and rereads the record before
releasing the lock. Only after that durable step may it create the instance
manifest with `instanceMetricGeneration=lastAllocatedGeneration`. A crash
after allocation burns the number; no restart, instance deletion,
configuration change, host reboot, wall-clock rollback, or same-second
creation can decrement or reuse it. A missing, unreadable, corrupt,
lock-unavailable, or maximum generation fails closed before manifest creation
or Gateway start; it yields missing exporter input, a bad SLO tick, and the
existing missing-input alert, never a guessed generation.

For that new instance the manager also sets `instanceMetricEpochUnixNano` to
`1_000_000_000 * floor(nowUnixNano / 1_000_000_000)` and persists both values
in the protected instance manifest. It initializes a crash-safe metric ledger
with all five rows at zero before any source adapter may poll or consume a
record. Every row uses the exact epoch as its OTLP cumulative start timestamp
and carries the safe-integer `instanceMetricGeneration` as the fixed resource
attribute `agents.gateway.metric_generation`. An enabled source exports all
and only its rows in every source-liveness batch, including a zero-valued
cumulative point for a reason that has never occurred. A disabled source is
excluded from recording-rule population and may omit points, but its durable
rows are retained.

The ledger value, start timestamp, and instance metric generation survive
exporter, daemon, watchdog, source-adapter, and configuration-generation
restarts under the same `instanceId`; disabling and re-enabling a source
neither deletes nor rebases them. Each marker/value update is fdatasynced
before the corresponding source cursor advances. A missing or corrupt ledger
for an existing `instanceId` makes the exporter failed and its rule input
absent; it is never repaired by silently creating zero. Only creation of a new
`instanceId` allocates a strictly greater `instanceMetricGeneration`, creates
a new OTLP resource/start timestamp, and initializes five zero values.

The first source-liveness export after enablement contains its complete row
population in one batch. At the first wall tick strictly after a full ACK, a
source with no historical loss therefore has current zero values with one
common start timestamp and generation. The delta bootstrap rule below records
zero and makes that tick good when all other freshness predicates pass. A
partial ACK, missing row, unequal start/generation, or any non-zero first
value makes the tick bad; no recording rule synthesizes a missing counter as
zero.

Counters are cumulative monotonic safe integers per OTLP resource
`service.name=agents-gateway`, `service.instance.id=instanceId`,
`agents.gateway.metric_generation=instanceMetricGeneration`, and start
timestamp; source semantic events increment once, exporter retries never
re-increment them, and daemon/watchdog restart under the same `instanceId`
restores persisted values. A new `instanceId` starts a new resource/time
series. The Collector must not promote `service.instance.id` or
`agents.gateway.metric_generation` into a Prometheus metric label. Histograms
have cumulative count/sum/buckets and observe each semantic event once.
Observable gauges publish the last current sample; missing/stale input is
absent, never coerced to zero. NaN, infinity, negative ages/counts, unknown
labels, wrong units/kinds/bounds, and `outcome=success` with non-`none` error
(or non-success with `none`) are schema errors. G/0/03, H/0/04, and I/0/05
may feed only these named instruments/labels; a new family or enum requires a
later schema version.

Flow linkage reuses the already-versioned Gateway trace/correlation context
through existing Gateway, Temporal, and coordination fields; E/0/04 changes
no public envelope or `agents:events` record. Before an OTLP exemplar is
created, the exporter derives a 16-byte telemetry trace ID as
`HMAC-SHA256(rotationKey, canonicalTraceId || correlationId)[0:16]`. The
server-owned key rotates daily and never leaves protected configuration.
Only that fixed-size unlinkable value may appear as an exemplar; raw trace,
task, session, message, or correlation IDs never become metric labels or
health fields. Only server-validated canonical IDs within the common opaque-ID
bound are hashed; missing, caller-only, or oversized context produces a metric
point without an exemplar.

Metrics, frames, snapshots, journals, audit, and operator responses exclude
repository/cwd/path, PID/argv, principal, raw trace/task/session/correlation,
provider/model, prompt, source, diff, output, exception/error text, tokens,
credentials, and arbitrary caller labels. The derived exemplar above is the
only correlation exception. Internal failures map to closed categories and
reason codes.

### SLOs, alerts, and dashboard

Recording rules evaluate on every wall-aligned
`recordingRuleIntervalSeconds=10` tick. V1 release topology has exactly one
expected D/0/05 Gateway instance. Every tick is in the readiness denominator,
including boot, planned stop, observer/exporter outage, and missing telemetry;
there is no maintenance exclusion. The evidence validator reconstructs all
expected 10-second timestamps and inserts a bad numerator for a missing
Prometheus rule result, so backend/rule downtime cannot disappear from a
range-vector denominator.

A health tick is fresh only when
`agents_gateway_observation_sample_timestamp_seconds` exists and is no older
than the exported `export_freshness` threshold, and
`agents_gateway_observer_age_seconds` is at or below the
`watchdog_snapshot_freshness` threshold. A missing/NaN/stale input is false,
not no-data. Source enablement comes from the candidate deployment manifest;
`agents_gateway_source_enabled` must agree or the release gate fails.

#### Exact wall-aligned loss delta

The generated Collector mapping carries each of the five counters' OTLP
data-point start timestamps into exactly two backend-only companion metric
families:
`agents_gateway:health_journal_gap_start_timestamp_seconds` and
`agents_gateway:exporter_data_loss_start_timestamp_seconds`. Each companion
has the same constant `schema_version`, `source`, and `data_loss_reason`
labels as its counter and the exact integer value
`instanceMetricEpochUnixNano / 1_000_000_000`. These companions are derived
from registered counter metadata, are not producer instruments, accept no
extra labels, and cannot be supplied by a caller.

The same mapping carries the integer
`agents.gateway.metric_generation` resource attribute into exactly two more
backend-only companion families:
`agents_gateway:health_journal_gap_instance_generation` and
`agents_gateway:exporter_data_loss_instance_generation`. They have the same
three fixed labels as their counters and the exact
`instanceMetricGeneration` as their safe-integer value. The attribute and
value never become labels and these companions are derived mapping state, not
new producer instruments.

Let `T` be a Unix-second timestamp with
`T mod recordingRuleIntervalSeconds = 0`. Two generated rule groups run in
the declared order at every `T`. The snapshot group selects, for each row in
the closed population table, the newest
counter/start-timestamp/instance-generation triplet whose point timestamp is
in `(T - 310 s, T]`. Ties must be byte-identical. It then requires the point
age to be at most the current `export_freshness` threshold, the source-enabled
and last-full-ACK inputs to be current, all expected rows for that enabled
source to exist, every start timestamp to equal the same persisted instance
epoch, and every generation to equal the same safe positive integer. Failure
of any requirement makes that source's input invalid at `T`; a missing, stale,
NaN, duplicate-conflicting, or unexpected series is never converted to zero.

For valid input the snapshot group writes
`agents_gateway:export_loss_counter_at_tick` and
`agents_gateway:export_loss_start_at_tick_seconds` plus
`agents_gateway:export_loss_generation_at_tick` at exact timestamp `T`,
retaining only (`schema_version`, `source`, `data_loss_reason`). The delta
group obtains `priorTick` only from those recording series at exact timestamp
`T - 10 s`; it does not use a lookback substitute. For every expected series
`k`, the delta assigned to the adjacent wall interval `(T - 10 s, T]` is:

```text
if current input is invalid:
    delta(k, T) = invalid
else if priorTick(k) is absent and currentValue(k) == 0:
    delta(k, T) = 0
else if priorTick(k) is absent:
    delta(k, T) = invalid
else if currentGeneration(k) != priorGeneration(k):
    delta(k, T) = invalid
else if currentStart(k) != priorStart(k):
    delta(k, T) = invalid
else if currentValue(k) < priorValue(k):
    delta(k, T) = invalid
else:
    delta(k, T) = currentValue(k) - priorValue(k)
```

Thus the first current zero after the first full liveness ACK is an explicit
zero baseline, including at the first wall tick strictly after that ACK.
A non-zero sample without `priorTick` is invalid. If a start timestamp differs
from the prior tick, the instance metric generation differs, or the counter
decreases, that tick is a reset/unknown interval, never a Prometheus
`increase()` extrapolation. Generation comparison precedes start/value
comparison. A valid current snapshot is stored even when its delta is invalid,
so one subsequent unchanged valid tick establishes a new comparison baseline.
No snapshot is stored for invalid current input.

The required golden same-second replacement has:

```text
prior:   start=S, instanceMetricGeneration=41, oldValue=1
current: start=S, instanceMetricGeneration=42, newValue=1
```

At the current tick the generation mismatch produces `invalid`, emits no
`agents_gateway:export_loss_delta10s`, records per-source input-valid zero,
makes the export-freshness SLO numerator zero, and fires
`GatewayMetricDataLoss`. It can never enter the `newValue - oldValue` branch
or report delta zero. If the following tick retains generation 42/start S/
value 1, that comparison is valid delta zero and resolves the alert under the
existing rule. Two replacements in one second, or replacement during
wall-clock rollback, differ by generation in exactly the same way.

The delta group records one
`agents_gateway:export_loss_delta10s` per expected series only when its delta
is valid. It records `agents_gateway:export_loss_input_valid` as `1` for a
source iff every expected series is valid and otherwise `0`, then computes
`agents_gateway:export_loss_delta10s_by_source` as the sum by (`schema_version`, `source`)
after dropping `data_loss_reason`. The five source/reason pairs are disjoint
across the two input counters, so this union cannot collide. These are backend
recording series derived from the closed registry, not additional producer
instruments.

For each manifest-enabled source, the rule generator emits one constant
expected-source vector carrying only `schema_version=v1` and that fixed
`source`. It left-joins the actual row population and records
`agents_gateway:export_loss_input_valid=0` when any counter, companion, ACK,
or freshness input is absent; an `unless` branch makes an absent join produce
the same zero rather than no series. This generated validity zero is not a
synthetic counter value. Disabled sources have no expected vector, validity
series, SLO denominator, or alert instance.

For enabled source `s`, the export-freshness numerator at `T` is exactly one
iff source enablement agrees with the manifest, source sample and full ACK are
fresh, `agents_gateway:export_loss_input_valid{s}=1`, and
`agents_gateway:export_loss_delta10s_by_source{s}=0`; otherwise it is zero.
The denominator contributes exactly one for every expected enabled-source
tick, or 8,640 samples per continuously enabled source in the half-open
window `(T - 24 h, T]`. A loss increment becomes one bad tick at the first
`T` whose normalized cumulative value contains it; that bad sample remains in
the rolling 24-hour SLO window until the evaluation at `T + 24 h`, even though
the next unchanged tick may be good.

`GatewayMetricDataLoss` evaluates the same per-source derived inputs every
10 seconds. It fires at `T` when the input-valid value is zero/missing or the
per-source delta is positive, retaining exactly `schema_version` and `source`
as alert aggregation labels. Its rule has `for: 0s` and
`keep_firing_for: 0s`; it resolves at the first later wall tick with complete
current input, valid delta, and a zero per-source sum. One isolated increment
therefore fires for one nominal 10-second evaluation interval; missing/stale
input fires until it recovers, a reset fires for at least its invalid tick,
and a restored positive series with no `priorTick` remains invalid until one
later stable comparison. `GatewayExporterStale` may fire simultaneously;
neither rule suppresses the other.

## Boot and recovery behavior

Boot readiness follows this order:

1. complete manager/watchdog bootstrap and announce `BOOTING`;
2. acquire and verify D/0/03 writer ownership;
3. open and validate required stores;
4. reconcile lifecycle/process state;
5. reconcile D/0/06 reservations without forgiving consumed cost;
6. initialize D/0/01 supervisor and E/0/00 operator transport; and
7. become ready only when all required evidence is current and converged.

An ambiguous lock, unverifiable orphan, contradictory lifecycle, corrupt
store, unsupported schema, or inconsistent budget ledger ends in
`recovery-required`. This sheet never deletes diagnostic state, kills an
ambiguous process, restarts the Gateway, or performs destructive remediation.

  rotation.
