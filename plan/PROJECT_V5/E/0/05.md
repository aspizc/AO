## Problem

An exact one-shot approval does not implement a reusable orchestrator grant.
Today broad execution can still be represented by flags or inherited
configuration, while the operator lacks a single place to create, inspect,
revoke, and understand bounded autonomy.

## Scope

- Add a server-owned `orchestrator_execution_grant` bound to principal,
  session, Gateway instance/boot audience, canonical repository/CWD, task,
  target agents/roles, allowed mode, mount/network/environment profile,
  evidence digest, expiry, `maxUses`, nonce, and budget.
- Support an exact one-shot grant and a bounded session grant. Both are signed,
  revocable, visible in inventory, and atomically consumed at the protected
  `agent.launch.<mode>` effect.
- Make missing, expired, revoked, exhausted, wrong-scope, or changed-digest
  grants create an exact pending approval and perform zero process launch.
- Add operator-only local-control commands to create, list, show, and revoke
  grants and to preview a launch before signing.
- Render `workspace-yolo` as repository/scratch autonomy with the control plane
  excluded, and `host-unconfined` as access available to the Gateway UID,
  including filesystem, credentials, network, other repositories, expiry,
  remaining uses, and budget.
- Preserve the public MCP catalog, `coordination.*`, `agents:events`, and
  `message.*`; no agent-facing tool can mint or widen a grant.

## Non-scope

- No role/flag/environment-derived authority, unlimited or unexpiring grant,
  unattended credential enrollment, automatic spend/rerun, hidden
  `host-unconfined` downgrade, public grant mutation, or claim that same-UID
  execution remains sandboxed.

## Acceptance criteria

- [ ] Broad execution occurs only under an exact valid grant or exact signed approval.
- [ ] Grant scope, expiry, uses, revocation, and budget are enforced atomically.
- [ ] Create/list/show/revoke and launch preview work without agent-facing mutation.
- [ ] The operator can distinguish workspace autonomy from same-UID host access.
- [ ] Invalid or raced grants cause zero launch and preserve an actionable pending state.
- [ ] No grant, signing key, credential, or unrestricted host detail enters MCP/audit output.

## Verification

(session grant, one-shot grant, and pending approval) for supported adapters,
operator CLI narrow/JSON rendering, control-boundary and secret canaries,
`bash scripts/ci.sh`, and `git diff --check`.
