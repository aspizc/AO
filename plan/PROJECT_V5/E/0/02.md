## Problem

Agent-facing `approval.respond` lets an untrusted channel represent operator
authority. A safe grant must be exact, signed, fresh, single-use, and consumed
at the authorized effect.

## Scope

- Issue a bound challenge and verify a canonical signed decision containing
  instance/boot audience, approval/action/context digest, nonce, expiry, and
  decision.
- Consume nonce and first-wins decision atomically with the effect precondition;
  wake waiters only as a hint.
- Remove `approval.respond` from public MCP/tool discovery.

## Non-scope

- No private signing key in Gateway/agent env, unsigned `--yes`, reusable grant,
  broad capability, or coordination message as approval.

## TDD RED

Cover tamper, wrong key/audience/action/digest/approval, expiry, replay before
and after restart, two-decision race, crash boundary, and self-grant through
MCP.

## TDD GREEN

Implement challenge/nonce persistence, signature verifier, atomic decision
consume API, and catalog migration removing the MCP mutation.

## Acceptance criteria

- [ ] Only a verified exact decision can authorize the bound effect.
- [ ] Grant/deny/cancel are first-wins and replay-safe across restart.
- [ ] Signing material is never mounted, logged, or accepted from an agent.
- [ ] `approval.respond` is absent from the public MCP catalog.

## Verification

Run crypto-envelope/nonce/race/fault tests, public catalog snapshots, control
integration, and adversarial MCP lane; then `bash scripts/ci.sh` and
`git diff --check`.
