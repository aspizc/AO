## Problem

Safe backend controls are not usable if the operator cannot understand current
state, preview the exact decision, sign it, and inspect the outcome from one
defensive CLI.

The current `agent-run audit show` and `agent-run approve` commands invoke Node
helpers that read the audit log and SQLite state directly. That is not a valid
operator boundary: it duplicates Gateway configuration, bypasses the
versioned local control protocol, and makes a missing control service look like
permission to operate on stores. This sheet replaces those paths; it does not
add another authority path.

## Delivery boundary and ownership

This sheet starts only after all four dependencies are implemented, reviewed,
and integrated:

- `D/0/05` supplies the operator-only endpoint, peer/audience checks,
  non-inheritance/auto-discovery controls, and recursive-writer prevention. It
  does **not** make the endpoint or operator files undiscoverable to a
  same-UID `host-unconfined` child.
- `E/0/00` supplies the versioned local transport, inventory/status
  operations, and their safe DTOs. Its normalized trace status consumes
  `C/1/01`; this CLI does not query lifecycle stores itself.
- `E/0/01` supplies immutable approval detail, pending list/show, full
  algorithm-qualified context digest, and deterministic preview fields.
- `E/0/02` supplies the canonical challenge, external-signature contract, and
  atomic first-wins decision operation.

Implementation write scope is limited to
`cli/src/agents_cli/{main,output,control_client,signer}.py`, focused files under
`tests/cli/`, the read-only allowlisted audit projection and its two operations
on the control server created by `E/0/00`, their focused Gateway tests, the
operator CLI contract, and narrowly necessary CLI packaging. Any lifecycle,
inventory, approval, signature, or authority correction returns to its owning
prerequisite sheet.

`policy validate` and `policy check` retain their existing contract. This sheet
does not edit the public MCP registry. In particular, the versioned removal of
`approval.respond` belongs exclusively to `E/0/02`. The exact eight-tool
`coordination.*` catalog remains, in protocol order:
`coordination.status`, `coordination.register`, `coordination.heartbeat`,
`coordination.discover`, `coordination.unregister`, `coordination.send`,
`coordination.receive`, and `coordination.ack`. `message.*` and the legacy
`agents:events` behavior remain unchanged.

## Scope

- Add the frozen inventory, status, approval, and audit CLI commands over the
  authenticated local control protocol.
- Add `audit.list` and `audit.explain` as bounded read-only operations on that
  operator control protocol. Their server projection allowlists only
  `eventId`, `timestamp`, `eventType`, `traceId`, `taskId`, `sessionId`,
  `approvalId`, `actorAgentId`, `actorRole`, `action`, `decision`, `ruleId`,
  `outcomeCode`, and a server-generated bounded `summary`; it never returns
  the stored event or metadata object.
- Replace the CLI's direct audit/state Node-helper paths with one typed local
  client, while retaining the documented compatibility command names.
- Require exact preview and consent before a bounded external signer and the
  effect-bound decision operation.
- Provide stable JSON envelopes and safe human rendering for redirected,
  narrow, and hostile terminal inputs.

## Frozen CLI v1 surface

The root control options precede the command group. Standard Typer
`--help` and the existing root `--version` behavior remain unchanged; neither
performs a control request. Every option/argument introduced or retained by
this sheet has the following deterministic parse contract:

| Input | Applies to | Required/default | Accepted value and bound |
|---|---|---|---|
| `--control-socket <path>` | every control-backed command | optional; resolution order below | Absolute filesystem path, no NUL/control character, 1–100 UTF-8 bytes. |
| `--timeout-ms <int>` | every control-backed command | optional; default `3000` | Integer 100–10000 inclusive. This is one monotonic total deadline for each connect/write/read exchange, not a per-phase timeout. |
| `--json` | every leaf command | flag; default `false` | Boolean flag only. |
| `--kind <kind>` | `inventory list` | optional; default `all` | `all`, `orchestration`, `task`, or `session`. |
| `<kind>` | `inventory show` | required positional | `orchestration`, `task`, or `session`; `all` is invalid. |
| `<resource-id>` | `inventory show` | required positional | 1–128 UTF-8 bytes, with no whitespace, NUL, C0/C1 control, bidi control, or ANSI/OSC escape. The owning server still validates the identifier schema. |
| `<approval-id>` | `approval show`, `approval decide`, compatibility `approve` | required positional | Same 1–128-byte lexical bound as `<resource-id>`. |
| `<event-id>` | `audit explain` | required positional | Same 1–128-byte lexical bound as `<resource-id>`. |
| `--include-recent` | `inventory list` | flag; default `false` | Boolean flag only. |
| `--limit <int>` | `inventory list`, `approval list`, `audit show` | optional; default `50` | Integer 1–100 inclusive; it is page size, never an unbounded total. This preserves the current `audit show` default of `50`. |
| `--cursor <opaque>` | `inventory list`, `approval list`, `audit show` | optional; default absent | Opaque non-whitespace value of 1–2048 UTF-8 bytes with no controls; the client never decodes it. |
| `--trace-id <id>` | `status`, `audit show` | optional; default absent | Same 1–128-byte lexical bound as `<resource-id>`. |
| `--type <event-type>` | `audit show` | optional; default absent | ASCII `[A-Z][A-Z0-9_]{0,63}`. |
| `--decision/-d <decision>` | `approval decide`, compatibility `approve` | required; current `-d` alias retained | Canonical command: `granted`, `denied`, or `cancelled`; compatibility alias: `granted` or `denied`. |
| `--note <text>` | both decision commands | optional; default empty | 0–512 UTF-8 bytes; it is signed but never echoed or placed in audit/telemetry. |
| `--signer <provider-id>` | both decision commands, interactive and noninteractive | **required; no default or environment fallback** | ASCII `[A-Za-z0-9][A-Za-z0-9._-]{0,63}` naming one operator-configured provider. |
| `--signer-timeout-ms <int>` | both decision commands | optional; default `30000` | Integer 1000–120000 inclusive; one monotonic total signer-process deadline. |
| `--non-interactive` | both decision commands | flag; default `false` | Boolean flag only. |
| `--confirm <text>` | both decision commands | default absent and forbidden interactively; required with `--non-interactive` | 1–1024 UTF-8 bytes and byte-for-byte equal to the current server-projected confirmation text. |

Missing required values, invalid enums, empty supplied values, out-of-range
integers, forbidden option combinations, and local lexical/bound failures
return exit 2 **before** socket or signer access. Booleans do not accept an
explicit string value. The consent prompt itself has no CLI timer; after input
and before signing, local expiry observation can fail early with exit 5, while
the server remains authoritative.

Endpoint resolution is, in order: explicit `--control-socket`, the
operator-launch environment value `AGENTS_CONTROL_SOCKET`, then
`$XDG_RUNTIME_DIR/agents-orchestrator/control.sock`. Every resolved value uses
the same absolute-path and 100-byte checks. Resolution never searches the
repository or workspace. If neither an explicit/environment path nor
`XDG_RUNTIME_DIR` exists, local configuration fails with exit 2; a resolved
path that is absent or is not a socket fails with exit 3. A present-but-empty
environment value, relative `XDG_RUNTIME_DIR`, or derived path above the bound
is invalid configuration (exit 2), not permission to try the next source.

`D/0/05` removes inherited endpoint/config values and auto-discovery from
configured child launches and excludes operator paths from the mounts used by
`confined` and `workspace-yolo`. This is non-inheritance, not isolation:
a same-UID `host-unconfined` child may inspect the predictable socket,
operator configuration, other host files, or process state. Such a launch
requires a separate exact `host-unconfined` execution grant and explicit
current operator consent before spawn. The CLI never creates that grant or
represents the mode as confined.

| Command | Frozen arguments/options | Result |
|---|---|---|
| `agent-run inventory list` | `--kind all\|orchestration\|task\|session` (default `all`), `--include-recent` (default false), `--limit` (default `50`), optional `--cursor`, `--json` | Bounded active inventory plus optional bounded recent terminal history; no identifier is required. |
| `agent-run inventory show <kind> <id>` | `kind=orchestration\|task\|session`, `--json` | One normalized relationship/status projection or a safe not-found error. |
| `agent-run status` | optional `--trace-id <id>`, `--json` | Control-instance/inventory status without an ID, or the normalized trace overview and typed blockers with an ID. |
| `agent-run approval list` | `--limit` (default `50`), optional `--cursor`, `--json` | Pending approvals only, in server-defined deterministic order. |
| `agent-run approval show <approval-id>` | `--json` | Immutable exact context, expiry/status, full digest, and `confirmationTexts` keyed by `granted`, `denied`, and `cancelled`. |
| `agent-run approval decide <approval-id>` | required `--decision/-d` and `--signer`; optional bounded `--note`; `--signer-timeout-ms` default `30000`; `--non-interactive` default false; conditionally required `--confirm`; `--json` | Preview, consent, external signature, atomic apply, and terminal outcome. |
| `agent-run audit show` | optional `--trace-id`, `--type`, and `--cursor`; `--limit` default `50`; `--json` | Bounded allowlisted events from the control protocol. |
| `agent-run audit explain <event-id>` | `--json` | Allowlisted actor/action/decision/rule/outcome explanation; never a raw event. |

The existing
`agent-run approve <approval-id> (--decision|-d) granted|denied --signer
<provider-id> [--note <text>] [--signer-timeout-ms <int>]
[--non-interactive --confirm <text>] [--json]` surface remains as a
compatibility alias for `approval decide`.
Requiring `--signer` is an intentional security-tightening change in the
versioned minor described below. The alias executes the same preview, consent,
signer, and control-protocol path, emits a deprecation warning only in human
mode on stderr, and never invokes `gateway/scripts/approval-respond.mjs`. It
does not accept `cancelled` and is not an unsigned compatibility escape.
Removing it requires a versioned CLI-breaking-change ADR.

`audit show` likewise keeps its current flags but stops invoking
`gateway/scripts/query-audit.mjs`. Existing direct helpers may remain for
other owned migrations, but this CLI cannot execute them or read their
underlying files.

The old audit/approve JSON shapes were not included in the stable
`docs/operator-cli-contract.md` surface. This reviewed delivery increments the
pre-1.0 `agents-cli` minor and establishes the envelope below as their first
versioned operator-control contract; `policy validate/check` output stays
unchanged. The new bounds on formerly unconstrained audit filters/limits and
approval arguments, plus mandatory signer selection, are explicitly part of
that minor; the current `-d` short alias is preserved. Any subsequent
incompatible command, option, exit, or envelope change requires an ADR and
another versioned CLI contract.

## Thin-client architecture

`agents_cli.control_client` is the only transport dependency of these
commands. It connects to the resolved AF_UNIX socket, verifies the local
protocol version and bounded frame, sends one typed operation with a
correlation ID, validates one strict allowlisted response, and closes. It does
not import Gateway code, start Node, start/reconnect an MCP server, connect to
Redis, or open SQLite, JSONL, state, artifact, or policy files.

The endpoint must already exist and pass the `D/0/05` peer/audience contract.
A missing path, non-socket path, refused connection, closed daemon, or deadline
returns `CONTROL_UNAVAILABLE`; the client does not auto-start the Gateway and
does not fall back to a database, audit file, public MCP request, Node helper,
or a second Gateway process. Reads may be retried only when the protocol
explicitly proves that no response was processed. `approval decide` is never
automatically retried.

Inventory/status map to `E/0/00`, approval list/show to `E/0/01`, and approval
decide to `E/0/02`; audit list/explain use this sheet's read-only projection on
the same `E/0/00` transport. The Python client contains no lifecycle reducer,
authorization rule, approval transition, digest builder, or audit parser.
Unknown response fields, oversized frames, invalid UTF-8, version/audience
mismatch, and malformed enums fail closed before rendering.

Every server cursor is bound to protocol version, control audience, operation,
effective filters, and page size. Reusing it with a different command,
`kind`, `includeRecent`, trace/type filter, or limit maps
`CONTROL_CURSOR_INVALID` to exit 2; an otherwise valid expired cursor maps
`CONTROL_CURSOR_EXPIRED` to exit 5. The client neither decodes nor repairs a
cursor and never restarts a listing silently.

## Informed decision flow

The canonical decision path is ordered and observable:

1. Fetch immutable approval detail and a fresh bound challenge over the
   control socket.
2. Validate the DTO and render approval ID, decision, action, repository,
   principal/target, canonical branch/ref, requested effect, expiry, challenge
   audience, and the **full algorithm-qualified context digest**. No field may
   be abbreviated, hidden by terminal width, or supplied from CLI arguments.
3. Require the exact phrase
   `DECIDE <decision> <approval-id> <context-digest>`.
4. Only after consent, resolve an external signer provider and give it the
   exact canonical challenge bytes owned by `E/0/02`.
5. Submit the signed envelope with the expected approval version and context
   digest. The server revalidates pending state, expiry, nonce, signature,
   audience, and digest and applies first-wins atomically.
6. Render the authoritative terminal outcome. A changed/stale/expired/already
   decided context is a conflict; the CLI never silently refreshes, resigns,
   or retries it.

Interactive decisions require a real controlling TTY. EOF, interrupt, an
incorrect phrase, or answering no exits without invoking the signer or
decision operation. `--json` only selects rendering and is never consent.
There is no `--yes`, `--force`, default grant, or inherited private-key option.
`--signer` is required before the preview request in both modes; interactive
execution never selects the first configured provider and has no default
provider.

Noninteractive use is allowed only when `--non-interactive`, the universally
required `--signer <provider-id>`, and the exact
`--confirm "DECIDE ..."` are present. Automation obtains the current phrase
for its selected decision from `approval show.confirmationTexts`; the decide
command fetches fresh detail and rejects a mismatch before signing. `--confirm`
without `--non-interactive`, or `--non-interactive` without `--confirm`, is
usage error.

Signer IDs resolve from
`$XDG_CONFIG_HOME/agents-orchestrator/signers.json` when
`XDG_CONFIG_HOME` is set to a non-empty absolute path, otherwise
`$HOME/.config/agents-orchestrator/signers.json`. A relative
`XDG_CONFIG_HOME`, or missing/non-absolute `HOME` when fallback is needed, is
exit 2; no repository/workspace search occurs. The file is operator-owned and
outside repository/workspace. D/0/05 excludes it from configured
`confined`/`workspace-yolo` mounts and inherited child configuration; this does
not make it unreadable to a same-UID `host-unconfined` process.

Configuration stores an argv array, never a shell string or private key. The
strict parser rejects duplicate provider keys, unknown fields, empty argv, and
non-string argv elements. The file must be a regular file owned by the
effective operator UID and not group/world-writable; an unsafe/malformed file
is exit 2. A syntactically valid provider absent from a valid file is exit 6.

The CLI invokes the selected provider without a shell, with a minimal
allowlisted environment and the frozen `--signer-timeout-ms` deadline; it
accepts only the strict signature envelope defined by `E/0/02`. A missing
config/executable, unknown provider, timeout, refusal/nonzero exit, or malformed
provider response is exit 6. Key material, signer stderr, canonical bytes,
signature bytes, and the optional note never enter CLI output, audit,
telemetry, or error text. The note, when present, is part of the signed
decision and is not echoed back as raw output.

The external signature plus server-side boot audience, context digest, nonce,
expiry, and first-wins checks remain the decision authority boundary. They are
not represented as a same-UID sandbox: an explicitly consented
`host-unconfined` process can inspect host resources and may be able to invoke
operator executables. Hardware/user-presence signers reduce that residual risk
but are not claimed as isolation. The operator must treat the separate
host-unconfined execution grant as acceptance of this residual exposure.

## Output and exit-code contract

Human output is deterministic plain text when redirected and uses color only
on a TTY while honoring `NO_COLOR`. At narrow widths (including 40 and 80
columns), records render as labelled vertical blocks. Values wrap; IDs, refs,
and full digests are never truncated. Control characters, bidi controls, ANSI
escapes, OSC hyperlinks, and embedded newlines are escaped before rendering.
Missing optional fields render as `-`; a missing required field is a protocol
error, never a guessed value or raw-object fallback.

`--json` writes exactly one compact UTF-8 JSON object plus newline to stdout
for success or failure and writes no banner, table, prompt, warning, or
traceback there. Interactive preview/prompt uses the controlling TTY/stderr.
The v1 envelope is:

```json
{"apiVersion":"agents-orchestrator/operator-cli/v1","command":"approval.show","ok":true,"data":{}}
```

or:

```json
{"apiVersion":"agents-orchestrator/operator-cli/v1","command":"approval.show","ok":false,"error":{"code":"CONTROL_UNAVAILABLE","message":"Operator control service is unavailable.","retryable":true}}
```

Each command has a strict DTO allowlist; the renderer constructs the envelope
field by field and never serializes an arbitrary server dictionary. Human-mode
errors are one bounded actionable line on stderr. Server, signer, OS, and
parser exception text, paths outside the selected socket, stack traces, raw
payloads, secrets, and unknown fields are never forwarded.

| Exit | Stable meaning |
|---:|---|
| `0` | A valid response was rendered and the requested operation completed. A successfully recorded `denied`/`cancelled` decision, or a fetched blocked/degraded status, is still exit 0. |
| `1` | The authenticated control service returned a safe non-conflict domain rejection. |
| `2` | CLI usage, required option, enum/range/bound/combination, cursor/filter binding, socket setting, or local non-secret configuration is invalid. No socket/signer access occurs for parse failures. |
| `3` | Control socket is absent, not a socket, refused, closed, or timed out. No fallback ran. |
| `4` | Protocol/version/audience/frame/DTO response is invalid or incompatible. |
| `5` | Approval or cursor is stale/expired; an approval was replayed, already decided, or changed after preview. No decision effect was applied by this invocation. |
| `6` | Required signer config/provider/executable is unavailable, or the signer times out, refuses, exits nonzero, or returns an invalid envelope. |
| `7` | Consent was not obtained: no TTY, EOF, interrupt, rejection, or phrase mismatch. |
| `70` | Unexpected local CLI failure, rendered safely without traceback or raw exception text. |

## Non-scope

- No direct read or write of SQLite, audit JSONL, artifacts, policies, Redis,
  Gateway state, or approval rows.
- No public MCP control command, MCP reconnect/restart, daemon auto-start,
  Node-helper fallback, generic query, raw audit/event view, or arbitrary
  server response renderer.
- No key path/key bytes in CLI flags or environment, agent-visible signer
  configuration, unsigned decision, implicit retry, or default auto-approval.
- No change to `coordination.*`, `message.*`, `agents:events`, or any MCP tool
  except the separately reviewed `E/0/02` removal of `approval.respond`.
- No claim that environment/mount exclusion hides the endpoint, signer
  configuration, process state, or host files from a same-UID
  `host-unconfined` process.
