## Why

The repository already mirrors sanitized audit metadata to `agents:events` and
stores trace-scoped messages in SQLite/Postgres. Neither mechanism gives
independent orchestrator processes leased identity, discovery, addressed
inboxes, acknowledgment, or direct queue access.

## Contract

The original reviewed slice added these MCP tools without changing the legacy
`message.*` contract:

1. `coordination.register`
2. `coordination.heartbeat`
3. `coordination.discover`
4. `coordination.unregister`
5. `coordination.send`
6. `coordination.receive`
7. `coordination.ack`

Expose the same operations as an importable service backed by a Redis adapter.
The Redis wire namespace is versioned and documented so trusted clients in
other languages can interoperate directly.

The current public surface also includes the additive read-only
`coordination.status` operation from [B/0/01](../../B/0/01.md). That follow-up
has its own TDD, commit, and review evidence and does not rewrite the historical
`A_0_0` verdict.

The KYA temporary artifact protocol remains semantically compatible:

- registration replaces the broadcast discovery role of `JOIN` and records
  version/base SHA/owned scope as participant metadata;
- `CHANGE_REQUEST`, `IMPACT_NOTICE`, `RESPONSE`, and semantic `ACK` are
  recommended `messageType` values;
- `correlationId` and `replyToMessageId` replace implicit artifact-thread
  polling, while artifact IDs, paths, evidence, and requested actions may remain
  in a JSON-encoded message body;
- `coordination.ack` is a transport acknowledgment and is distinct from a
  semantic `ACK` message; and
- ownership never transfers through the bus and no coordination message
  authorizes merge, review verdict, cleanup, or closure.

## Implementation plan

This file is the umbrella contract and final review unit. Execution is
decomposed into the epics and atomic TDD sheets defined in:

- [`../../EPICS.md`](../../EPICS.md)
- [`../../SHEETS.md`](../../SHEETS.md)

The binding order is:

1. E0 freezes the public and Redis wire contracts.
2. E1 implements and proves Redis-independent service semantics.
3. E2 implements and proves pending-safe Redis delivery.
4. E3 exposes the same service through direct and MCP access with safe JSONL
   audit.
5. E4 reconciles documentation, runs the complete verification gate, creates
   the scoped commit range, and obtains independent review.

No epic may weaken the whole-slice acceptance criteria below. The final
`A_0_0` review covers the complete tree and every sheet's evidence.

## Acceptance criteria

- [x] Two participants can register, discover one another, exchange messages in
      both directions, and acknowledge them.
- [x] Expired participants disappear from discovery and cannot send, receive,
      heartbeat, or acknowledge.
- [x] Stale credentials cannot mutate, read, or acknowledge a replacement
      participant that reuses the same public ID; Redis compares the expected
      token digest and scope at the authoritative operation.
- [x] A wrong lease token, unknown recipient, cross-recipient acknowledgment,
      oversized body, `restricted` classification, and detected secret are
      rejected with structured errors.
- [x] Unacknowledged messages can be recovered after the configured idle time.
- [x] Duplicate `messageId` sends are idempotent for the same sender within the
      configured dedupe window, return the original delivery ID, renew that
      window on an equal retry, and fail closed when the envelope differs.
- [x] The metadata event Stream contains no body or lease token.
- [x] Coordination domain audit and generic coordination MCP-call audit remain
      JSONL-only; they do not add entries to legacy `agents:events`.
- [x] With no Redis URL, coordination tools return
      `COORDINATION_UNAVAILABLE`; unrelated Gateway tools still work.
- [x] MCP and direct service calls share one implementation and produce the same
      wire format.
- [x] `agents:events` and legacy `message.*` semantics remain unchanged.
- [x] The relevant tests and the repository CI gate pass.

## Security boundary

Queue messages never grant authority and never trigger tools automatically.
Consumers must treat bodies as untrusted input. Direct Redis clients are inside
a trusted-local data-plane boundary and cannot claim Gateway policy enforcement;
deployments outside that boundary must use dedicated Redis ACL credentials,
TLS, network isolation, and separate namespaces.
