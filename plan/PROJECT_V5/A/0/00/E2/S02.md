# V5 E2/S02 — Atomic send, dedupe, and inbox backpressure

Status: **complete**

Depends on: E2/S01 and E1/S04.

## Goal

Append an addressed delivery only when both participants still match their
fences and the inbox has capacity.

## Write scope

- send Lua and adapter method
- focused send/dedupe/capacity tests

## RED

Sender/recipient replacement, sender ID collision, changed retry, original
delivery loss, window expiry, or blind trimming can occur.

## GREEN

One atomic operation validates both fences, applies `XLEN` backpressure without
`MAXLEN`, stores `{envelope,deliveryId}` with PX, renews equal retries, and
emits metadata only.

## Evidence

- full adapter fake suites through send — 39 tests passed
- Redis 7.2 live adapter suite — 41 tests passed
- dual-fence, semantic-field, corrupt-dedupe, TTL, conflict, expiry, and capacity cases
- maximum-ID best-effort metadata and body/digest leak assertions
