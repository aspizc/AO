# C/0/02 — Candidate identity, promotion-state validation, and dependency waivers

| Field | Value |
|---|---|
| Status | `planned` |
| Functional priority | P0 — release identity and supply-chain gate |
| Depends on | `C/0/00` |
| absorbed_from | V4 `M0/0/00`, `M0/3/00`, `M0/4/02` (V4 specification provenance; behavior not yet implemented) |
| Review id | `C_0_2` |

## Problem

Review, integration, promotion, and release claims can refer to different trees,
locks, suites, or tags, while dependency risk can be hidden behind an
unstructured or stale waiver.

## Scope

- Define one machine-readable candidate manifest with full commit/tree identity,
  base and branch, runtime and lock digests, suite/skip inventory, and review
  evidence digests.
- Validate distinct `planned`, `implemented`, `reviewed`, `integrated`,
  `promoted`, and `released` states against repository refs and immutable
  evidence; no state is inferred from prose or another state.
- Scan the complete production dependency graph from reproducible locks and
  reject lock drift, missing locks, and every unaccepted high/critical finding.
- Require each accepted advisory to bind package/advisory, candidate and lock
  digest, owner, reachability rationale, compensating control, and expiry.

## Non-scope

- No automatic tag, push, publication, dependency-major upgrade, or readiness
  claim based only on a checklist/review filename.

## TDD RED

Exercise abbreviated or mixed SHAs, changed tree/lock/review evidence,
contradictory refs/status/checklists, tag outside the candidate, a new
production advisory, and waivers that are expired, ownerless, overbroad, or
bound to another lock.

## TDD GREEN

Add the candidate/state schemas and validator, deterministic ref/evidence
collector, lock/SCA manifest, and narrowly scoped waiver registry.

## Acceptance criteria

- [ ] Every candidate field and evidence item resolves to one full commit/tree.
- [ ] State advancement is explicit, ordered, and independently verifiable.
- [ ] Reproducible locks cover every installed production dependency.
- [ ] No high/critical advisory passes without a current candidate-bound waiver.
- [ ] Review, ref, tag, lock, or waiver drift blocks promotion.

## Verification

Run candidate/state/ref contradiction fixtures, clean lock installs, the
production SCA/waiver suite, and release-validator structure tests; then
`bash scripts/ci.sh` and `git diff --check`.
