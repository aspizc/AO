## Problem

Tool lists, prompts, handwritten documentation, runtime validators, and MCP
error envelopes can drift, making the product impossible to call reliably.

## Scope

- Establish one typed catalog as authority for names, schemas, descriptions,
  availability, and domain-to-MCP error mapping.
- Generate or bidirectionally verify every prompt/doc/schema projection.
- Preserve structured domain code/details through the MCP envelope without
  leaking payloads or credentials.

## Non-scope

- No compatibility-breaking removal before a versioned migration/cutover and
  no policy broadening through schema generation.

## TDD RED

Introduce drift fixtures for tool count/name, required fields, numeric bounds,
prompt examples, description semantics, unknown error, and secret-bearing
error details.

## TDD GREEN

Build the catalog/projection validator and one safe domain-error serializer
used by every tool handler.

## Acceptance criteria

- [x] Runtime validation and published schema are structurally equivalent.
- [x] Prompts/examples mention only registered tools and valid arguments.
- [x] Domain codes survive MCP calls with safe field-specific detail.
- [x] Catalog drift fails CI before release.

## Verification

Run tool-registry, schema-projection, prompt-contract, error-envelope,
bootstrap, and structure tests; then `bash scripts/ci.sh` and
`git diff --check`.
