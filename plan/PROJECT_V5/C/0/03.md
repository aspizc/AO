## Problem

The suite can remain green while production hotspots lose branch coverage,
high-risk mutants survive, layer boundaries erode, or mutable process-global
state makes interaction tests serial and timing-sensitive. A prose target or a
diagnostic report is not a release gate.

## Scope

- Freeze a candidate-bound hotspot manifest whose initial required entries are
  `coordination_queue.js` and `coordination_service.js` under
  `gateway/src/services/`, plus every additional production hotspot named by
  the reviewed audit inventory. Each entry records its owned invariants,
  public/wire surface, characterization suite, façade, extracted modules, and
  immutable before/after metrics.
- Start from the reviewed G/0/01 client-lifecycle result so extraction does not
  race or erase its behavior. Completed G/0/01 remains supporting evidence
  only; C/0/03 remains the accountable decomposition owner.
- Rebaseline the final candidate-bound source and suite inventories only after
  G/0/02 ACK reconciliation is independently OK. C/0/03 may characterize
  fitness semantics earlier, but it cannot authenticate, review, or integrate
  an extraction candidate against ACK code that remains KO.
- Characterize the current coordination wire responses, Redis key/fence/
  lifetime behavior, lifecycle transitions, audit projections, failure codes,
  and race outcomes before extraction. Decompose both named hotspots along
  those tested seams without changing the public `coordination.*`,
  `message.*`, or `agents:events` contracts.
- Enforce explicit module rules: the queue façade may depend only on focused
  codec/key, presence/lease, send/dedupe, receive/reclaim, and ACK/tombstone
  modules; the service façade may depend only on validation, presence,
  discovery, messaging, and lifecycle application services. Extracted modules
  cannot import either façade, tool adapters, server entry points, or
  composition roots, and the declared extraction graph must remain acyclic.
- Require at least a 50% logical-line reduction in each original hotspot, cap
  every resulting production module at 500 logical lines, cap hotspot
  functions at cyclomatic complexity 15, and cap each façade function at 5.
  Across each transitive extraction set, aggregate cyclomatic complexity and
  duplication may not increase from the locked RED baseline; copying logic
  behind a forwarding façade is therefore a failing result.
- Add candidate-bound source and changed-line coverage gates over production
  code only, with minimums of 85% lines and 75% branches.
- Add focused mutation gates for policy, approval, result parsing, lifecycle,
  idempotency, and authorization. The versioned minimum score is 80%, and no
  seeded High/Critical boundary mutant may survive.
- Enforce a checked dependency direction from tool adapters through application
  services to repositories/adapters, with construction confined to reviewed
  composition roots.
- Ratchet versioned file/function complexity and dependency-cycle baselines
  outside the mandatory hotspot reductions; a waiver cannot exempt a named
  hotspot from decomposition or raise its closure budgets.
- Require injectable state, clock, scheduler, process, and transport seams in
  affected critical modules; wall-clock assertions remain hang sentinels, not
  correctness or scheduling oracles.
- Publish one machine-readable fitness result bound to the same candidate,
  source manifest, suite inventory, and waiver rules as `C/0/00` and `C/0/02`.

## Non-scope

- No 100% global coverage target, framework rewrite, production refactor solely
  to satisfy a metric, self-refreshing baseline, coverage of tests as product
  code, waiver inferred from a review comment, public wire redesign, or
  complexity relocation into a façade or renamed monolith.

## TDD RED

First lock characterization fixtures for the named coordination hotspots.
Then demonstrate the existing monoliths, a copied/renamed monolith, a
forwarding façade that retains invariant logic, a missing hotspot-manifest
entry, a forbidden reverse import, and an extraction cycle passing the current
ratchet. Also demonstrate a removed authorization branch, surviving approval/
lifecycle mutant, new mutable singleton, complexity regression, changed line
without coverage, wall-clock-only oracle, and result bound to another tree.

## TDD GREEN

Add characterization-preserving hotspot extraction, the immutable hotspot
manifest, declared module graph, logical-line/complexity/duplication budgets,
and no-relocation validator. Add deterministic source/diff coverage, focused
mutation, seam, and candidate-binding validators. Commit immutable policy
baselines separately from generated observations and require explicit,
expiring waivers only for work outside the mandatory hotspot closure.

## Acceptance criteria

- [ ] Production source and changed-line coverage meet 85% lines/75% branches.
- [ ] Focused mutation score is at least 80% and no seeded critical mutant survives.
- [ ] The hotspot manifest covers both named coordination files and every
      additional reviewed-audit hotspot, with characterization evidence bound
      to the candidate.
- [ ] Each original hotspot is at least 50% smaller and no resulting module
      exceeds 500 logical lines; hotspot functions are at most complexity 15
      and façade functions at most 5.
- [ ] The transitive extraction set does not increase aggregate complexity or
      duplication, and no invariant is copied or moved into a façade.
- [ ] Required module directions, forbidden imports, dependency cycles, and
      new mutable global seams fail CI.
- [ ] Timing-oracle regressions fail against the reviewed baseline.
- [ ] Every result and waiver is complete, candidate-bound, and machine-verifiable.

## Verification

Run the pre/post coordination characterization and race suites, hotspot
manifest/completeness check, logical-line/complexity/duplication budgets,
facade-copy and reverse-import fixtures, production coverage and focused
mutation lanes, deterministic clock/scheduler tests, candidate identity
mutation cases, `bash scripts/ci.sh`, and `git diff --check`.
