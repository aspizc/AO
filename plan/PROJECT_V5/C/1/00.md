## Problem

Task/session state is mutated through multiple paths, so caller assertions,
process observations, approvals, and completion can disagree or reopen terminal
work.

## Scope

- Define one task/session state model and pure reducer with versioned,
  server-owned transition commands.
- Reserve `starting` before launch; persist idempotency keys and transition
  evidence; make terminals monotonic.
- Route all current lifecycle mutations through the reducer/repository boundary.

## Non-scope

- No synchronous or asynchronous process supervisor, FIFO helper,
  guardian/reaper, Python runtime selection, shell/argv construction,
  process-group or descendant cleanup, cancellation, process budget, process
  sandbox, signed approval, review gate, or Temporal orchestration in this
  sheet. Process execution is owned exclusively by `D/0/01`.

- The action-specific lifecycle port carries a stable idempotency key from its

  PostgreSQL, and the fake. It is non-negative, monotonic under JavaScript
  arithmetic, and representable by both durable backends; PostgreSQL state
  and status constraints must match SQLite.
- After any persistence conflict, including a concurrent
  `SESSION_RESERVE` primary-key race, the repository rechecks the durable
  idempotency winner. An exact winner converges; a different request or
  unrelated conflict remains a static fail-closed error.
