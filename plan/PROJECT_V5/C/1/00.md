## Problem

Task/session state is mutated through multiple paths, so caller assertions,
process observations, approvals, and completion can disagree or reopen terminal
work.

## Scope

- Define one task/session state model and pure reducer with versioned,
  server-owned transition commands.
- Reserve `starting` before launch; persist idempotency keys and transition
  evidence; make terminals monotonic.
- Route all current lifecycle mutations through the reducer/repository boundary.

## Non-scope

- No process sandbox, signed approval, review gate, or Temporal orchestration in
  this sheet.

## TDD RED

Fail invalid/replayed/out-of-order transitions, caller-supplied terminal state,
cross-task/session transition, launch-before-reserve, and terminal reopen.

## TDD GREEN

Implement the reducer, optimistic version check, command handlers, migrations,
and adapters from existing service operations.

## Acceptance criteria

- [ ] One reducer decides every persisted lifecycle transition.
- [ ] Callers request actions but cannot assert effective state.
- [ ] Exact retries are idempotent; conflicting retries fail closed.
- [ ] Terminal sessions/tasks cannot silently reopen.

## Verification

Run reducer table tests, repository/migration tests, service lifecycle tests,
and existing task/session suites; then `bash scripts/ci.sh` and
`git diff --check`.
