## Problem

Expired registry entries, orphan inboxes, tombstones, dedupe/DLQ data, and
unbounded clients/messages can accumulate without safe operational visibility.

## Scope

- Add leader-safe/idempotent reaping and documented retention windows.
- Enforce per-scope/participant inbox, pending, body-byte, DLQ, and rate quotas
  without trimming unacknowledged data.
- Register coordination health, backlog, retry, age, quota, and cleanup as the
  fixed `coordination` flow in the E/0/04 metadata-only exporter; do not create
  a second metric transport, label contract, cursor, or readiness reducer.

## Non-scope

- No message body/token in telemetry, broad Redis scan/delete, acknowledged-data
  retention promise beyond configured windows, or silent data loss.

## TDD RED

Advance fake time through active/expired/pending/orphan/tombstone/DLQ cases,
race two reapers, exceed every quota, reject an unregistered metric/label, and
inject secret-bearing metadata.

## TDD GREEN

Implement indexed bounded cleanup, safe quota checks, and the E/0/04
allowlisted coordination metric-source adapter.

## Acceptance criteria

- [ ] Cleanup never removes active or unacknowledged delivery state.
- [ ] Storage/rates are bounded with explicit structured errors.
- [ ] Concurrent/restarted reaping is idempotent.
- [ ] Metrics reveal health/backlog without bodies, tokens, or credentials.
- [ ] Coordination metrics use E/0/04's durable exporter and fixed flow/labels.

## Verification

Run fake-clock reaper/quota/metric leak tests and long-running Redis churn lane;
then `bash scripts/ci.sh` and `git diff --check`.
