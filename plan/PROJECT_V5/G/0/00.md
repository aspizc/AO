## Problem

Optional live tests and single-client fakes cannot validate Redis version,
atomic fences, pending delivery, dedupe, ACK, or replacement-incarnation races.

## Scope

- Add a required ephemeral Redis 7 lane with isolated namespace and readiness.
- Run multiple independent clients through lease replacement, concurrent send,
  dedupe conflict/equality, reclaim, ACK/tombstone, expiry, and failure races.
- Fail on skip, wrong Redis version/topology, zero tests, or leaked test keys.

## Non-scope

- No use/flush/restart of shared Redis, cluster support claim, or secret-bearing
  test payload.

## TDD RED

Introduce deterministic race schedules that expose missing digest/scope fence,
trimmed pending delivery, sender aliasing, partial ACK, and false skipped green.

## TDD GREEN

Ship the isolated Redis harness and required CI service/lane with bounded
cleanup and exact protocol assertions.

## Acceptance criteria

- [x] Redis 7 standalone is exercised as required CI, not an opt-in skip.
- [x] Multi-client races preserve lease, dedupe, pending, and ACK invariants.
- [x] Test namespaces are isolated and cleaned without broad destructive ops.
- [x] Failure reports unavailable infrastructure separately from assertion fail.

## Implementation evidence

- The governed suite topology promotes `test.redis-live` to `required` while
  retaining a readiness condition. Missing `AGENTS_TEST_REDIS_URL` reports
  `infrastructure_unavailable` and returns nonzero without running a skipped
  test; an unselected optional service keeps its existing honest exit policy.
- Each GitHub Actions Node matrix job owns a health-checked
  `redis:7.2-alpine` service on loopback. The live tests assert Redis 7,
  standalone/non-cluster primary topology, and exact namespace cleanup.
- The repeated race matrix uses four independent service/client factories for
  six equality/conflict schedules, then covers pending-safe capacity, reclaim,
  all-or-nothing ACK, tombstone retry, replacement, connection-loss, and
  expiry-at-mutation boundaries.
- A final read-only live-lane guard fails if any `agents:test:v5:*` key remains.
  No shared Redis process, namespace, restart, or broad cleanup is used.
- The final offline authoritative gate exited zero with 1,097 tests: 1,085
  passed, 12 exact pre-existing infrastructure skips, and zero failures.
  `test.redis-live` contributed 9/9 passed with zero skips; the aggregate
  remained honestly `infrastructure_unavailable` for the allowlisted
  PostgreSQL/Gateway/Temporal cases and unselected real-agent lane.
