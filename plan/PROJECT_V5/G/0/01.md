## Problem

A disposable Redis connection per operation is simple but costly and lacks an
explicit reconnect, bounded concurrency, draining, and shutdown contract.

## Scope

- Introduce owned persistent command/blocking clients with lazy connect,
  reconnect state, bounded queues, backpressure, health, and graceful shutdown.
- Preserve operation-level isolation/fencing and explicit unavailable errors.
- Keep test/direct factory ownership and process signal handling deterministic.

## Non-scope

- No infinite request queue, hidden retry of non-idempotent operations, global
  singleton across test/Gateway instances, or shared-server restart.

## TDD RED

Cover concurrent connect, connection drop mid-command/block, queue saturation,
shutdown during receive, reconnect storm, double close, and listener/client
leaks.

## TDD GREEN

Implement a per-service client lifecycle/pool with bounded scheduler and clear
retry classification.

## Acceptance criteria

- [ ] Healthy operations reuse owned connections.
- [ ] Backpressure rejects/bounds work before memory grows unbounded.
- [ ] Reconnect never duplicates a non-idempotent semantic operation.
- [ ] Shutdown drains/cancels boundedly and leaves no handles.

## Verification

Run fake-client lifecycle/fault/leak tests and the Redis 7 concurrent lane; then
`bash scripts/ci.sh` and `git diff --check`.
