## Problem

Transport receive/ACK primitives do not define how a long-running consumer
handles transient failure, poison messages, crash recovery, or safe replay.

## Scope

- Add a supervised consumer runner with bounded retry/backoff, attempt metadata,
  poison threshold, body-safe DLQ record, and authorized replay.
- Verify participant/trace/scope context and idempotent business consume before
  transport ACK.
- Expose health/backlog/degraded state to operator inventory.

## Non-scope

- No automatic execution of message instructions, infinite poison loop, raw
  body in metrics/audit/DLQ metadata, or unauthenticated replay.

## TDD RED

Cover crash before/after consume/ACK, including the real
`prepareAck -> XACK/XDEL -> commitAck` loss window; transient handler error,
malformed/poison envelope, duplicate delivery, stale lease, participant
identity loss/rejoin, shutdown, DLQ replay mismatch, and message-carried
authority.

## TDD GREEN

Implement the abortable runner, retry classifier, durable consume receipt/DLQ
metadata, and operator-authorized replay command.

### ACK reconciliation design decision

The existing durable `acknowledging` transition becomes a private, enumerable,
claim-fenced ACK outbox. A new migration after the reviewed STORE baseline
adds intent state, monotonic claim epoch/token, due time, closed proof/reason
codes, and bounded cursor indexes. It does not reopen the STORE migration,
persist a lease token, duplicate message bodies/locators, or change the public
receipt projection.

The repository port must support bounded intent enumeration, claim/renew,
confirmed commit, defer, and `recovery_required`. Only a current claim token
may settle an intent. Confirmation atomically records one closed proof:

- `DIRECT_ACK` when the live managed-client incarnation received ACK success;
- `ACK_TOMBSTONE` when an internal Redis inspection proves the existing
  recipient-scoped tombstone; or
- `ORPHAN_ACK` when an internal atomic finalizer proved the old participant
  absent, validated the exact PEL/envelope identity, and performed the
  recipient's `XACK/XDEL` plus tombstone.

Tombstone inspection and orphan finalization are queue-internal operations,
never service, tool, MCP, or caller authority. They bind exact scope, old
participant, delivery, message, and receipt identity; return no body; and fail
closed on corrupt or ambiguous Redis state. If the old presence remains live,
reconciliation defers. If neither tombstone nor the exact PEL entry exists,
the intent becomes `TRANSPORT_STATE_UNKNOWN`/recovery-required and the receipt
must not become completed.

#### Trial 1 KO and Trial 2 correction gate

ACK_RECONCILIATION_CORE Trial 1 preserves its request and independent KO result
at `76e63cf` and `075c1ed`. The code candidate is not integrated. Trial 2 must
close all four reviewed P1 findings before the SQLite outbox or WIRING starts:

- Every dependency DTO (page, intent, claim, renewal, status, queue reply, and
  summary) is converted once into a closed own-data snapshot. Accessor-backed
  fields are rejected, and validation plus branching/projection consume only
  that snapshot; no validated caller object is reread.
- `claim` repeats reconcilable-state and `dueAt <= now` checks under the same
  mutation authority as its epoch/token update. It returns closed
  `not_due`, `committed`, and `recovery_required` outcomes for stale list
  races without changing state. The reconciler treats those outcomes as
  bounded no-ops rather than aborting the page or defeating backoff.
- The public queue object cannot mint or reveal the Redis recovery facet.
  Trusted runtime composition receives the facet exactly once and injects it
  into the reconciler; ordinary queue holders, services, tools, and MCP callers
  have no method, property, exported helper, or discoverable capability that
  yields tombstone inspection or orphan finalization.
- Tombstone inspection distinguishes a genuine transport failure from corrupt
  Redis state. Wrong-type tombstones and malformed/partial presence records
  become `TRANSPORT_STATE_UNKNOWN`; only a complete canonical live old
  presence may defer as `old_participant_present`.

Trial 2 also resolves the reviewed P2 before durability: arbitrary proof
strings do not cross producer boundaries. Direct ACK and reconciler settlement
use distinct narrow facets with fixed commit operations, so only the direct
consumer can record `DIRECT_ACK` and only the reconciliation facet can record
the tombstone/orphan proof selected from its validated transport snapshot.

The new RED set includes toggling/accessor DTOs, summary projection, two
reconcilers over one stale list, stale-list-after-defer, terminal/not-due
claims, public-facet reachability, wrong-type tombstones, partial/corrupt
presence, repeated corrupt-state convergence, and producer/fixed-proof
separation. Fake tests use no socket; any later live Redis evidence remains
isolated and non-authoritative until the durable slice is independently OK.

#### Trial 2 KO and Trial 3 correction gate

Trial 2 preserves its request and independent KO result at `80ddcbe` and
`11f3d4a`. Its code remains unintegrated. Trial 3 keeps the verified
single-snapshot, due/stale CAS, fixed-proof, typed-tombstone, and pure
build/decode corrections, but must close the two formal-review P1 findings
and the independently reproduced cross-facet settlement gap:

- An ordinary `RedisCoordinationQueue` must not expose a managed Redis client
  through an own/prototype property, lane, callback executor, factory, URL, or
  options object. Client factories/options, command and blocking lanes, and
  raw-client dispatch are language-private or module-private. Public queue
  possession exposes only constrained queue operations and safe frozen
  projections.
- Orphan finalization treats only a complete, canonical, positively leased
  presence as live. It verifies the original JSON container token kinds for
  `capabilities` and `metadata` (or an equivalently exact unambiguous storage
  representation), requires positive `PTTL`, and maps empty wrong-container
  shapes, persistent keys, partial records, and other deterministic corruption
  to `TRANSPORT_STATE_UNKNOWN`.
- Direct-ACK and reconciliation claims are domain-separated, not merely
  co-returned method names over the same owner/token. A claim minted through
  `directAck` cannot commit `ACK_TOMBSTONE`/`ORPHAN_ACK`, and a reconciliation
  claim cannot commit `DIRECT_ACK`; rejected cross-facet attempts mutate no
  receipt, intent, proof, counters, or audit projection.

The directed RED starts from only an ordinary queue plus public module exports
and proves that no reachable value can receive the managed client or execute
either recovery command. Presence REDs cover empty-object capabilities,
empty-array metadata, a persistent canonical-looking key, complete leased
presence, and repeat convergence. Repository REDs cover direct-claim to both
recovery commits and reconciliation-claim to direct commit, including
same-owner/token reuse. No public helper may weaken the client boundary merely
to make the fake executable.

#### Trial 3 KO and Trial 4 correction gate

Trial 3 preserves its request and independent KO result at `1f72913` and
`50dfa3d`. Its technical candidate remains unintegrated. Trial 4 retains the
single-snapshot/CAS, claim-family, positive-presence-lease, and recursive
duplicate-presence corrections, plus the lint hygiene, while closing all four
reviewed P1 findings:

- `RedisCoordinationQueue.lifecycle()` cannot invoke an
  attacker-replaceable method on a privileged lane. Starting with only an
  ordinary queue and public module exports, no prototype replacement,
  projection substitution, or object traversal may yield a lane, factory,
  URL/options, raw client, or callback executor.
- Direct ACK, tombstone inspection, and orphan finalization accept a
  tombstone only when its type/value are exact and `PTTL` is numeric and
  strictly positive. Missing, persistent, expired/non-positive, wrong-type,
  and wrong-value states remain distinct and fail closed before settlement.
- Every raw JSON validation path has a reviewed byte ceiling and shared
  token/work budget. Wide flat containers and long strings cannot make an
  atomic Redis Lua script perform unbounded work; depth alone is not a work
  bound.
- Stored stream envelopes receive the same bounded decoded-key duplicate
  rejection as presence before `cjson.decode`. Ambiguous top-level or nested
  keys perform no `XACK`, `XDEL`, tombstone write, repository commit, defer,
  or recovery success.

Trial 4 RED must reproduce raw `ECHO` execution through the lifecycle lane,
positive versus persistent tombstones across all three operations,
byte/token/depth boundary matrices, and escaped duplicate keys across every
canonical envelope field and nested body objects/arrays. Its GREEN keeps
parsing and destructive settlement within one atomic, fail-closed command.
Only a new source-only candidate and independent OK result can unblock durable
migration `003`, WIRING, or C/0/03's final candidate-bound fitness artifact.

The implementation explicitly rejects these shortcuts:

- `commitAck` before transport ACK, because it would make `ackedAt` and
  completion claims before `XACK/XDEL`;
- persistence of the private lease token, which expands secret/backup scope
  and still fails after lease expiry; and
- rebind or implicit inheritance by a new participant ID, which would weaken
  inbox ownership and fencing.

The focused live lane must cover lost ACK response, crash after real
`XACK/XDEL`, tombstone confirmation, old-presence/expiry races, exact orphan
finalization, retry idempotency, and the unknown-state terminal. It uses only
an isolated disposable Redis namespace; all outbox CAS, cursor, corruption,
and secret-leak cases run against fakes and SQLite.
