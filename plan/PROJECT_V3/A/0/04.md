## Por que existe?

Quedan restos de una iteracion anterior: directorios `.git/` vacios dentro de
`gateway/`, `docs/` y `orchestrator-langgraph/` que confunden (parecen
submodulos o repos anidados y no lo son). La parte del hallazgo D3 sobre
ficheros sin trackear debe verificarse, no asumirse: `plan_proyecto_v4.md`,
`tareas_implementacion_v4.md` y `docs/pending-implementation-items.md` deben
estar en `git ls-files` antes de cerrar esta tarea.

## Que hay que hacer?

Eliminar los tres `.git/` vacios y documentar la ubicacion canonica de los
docs v4 historicos (se quedan en la raiz: `plan/PROJECT_V0/README.md` y
`plan/PROJECT_V1/README.md` los enlazan como `../../plan_proyecto_v4.md`).

## Plan de implementacion paso a paso

### 1. Branch

```bash
git checkout develop && git pull --ff-only || true
git checkout -b feature/V3-A-0-4-tree-hygiene
```

### 2. Eliminar restos

Antes de borrar, verificar que estan realmente vacios (solo `.` y `..`):

```bash
ls -la gateway/.git docs/.git orchestrator-langgraph/.git
rmdir gateway/.git docs/.git orchestrator-langgraph/.git
```

`rmdir` (no `rm -rf`) como salvaguarda: falla si tuvieran contenido.

### 3. Documentar los docs v4

Anadir a `plan/README.md` una nota breve: `plan_proyecto_v4.md` y
`tareas_implementacion_v4.md` son la spec historica V4 en castellano que
origino Project V0; viven en la raiz porque los README de V0/V1 las enlazan
con rutas relativas; no se mueven ni se actualizan.

### 4. Verificacion

```bash
find . -name .git -type d -not -path ./.git   # sin resultados
git ls-files plan_proyecto_v4.md tareas_implementacion_v4.md docs/pending-implementation-items.md
./scripts/ci.sh
```

## Detalle adicional de ejecucion

  directorio `.git` anidado. Si alguno tiene contenido real, parar y crear
