## Por que existe?

No existe ninguna configuracion de linting ni formateo en el repo (ni
eslint/prettier en `gateway/package.json`, ni ruff/black/mypy en los
`pyproject.toml`). La calidad de estilo depende solo de la disciplina manual,
y los stages B-D van a tocar codigo Python y JS: conviene que el gate detecte
problemas mecanicos antes de esos cambios.

## Que hay que hacer?

Anadir ruff (cli + orchestrator-langgraph) y eslint flat-config (gateway) con
reglas conservadoras, cablearlos a `scripts/ci.sh`, y aplicar un autofix
inicial acotado (sin reformateo masivo).

## Plan de implementacion paso a paso

### 1. Branch

```bash
git checkout develop && git pull --ff-only || true
git checkout -b feature/V3-A-0-2-lint-gate
```

### 2. ruff (Python)

- Anadir `ruff>=0.4` al grupo dev de `cli/pyproject.toml` y crear el grupo
  dev equivalente en `orchestrator-langgraph/pyproject.toml`.
- Configurar `[tool.ruff]` en ambos: `target-version = "py311"`, select
  conservador (`E`, `F`, `I`, `W`) — sin reglas de formateo agresivas en esta
  primera pasada.
- `ruff check cli orchestrator-langgraph tests` y arreglar lo que salga
  (esperable: imports sin usar, orden de imports). Autofix solo con
  `ruff check --fix` para reglas seguras; revisar el diff a mano.

### 3. eslint (gateway)

- `eslint` flat config moderno como devDependency de `gateway/package.json`,
  con `@eslint/js` recommended y ajustes para ESM node (`ecmaVersion`,
  `globals.node`). Crear `gateway/eslint.config.js`.
- Script npm: `"lint": "eslint src tests ../tests/gateway ../tests/e2e ../scripts"`
  (ajustar paths segun lo que resulte razonable; minimo `gateway/src`).
- Pasada inicial: corregir findings o desactivar reglas concretas con
  justificacion en el config (no inline-disable masivo).

### 4. Cablear a `ci.sh`

Nueva seccion antes de los tests:

```bash
echo "==> Lint (ruff + eslint)"
ruff check cli orchestrator-langgraph
npm --prefix gateway run lint
```

### 5. Verificacion

`./scripts/ci.sh` verde; introducir un import sin usar en un fichero Python y
un `var` sin usar en gateway, comprobar que el gate falla, revertir.

## Detalle adicional de ejecucion

- Hacer primero una pasada read-only de lint para medir la deuda antes de
  aplicar autofix; anotar cualquier regla desactivada en la review.
- No incluir `plan/**`, `workspace/**`, lockfiles generados o artifacts en
  eslint/ruff salvo que haya una razon explicita.
- El script `npm --prefix gateway run lint` debe ser estable en un clone
  fresco usando `npm ci`; por tanto `gateway/package-lock.json` se actualiza
  junto con `package.json`.
- Para ruff, preferir `ruff check` sobre `ruff format` en V3 A/0/2. Si una
  regla produce mucho churn, desactivarla en config con comentario y abrir
  follow-up si procede.
- En la review, separar cambios de configuracion de lint de cambios mecanicos
  de autofix para que el reviewer pueda detectar cualquier cambio logico.

## Errores comunes

- ❌ Activar prettier/black o reglas de formato global en esta pasada: el
  objetivo es lint semantico conservador, no un re-format del repo.
- ❌ Silenciar findings con `// eslint-disable` linea a linea: si una regla no
  encaja con el codebase, se desactiva en el config con comentario.
- ❌ Cambiar comportamiento al "arreglar" un finding (p.ej. eliminar una
  variable que en realidad documentaba un TODO): ante la duda, regla off.

## Verificacion: Gateway contract inmutable

Los fixes de lint no deben cambiar logica: `npm --prefix gateway test` y
todas las suites del gate quedan verdes sin modificar ningun test.
