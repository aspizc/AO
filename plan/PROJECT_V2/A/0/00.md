# W/0/0 - Nullable session task migration

## Quick reference

| Campo | Valor |
|---|---|
| Stage | W - Task-less sessions |
| Branch | `feature/W-0-0-nullable-session-task` |
| Depende de | K/0/3, F/0/1, F/0/2 |
| Esfuerzo | M (3-5h) |

## Por que existe?

La tabla `sessions` exige `task_id TEXT NOT NULL`. Por eso `K/0/3` tuvo que
hacer obligatorio `taskId` en `agent.delegate` y `agent.spawn`; si no, el
Gateway podia devolver un `sessionId` que no existia en SQLite y despues
`ask/view/kill` fallaban con `unknown session`.

Para soportar sesiones sin tarea de forma correcta, primero hay que cambiar el
contrato persistente.

## Que hay que hacer?

Crear una migracion idempotente que permita `sessions.task_id = NULL`, mantener
la FK cuando haya task, y actualizar repository/tests para round-trips con y
sin task.

## Plan de implementacion paso a paso

### 1. Branch

```bash
git checkout develop && git pull --ff-only || true
git checkout -b feature/W-0-0-nullable-session-task
```

### 2. Tests rojos primero

Actualizar `tests/gateway/sqlite_migrations.test.js` y
`tests/gateway/domain_repositories.test.js`:

- una session puede insertarse con `taskId: null`;
- una session con `taskId` invalido sigue fallando por FK;
- una session con `taskId` valido sigue funcionando;
- `listSessionsByTrace` devuelve ambas.

### 3. Migracion

Crear `gateway/migrations/002_nullable_session_task.sql`.

SQLite no puede relajar `NOT NULL` con un simple `ALTER COLUMN`, asi que usar
patron de rebuild transaccional:

1. Crear `sessions_new` con la misma estructura pero `task_id TEXT REFERENCES
   tasks(task_id) ON DELETE CASCADE` nullable.
2. Copiar datos existentes.
3. Dropear `sessions`.
4. Renombrar `sessions_new` a `sessions`.
5. Re-crear indices necesarios.
6. Registrar `002_nullable_session_task`.

Verificar que la migracion es idempotente bajo el migrator existente.

### 4. Repository contract

Actualizar `gateway/src/core/repositories/session_repo.js` solo si hace falta:

- aceptar `taskId: null`;
- no convertir `null` a `undefined`;
- mantener nombres de columnas sin mapper innecesario.

## Errores comunes

- Perder filas existentes durante rebuild.
- Eliminar la FK para sesiones con `task_id` no null.
- Romper DBs ya migradas con `001_initial`.
- Cambiar el contrato de `tasks`; esta tarea solo toca `sessions`.
