# W/0/1 - Task-less agent tool semantics

## Quick reference

| Campo | Valor |
|---|---|
| Stage | W - Task-less sessions |
| Branch | `feature/W-0-1-taskless-agent-tools` |
| Depende de | W/0/0, K/0/3 |
| Esfuerzo | M (3-5h) |

## Por que existe?

Tras W/0/0, SQLite ya puede persistir sesiones sin task. Ahora hay que relajar
la API MCP que K/0/3 hizo estricta por seguridad: `agent.delegate` y
`agent.spawn` deben aceptar `taskId` opcional sin crear sesiones huerfanas.

## Que hay que hacer?

Actualizar tools y `AgentService` para que:

- `taskId` sea opcional en `agent.delegate` y `agent.spawn`;
- toda sesion se persista aunque `taskId` sea null;
- la respuesta indique `taskLinked: true|false`;
- audit diferencie sesiones task-linked y task-less;
- policy, cwd allowlist, timeouts y adapter disabled behavior sigan iguales.

## Plan de implementacion paso a paso

### 1. Branch

```bash
git checkout develop && git pull --ff-only || true
git checkout -b feature/W-0-1-taskless-agent-tools
```

### 2. Tests rojos primero

Actualizar `tests/gateway/tool_agent.test.js` y
`tests/gateway/tool_session_attach_info.test.js`:

- `agent.spawn` sin `taskId` devuelve `sessionId`, `taskLinked: false` y se
  puede `ask/view/kill`;
- `agent.delegate` sin `taskId` devuelve `sessionId`, `taskLinked: false` y una
  session row cerrada;
- con `taskId` devuelve `taskLinked: true`;
- `session.attach_info` funciona para task-less supervised sessions;
- Codex disabled y policy denied siguen estructurados.

### 3. Tool schemas

En `gateway/src/tools/agent.js`, hacer `taskId` opcional para:

- `agent.delegate`;
- `agent.spawn`.

No relajar `traceId`, `cwd`, `agent`, `role` ni `repo` donde aplique.

### 4. AgentService

Actualizar `createSessionIfTaskProvided` o reemplazarlo por un helper que
siempre persista session:

```text
createSession({ taskId: taskId ?? null, ... })
```

Las respuestas deben incluir:

```json
{ "taskLinked": true }
```

o

```json
{ "taskLinked": false }
```

### 5. Audit

Los eventos `SESSION_STARTED` o el audit service-level deben incluir
`taskId: null` y `taskLinked: false` cuando aplique. No introducir un nuevo tipo
de evento salvo que sea necesario; preferir enriquecer eventos existentes.

## Errores comunes

- Volver a crear sesiones no persistidas.
- Usar `undefined` en vez de `null` contra SQLite.
- Permitir `ask/view/kill` sobre un sessionId que no existe.
- Saltarse policy por no tener task.
